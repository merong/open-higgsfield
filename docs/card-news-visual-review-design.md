# 카드뉴스 이미지와 출력 검수 · 2026-09-20

기존 참여형 설계의 이미지/검수/완료 흐름을 아래와 같이 확장한다. 원본 식물 예시 문서는 보존하며 기능은 모든 주제에 적용한다.

## 제작 흐름

기획 승인 → 원고 작성/내용 검수 → 전체 카드 이미지 확인 → 비용 확인 후 빈 카드 이미지를 일괄 생성(또는 업로드) → 실제 PNG 출력물 검수 → 선택 카드 재배치/명시적 문구 수정 → 다시 검수 → 사용자 확인 후 파일 완료.

모든 카드에 이미지를 넣는 것을 기본 권장한다. 이미 있는 이미지는 덮어쓰지 않는다. 타이포그래피 카드가 필요한 경우 누락을 숨기지 않고 이미지 없는 카드 수와 사용자의 예외 사유를 기록한다. 한 번에 전체 예상 비용을 표시하고 승인된 카드만 순차 생성한다. 새로고침으로 큐를 복원하며 실패/불명 요청은 자동 재결제하지 않는다. 취소/조건 변경 시 남은 큐와 늦은 결과를 현재 카드에서 분리한다.

## 다섯 가지 평가

| 항목 | 근거와 판정 |
| --- | --- |
| 텍스트 매칭 | 실제 PNG와 원고를 함께 모델에 전달하여 피사체, 분위기, 잘린 부분, 의미 대응을 카드별 평가. 이미지 누락은 별도로 표시. |
| 타이포그래피 | 실제 이미지의 위계·줄바꿈·행간·자간과 360px 폭 환산 글자 크기 측정을 함께 사용. |
| 내용 검수 | 원고/출처/이미지 비교로 오탈자, 고유명사(식물명 포함), 수치, 과장 표현을 점검. 종 식별이나 출처가 부족하면 확인 필요로 남기며 사실 검증 완료라 단정하지 않음. |
| 출력 검수 | 폰트·이미지 로드, 텍스트 영역 경계, 본문/제목 누락, PNG 디코딩/규격, 실제 시각적 잘림을 점검. 기계 검사와 모델 판단을 구별. |
| 수정 원칙 | AI 수정 기본값은 문구 보존. 서버가 제목/본문/머리말/CTA/종류/프롬프트를 원본에서 복사하고 배치/크롭/명암만 허용. 문구 수정은 선택 카드에서 명시적으로 허용. |

임의의 점수를 만들지 않고 통과/확인 필요/수정 필요와 관찰 근거를 표시한다. 검수는 동일 버전 ZIP의 PNG를 사용하고 완료도 그 ZIP으로만 허용한다. 수정하면 이전 검수는 무효화한다. 문구 보존 배치 수정은 불필요한 원고 재검수를 건너뛰고 실제 출력 검수로 돌아간다. 이미지 구상은 선택 카드에서 편집하고 비용을 확인한 뒤 다시 생성할 수 있다. 모델 응답 실패는 재시도 가능한 상태로 남긴다. 수정 필요는 완료를 차단하고, 확인 필요는 사용자의 게시 전 확인을 받는다.

## UI·UX

기존 dark/lime 디자인과 Pretendard, `--accent`, `--border-subtle`, `--tx2` 토큰을 재사용한다. 새로운 평가 점수나 장식 그래프를 추가하지 않는다.

```text
[카드 이미지 1/5]  [빈 카드 4장 채우기 · 16 크레딧]
[실제 썸네일 01] [02 이미지 필요] [03 이미지 필요] ...
[선택 카드 4:5 미리보기] [문구 보호 · 배치 수정 / 문구 수정 허용]
                       [균형 / 설명 중심 / 이미지 중심] [사진 위치]
[실제 출력물 검수] → [5개 평가 요약 + 카드별 근거/수정 제안]
                    [수정할 카드 보기] [문구 보존하고 재배치]
[확인 필요 항목 확인] [검수한 PNG·ZIP 완성]
```

썸네일은 출력과 동일한 ProjectSlide를 사용한다. 모바일은 한 열로 쌓고 카드 목록만 수평 스크롤한다. 검수 결과는 선택 카드와 연결하며 실제 출력 360px 미리보기를 제공한다. 본문 가독성 토큰은 4.5cqw(360px에서 16.2px), 행간 1.65, 줄바꿈 보존. 긴 문구에는 이미지 영역 비율을 줄여 텍스트 공간을 확보하는 설명 중심 배치를 먼저 제안하고 글자 축소를 자동 적용하지 않는다.

검토: 이미지 없는 카드가 눈에 띄지 않던 탭을 실제 썸네일 목록으로 바꾼다. 생성→검수→완료 세 행동을 구분하여 '파일이 만들어짐'을 '품질 통과'로 오인하지 않게 한다. 추가 설정은 선택 카드에만 표시한다.

## 검증

일괄 이미지 중복 제출/실패/새로고침/취소, 선택 범위와 문구 보존, 최신 버전/ZIP 결합, 소유권, 손상 파일, 모델 검수 실패/차단을 테스트한다. 기존 식물 5장 결과를 후속 수정하여 이미지 1/5→5/5, 실제 PNG 검수, 배치 변경 전후 문구 동일성, 모바일/데스크톱 및 다운로드를 확인하고 실제 결점과 잔여 불확실성을 QA 문서에 기록한다.

API 근거: [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision). 저장된 모델 설정을 유지하며 Responses input_image로 소유 ZIP에서 검증한 PNG만 전달한다.
