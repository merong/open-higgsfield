# 개선 항목과 실행 순서

2026-09-28 · 구현 전 초안 · 기존 리뷰와 인터뷰를 기준으로 작성

## 목표와 유지할 원칙

랜딩·제품 상세페이지는 설명+사진 / 상품·서비스 URL / 한 문장 중 하나로 시작한다. AI가 취향·배치를 판단하고, 미제공 가격·규격은 제외하며, 판매 대상이 모호할 때만 짧게 확인한다. 대표 시안·기획 승인을 의무화하지 않는다. 명확한 수정은 즉시 처리하고 의도·품질을 충족하는 최소 변경을 선택한다. 실제 상품의 형태·색·로고를 보존한다. 수정 결과 즉시 적용과 선택적 비교·되돌리기는 초기안이다.

기존 이미지 기획·보드·원고 검수·크레딧·동시 편집 보호를 재사용한다. Open Design 전체 런타임, 기본 질문 폼, 고정 16개 이미지 템플릿을 그대로 이식하지 않는다. 근거는 [도입 리뷰](../reference/open-design/review/adoption-review.md)다.

## 선행 발견

- [db.ts](../../src/service/db.ts:12)는 PostgreSQL/PGlite에 상태·버전·요약 이벤트를 저장한다. 프로젝트별 SQLite 실행 로그는 없다.
- 랜딩 [event](../../src/service/landing-workflow.ts:20)는 최근 70개 요약만 유지한다. [landingModel](../../src/service/landing-model.ts:61)은 응답 메시지를 파싱한 값만 반환한다. 원본 요청/응답·provider request ID·usage·reasoning summary의 프로젝트별 연속 기록이 아니다.
- [프로젝트 직접 생성](../../src/service/projects.ts:37) 외에 각 workflow와 [AI 구성안](../../src/service/outline.ts:92)이 직접 INSERT한다. 공통 초기화의 적용 범위를 먼저 정해야 한다.
- [workflowModel](../../src/service/workflow-model.ts:39)과 [reelModel](../../src/service/reel-model.ts:45)의 검색 도구 사용, [generation](../../src/service/generation.ts:68)의 이미지 작업은 같은 trace에 연결해야 한다. UI 요약 로그를 그대로 확장하는 것으로 충분하지 않다.

## 단계별 진행

1. **기록 기반 확보:** W00. 모든 신규 프로젝트 초기화부터 적용하고 모델·도구 기록을 연결한다. 랜딩/상세페이지를 우선 깊게 검증하되 카드/릴스/구형 agent/구성안 생성 경로도 초기화·기록 누락 없이 목록화한다.
2. **기준선 확보:** W01. 현재 승인형 동작을 먼저 관찰한다. 계측과 UX 변경을 한꺼번에 넣어 기준선을 잃지 않는다.
3. **최소 범위 실험:** W06의 변경 단위 보존과 W02의 조건부 질문, W04의 문구/배치 단일 코멘트. 유료 이미지 재생성 없이도 품질·사용자 부담을 검증한다.
4. **이미지 개선:** W03·W05를 연결하고 보존 검증을 통과한 결과만 W06으로 자동 적용한다. 원본 전달 지원 검증 없이 자동 재생성부터 켜지 않는다.
5. **진입·품질 확장:** W07·W08, 필요한 조회 화면 W09. W10은 실제 병목 근거가 있을 때만 진행한다.

## 검증 시나리오

- 설명+사진, 한 문장, URL 각각으로 시작하고 AI 요청에 사용된 실제 입력·출처를 추적한다. 필수 아닌 빈칸 때문에 추가 질문이 생기지 않아야 한다.
- 같은 입력에서 기존 경로와 변경 경로의 질문 수·대기·호출 수를 비교하되 생성 결과 품질도 별도 판정한다.
- 사진을 크게 해 달라는 요청은 배치 변경으로 해결되면 이미지 생성 호출 0회여야 한다. 확대 후 흐려짐·잘림도 검사한다.
- 배경만 수정한 결과의 상품 외형·로고가 달라지면 적용하지 않는다. 선택한 원본이 provider에 실제 전달됐는지 로그로 확인한다.
- 같은 요청 재전송, 타임아웃 뒤 늦은 응답, 취소, unknown provider 결과, 사용자 동시 편집에서 중복 과금·중복 적용이 없어야 한다.
- 적용 후 이미지·제목을 수정하고 이전 요청을 되돌릴 때 충돌을 식별해야 한다. 아직 정하지 않은 충돌 정책은 자동 덮어쓰기로 구현하지 않는다.
- trace DB 준비 실패, 기록 저장 장애, 프로세스 종료, outbox 재전달, 기존 프로젝트 도입 시나리오는 [로그 설계](project-trace-design.md)의 합격 조건을 따른다.

## 사용자 결정이 남은 항목

이미지 자동 재생성 비용 한도와 모델 교체 범위, 나중 편집과 복원 충돌 시 처리, 대상은 아는 URL 읽기 실패의 처리, 여러 코멘트 묶음 방식. 숫자·보존 기간·모델 정책은 임의 확정하지 않는다. 기술 구현의 선택지는 리뷰에서 줄여 제안한다.
