# 숏폼 HITL 구현 및 검증

2026-09-21. 로컬 개발 서버: http://127.0.0.1:3000

## 구현한 흐름

원문 [숏폼 참여형 가이드](shortform-reels-human-in-the-loop-guide.md)를 저장하고 [설계](reels-hitl-design.md)를 먼저 작성했다. 식물에 한정하지 않는 주제 입력 → 필요한 목적 질문/근거 조사 → 대본·콘티 승인 → 실제 5~8초 샘플 → 샘플 승인 → 나머지 장면 → 전체 MP4 → 구간 수정·검수 → 사용자 최종 확인 → 파일 보관을 연결했다.

- 새 프로젝트의 숏폼 `AI와 함께 제작` / `직접 구성하기` 분리. 기존 직접 구성하기는 WebM 편집기를 유지한다.
- `reel_workflows`, `reel_workflow_versions`: 계정별 실행·질문·응답·리비전·잠금·사용량·비동기 요청·버전 저장. 대기 중 모델 재호출 없음. 재방문/프로젝트 링크에서 저장된 작업 복원.
- 대본과 화면 문구 분리. 확정 문구·길이 보호, 장면별 수정, 배경 교체·사진 확대/위치·자막 스타일 변경 시 음성 재사용.
- Higgsfield 이미지/영상, 본인 에셋 연결/업로드, OpenAI AI 음성·실제 전사/타임스탬프. 글자·분할 구도가 들어가지 않도록 정지 사진 생성 지시를 강화했다.
- 음성이 길면 문구를 임의 축약하지 않고 시간 재배분 또는 길이 변경 허용. 마지막 전사 구간의 EOF 초과는 실측 음성 끝으로 제한. 정렬 실패 시 원본 음성 보관 및 정렬만 재시도.
- 사용자별 견적·크레딧 예약/확정/환불, 영상 잔액 50 초과 조건, 모델·자산·음성·렌더 호출 한도. 접수 불명은 자동 재결제하지 않는다. 음성 새 요청은 해당 장면과 추가 비용을 명시적으로 확인한다.
- Canvas의 번들 한글 글꼴·원문 레이어를 검증하고 서버 FFmpeg로 1080×1920 H.264/AAC, 30fps를 합성한다. 소유한 파일만 사용하며 외부 URL/플레이리스트를 FFmpeg 입력으로 허용하지 않는다.
- 전체 디코딩·프레임 수·길이·코덱·음량 피크 및 대표 프레임 AI 검수. AI 검수 기록/이전 MP4를 보관하고 필수 오류·구버전·청취 미확인 상태의 최종 완료를 차단한다.
- 최종 MP4·커버·게시문·프로젝트 JSON·검수 JSON ZIP, 음성 사용 시 SRT/VTT/대본. 사용자 라이브러리와 관리자 사용자/기능 필터에 연결했다.
- 도움말의 숏폼 설명·워크플로우·실제 화면을 업데이트했다.

## 자동 검증

- `corepack pnpm test`: 전체 83/83 통과. 기존 카드뉴스·계정·권한·크레딧·라이브러리 회귀 포함.
- `node --import tsx --test test/reel-workflow.test.ts`: 숏폼 10/10 통과. 별도 메모리 DB를 사용한다.
- `corepack pnpm build`: 프로덕션 빌드·TypeScript 통과. 빌드 검사에서는 `LOCAL_DATABASE_DIR=memory://`를 사용하며 실행 중인 로컬 PGlite를 중복으로 열지 않는다.
- 실제 FFmpeg 샘플/전체 인코딩과 전체 디코딩, 검수 승인 조건, 완성 ZIP 파일명·MP4 형식·검수 렌더 ID를 테스트했다. 자동 테스트의 모델/사진/음성/문구 레이어는 명시적인 fixture이므로 실제 생성 품질 증거와 구분한다.
- UI: 1057px 3열 편집 화면, 390px 모바일 화면에서 가로 넘침 없음. 정상 속도 재생·무음 보기·새로고침 복원·자막 스타일만 수정·프로젝트 재진입을 확인했다.

## 실제 식물 예시 E2E

- 작업: `4e0279e7-3f99-4124-96b5-1f9353f2dcec`
- 프로젝트: `d19dcb87-d91a-4ec9-b3c6-aac6af1fa792`
- [작업 열기](http://127.0.0.1:3000/projects/new?format=reels&reelWorkflow=4e0279e7-3f99-4124-96b5-1f9353f2dcec)
- 입력: 직장인의 빈 책상에 작은 초록 화분을 두는 30초 릴스, 5장면, 따뜻한 자연광, 한국어 내레이션. 가격·구매 CTA·공기정화·건강 효능·관리 난이도 주장 제외.
- 저장된 `gpt-5.6-terra / low`로 의도 해석·대본 생성. 명시된 목적을 다시 묻지 않았고, 효능 주장이 없는 연출 요청에는 불필요한 웹 조사를 수행하지 않았다.
- 실제 Soul 2 이미지 5개, TTS/Whisper로 5장면의 음성/정렬 완료. 실측 4.95 / 4.40 / 4.80 / 5.45 / 3.70초. 모든 대본·전사는 공백/문장부호 정규화 후 일치했다.
- 대표 6초 샘플을 생성·재생·승인하고 전체 30초를 합성했다. 완료된 요청 ID와 자산은 새로고침 후 유지됐다.
- 최초 전체 출력(v15)에서 AI 검수와 직접 프레임 확인으로 가짜 외국어·분할 구도·서로 다른 화분/식물 문제를 확인했다. 필수 오류 8건으로 완성을 차단했다.
- 문구와 다섯 음성 asset ID를 그대로 보존하고, 2~5장면에 동일한 보관 사진을 재사용했다. 확대·크롭으로 가짜 글자를 제외하고 마지막 자막만 강조했다. 추가 생성 비용 없이 재합성했다.
- 수정 출력(v23): 1080×1920, H.264/AAC, 30fps, 정확히 900 영상 프레임. 영상 30.000초/컨테이너 30.021333초(AAC 패딩), 2,694,889바이트. 전체 디코딩 오류 없음, 오디오 피크 -9.6dB.
- 실제 브라우저 플레이어: 30.021333초까지 도달, `ended=true`, `playbackRate=1`, 미디어 오류 없음. 무음 가독성과 장면 프레임도 확인했다.
- 재검수: 필수 오류 0, 확인 권장 5. 같은 사진 반복, 놓는 동작/업무 맥락 부족, 식물 크기 인상에 대한 의견은 남았다. 이 예시는 이미지 모션 결과이며 새로운 실제 동작 영상이 생성됐다고 주장하지 않는다.
- 사용자 라이브러리와 관리자 `reels`/사용자 필터에서 해당 MP4를 조회했고 다운로드 바이트 수/MIME을 확인했다. `listened=false` 완료 요청은 HTTP 400으로 차단됐다.
- **실제 음성을 사람이 청취했다고 기록하지 않았다.** 본 실행 환경에서 청취를 독립 검증할 수 없어 최종 청취 체크와 ZIP 확정은 사용자에게 남겼다. UI에는 검수 의견과 실제 MP4가 준비돼 있다. 자동 테스트에서는 검수/청취 확인 입력을 fixture로 제공하여 최종 ZIP 경로까지 검증했다.

총 앱 크레딧은 386 → 351(35 사용): 대본 1, 이미지 20, 음성 요청 14. 음성 요청 중 2건은 구버전 정렬 처리 실패/응답 불명으로 원장에 확인 대상으로 유지된다. 추가 비용을 명시적으로 확인한 새 요청으로 재시도했으며, 자동 중복 결제나 기존 잔액 일괄 변경은 하지 않았다. 공급자의 실제 화폐 과금은 이 앱 원장과 별개다.

## 현재 범위

서버에 FFmpeg/ffprobe 설치가 필요하다. 음성은 AI 음성으로 표시하며 원본 영상 소리는 제외한다. 배경음은 권한이 있는 사용자 파일을 업로드한다. 장면 이미지의 정확한 피사체 일치나 모든 영상 동작은 자동 보장하지 않으므로 검수 후 교체/재사용/업로드한다. SNS 자동 게시, 자동 BGM 생성, 외부 전용 렌더 워커 배포는 이번 구현에 포함하지 않는다.
