# 사진에서 시작하는 숏폼·릴스

## 제작 흐름과 화면

사진 1~6장 → 이미지 기반 프롬프트 추천(선택) → 제작 의도 확인 → 원본 사진이 연결된 컷 승인 → 사진을 움직이는 영상으로 생성 → 대표 샘플 승인 → 나머지 컷 영상 → 전체 MP4·검수.

시작 화면 왼쪽은 기존 제품 상세 갤러리를 재사용한다. 실제 사진을 큰 프레임에 표시하고 아래 썸네일·대표 지정·제거를 제공한다. 오른쪽은 길이·음성 방식과 의도 입력, 사진 기반 추천을 둔다. 추천은 관찰한 피사체·분위기에서 영상 방향과 훅/전개/마무리 아이디어를 제시하고 사용자가 확인한 뒤 프롬프트에 적용한다. 사진만 업로드하고 바로 대본을 요청할 수도 있다.

```
사진으로 시작               영상 방향
큰 원본 미리보기            [이미지 기반 프롬프트 추천]
[사진][사진][＋]             추천 방향 / 컷 흐름 / 적용
대표 사진 · X 제거          프롬프트 · 길이 · 음성
                            [사진으로 컷 만들기]
```

콘티에서는 모든 컷에 원본 썸네일과 카메라/동작 프롬프트를 함께 표시한다. 한 장은 구도·움직임을 달리해 재사용하고, 여러 장은 컷별로 배정한다. 원본을 바꾸거나 프롬프트를 수정한 뒤 승인할 수 있다. 현재 컷의 원본은 생성된 영상과 별도로 보존하여 재생성에도 사용한다.

기존 surface/text/border/accent 토큰과 Pretendard를 유지한다. 시각적 중심은 실제 사진에서 세로 콘티로 이어지는 이미지 트레이이며 새로운 장식 색상은 추가하지 않는다. 모바일에서는 사진→의도 입력→컷 순서로 쌓인다.

## 구현 범위와 경계

- 업로드 파일 디코딩·소유권 검증·원본 보관 및 제한(6장, 각10MB)은 기존 검증 로직을 공유한다. 사진 목록은 제작 JSON에 저장하고 재접속·후속 제작에 보존한다.
- OpenAI 의도/기획/수정 단계에 실제 사진 사본을 전달한다. 외형·색상·구성 외 사실/성능/정체성은 추정하지 않고 촬영 연출과 관찰 사실을 구분한다.
- 사진 추천은 앱 크레딧 차감 없이 계정당 분당3회. 대본은 기존1크레딧, 영상은 컷별 비용 확인 및 잔액50초과 규칙을 유지한다.
- 이미지 기반 영상은 원본 사본을 Higgsfield의 공식 업로드 API로 전달하고 image-to-video 경로에 연결한다. 원본은 변경하지 않으며 세로 캔버스에 contain으로 맞춰 잘리지 않게 한다. API 키는 서명 URL에 전달하지 않는다.
- 영상 생성 상태·접수 ID·중복 결제 방지·실패 환불·샘플 승인·최종 합성은 기존 흐름을 재사용한다. 업로드 실패 시 텍스트 영상으로 자동 대체하지 않는다.
- 외부 업로드와 모델 호출은 영상 생성 버튼을 누른 뒤 수행한다. 로컬 HTTP 주소를 외부 입력으로 전달하지 않는다.

## 검증

사진만 입력, 다중 사진 추천, 소유권/변조/빈 입력, 사진-컷 매핑과 수정 보존, I2V 전송·재생성 원본 유지·크레딧 정책을 자동 테스트한다. 실제 UI에서 사진 업로드→추천→컷 승인→한 컷 영상 생성·재생·서버 보관을 확인하고 모바일을 검수한다. 외부 공급자 실패는 앱 구현 결과와 구분해 기록한다.

업로드 계약 참고: [공식 Higgsfield Python SDK](https://github.com/higgsfield-ai/higgsfield-client/blob/main/src/higgsfield_client/http/client.py) — 서명 URL 발급, 파일 PUT, public URL 반환.
