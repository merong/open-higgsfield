# 랜딩 이미지 기획·일괄 제작

## 목표와 사용자 흐름
랜딩 방문자가 메시지를 이해하는 데 필요한 섹션만 이미지로 보강한다. AI는 페이지 기획에서 섹션별 이미지 필요 여부, 장면 설명, 비율을 제안한다. 사용자는 이미지 포함 체크와 비율·설명을 수정하며 총 장수를 확인한다. 초안은 실제 크기 비율의 빈 이미지 영역에 장면 설명·목표 크기·생성 프롬프트를 표시한다. 해당 이미지의 alt에도 프롬프트를 제공한다.

초안 검수와 기존 편집기에 공통 이미지 제작 모달을 제공한다. 섹션 순서대로 이미지, 크기, 모델, 프롬프트, 상태를 나열한다. 전체 빈 이미지 생성은 한 번 승인하되 서버에 큐와 요청 키를 기록하고 순서대로 접수한다. 진행 타일에는 shimmer와 실제 상태 문구를 표시한다. 생성 후보는 페이지를 자동 교체하지 않는다. 사용자는 장별 모델·프롬프트를 수정하여 재생성하거나 확인 버튼으로 준비된 후보를 적용한다. 이미 있는 이미지는 기본 일괄 생성에서 보존한다. 실패한 장만 재시도하며, 접수 불명 요청은 중복 결제를 막고 상태 확인만 허용한다.

## UI 설계
기존 디자인 시스템의 canvas #0b0d0f, panel #141719, raised #202426, text #f2f3f3, muted #9ca5a8, lime #c8ff00 역할을 재사용한다(실제 CSS는 의미 토큰 참조). Pretendard 본문·제목, 시스템 monospace 크기·상태 수치. 2열 검수 보드/모바일 1열, 이미지 비율은 실제 페이지와 동일하다. 이 기능의 시각적 중심은 이미지가 놓일 공간 자체에 설명을 담은 ‘제작 전 도면’이다. 장식용 그래디언트는 사용하지 않고 shimmer는 진행 중 상태에만 쓴다. reduced motion에서는 정지 상태와 텍스트로 대체한다.

```
[페이지 이미지 3장] [완료 1/3]                [닫기]
[이미지/빈 도면] [이미지/생성 shimmer]
[섹션·목표 크기] [섹션·목표 크기]
[모델 / 프롬프트 / 다시 생성]
[전체 빈 이미지 생성 · 예상 크레딧] [확인하고 적용]
```

검토: 범용 생성 갤러리처럼 보이는 고정 정사각형 타일 대신 각 이미지의 의도와 실제 비율을 함께 보여준다. 금액과 진행은 서버 상태만 표시하고 가짜 백분율은 사용하지 않는다.

## 구현과 검증
- 하위 호환 선택적 imagePlan: enabled, ratio, description. 과거 랜딩은 hero/features/story에 기본 영역 제안, 사용자가 끌 수 있다.
- 기획·원고·저장 검증·미리보기·HTML 출력까지 동일 계획을 보존한다. FAQ/CTA도 이미지 선택 시 반영한다.
- 프로젝트별 영속 이미지 보드, 장별 멱등 요청 키, 서버 비용 검증·소유권 검증. 기존 provider/크레딧/라이브러리 사용.
- 명시적 적용 시 최신 섹션의 문구/이미지/계획 스냅샷과 대조하여 오래된 후보가 변경 내용을 덮어쓰지 않도록 한다. 활성 AI 워크플로우도 동일 트랜잭션에서 갱신한다.
- 계획·보안·중복 요청·실패 환불·재생성·적용/충돌·재개 테스트, 전체 회귀, 빌드, 브라우저 데스크톱/모바일 검증. 실제 제공자 소량 생성 검증은 별도 기록한다.
