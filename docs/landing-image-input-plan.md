# 이미지에서 시작하는 랜딩 페이지

## 범위와 화면

브랜드·공간·제품·서비스 이미지를 가지고 있는 사용자가 한 줄부터 쉽게 페이지를 기획한다. 왼쪽 소개 영역을 실제 업로드 이미지 보드로 바꾸고 오른쪽은 사용자 의도 입력과 제작 시작에 집중한다.

```
이미지에서, 페이지의 방향을.    어떤 페이지를 만들고 싶으세요?
사진 선택 / 드래그 앤 드롭      [사용자 메모 또는 적용한 프롬프트]
[큰 원본 미리보기 · X]          예시 / 제작 단계 안내
[썸네일][썸네일][추가]          [AI와 페이지 기획하기]
대표 지정 · 크기
[이미지 기반 프롬프트 추천]
관찰 · 페이지 방향 · 사진별 역할
[추천 프롬프트 적용 →]
```

추천은 자동 적용하지 않는다. 이미지에서 확인한 특징과 제안한 대상·목표를 구분하며, 현재 메모의 조건을 보존한다. 응답을 기다리는 중에는 이미지와 메모 변경·제작 시작을 잠근다. 사진 목록/순서 변경 시 이전 추천을 폐기한다. 추천 이후 메모를 바꾸면 다시 분석하도록 안내하여 뒤늦은 응답이 입력을 덮어쓰지 않게 한다.

## 디자인

기존 토큰을 유지한다: canvas #0a0a0b, panel #151719, raised #1a1d1f, primary #edefef, secondary #a8aeaf, accent #d1fe17. 제목·본문은 앱의 기존 한글 Pretendard/UI 폰트, 영문 캡션은 기존 Inter 계열을 상속한다. 제목34~44px, 본문14px, 이미지 메타11px. 실제 업로드 이미지와 사진→섹션 연결을 화면의 중심으로 삼고 별도 장식 이미지는 넣지 않는다. 기존 세로 문구 흐름은 삭제해 이미지와 추천을 위한 공간을 확보한다. 모바일에서는 이미지 보드→추천→메모 순으로 쌓는다.

## 데이터와 생성

- 공통 파일 컴포넌트를 landing 용도로 확장: JPG/PNG/WebP 최대6장, 장당10MB, 미리보기·썸네일·대표 지정·X 선택 제외. 원본은 내 라이브러리에 보존한다.
- 소유권·파일 디코딩 검증 후 실제 이미지 사본을 OpenAI 추천과 랜딩 워크플로우에 전달한다. 임의 원격 URL은 받지 않는다.
- 추천 API는 계정당 분당3회, 앱 크레딧 별도 차감 없음. 실패 시 입력을 보존한다. 사진으로 추정할 수 없는 가격·후기·기능·일정·인증·신원은 생성하지 않는다.
- 사진만으로도 시작 가능. 현재 메모와 사진을 함께 의도 분석하고 사용자가 방향을 확정한다.
- 섹션 기획에 업로드 원본 ID를 연결하고 대표 이미지를 첫 화면 기본값으로 제안한다. 사용자는 섹션별 원본·새 이미지·이미지 생략을 선택한다. 승인한 사진은 초안에 바로 배치하고 문구 수정·새로고침·편집기 전환에도 보존한다.
- 기존 제품 상세·릴스·텍스트 전용 랜딩의 계약과 크레딧 정책은 유지한다.

## 검증

추천의 실제 이미지 입력·명시적 적용·소유권·오류·모델/effort, 사진만 시작·과금 전 검증, 섹션 원본 변경/해제·초안 반영·수정 보존·복원을 테스트한다. 브라우저에서 다중 업로드·썸네일·제거·추천·기획 진입과390px 화면을 확인한다. 실제 모델 검증과 모의 응답 검증을 분리해서 기록한다.
