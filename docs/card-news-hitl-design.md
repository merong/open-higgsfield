# AI와 함께 제작 — 범용 사용자 참여형 워크플로 설계

작성: 2026-09-20. 구현 전 설계. 원본 요구 문서는 [사용자 제공 예제](plant-cardnews-human-in-the-loop-workflow.md)에 변경 없이 보관한다. 식물은 E2E 평가 주제이며 제품 로직·질문·템플릿에 식물 전용 분기를 넣지 않는다.

## 현재 흐름에서 바꿀 점

기존은 기획 방향 3개 → 전체 원고 → 검수 → 개선 → 편집기 이동이다. 사용자 선택은 방향 한 번에 집중되어 있고, 제작 조건의 출처·장별 기획 승인·표지 비교·특정 카드만 수정·실제 파일 기준 완료가 없다. 기존 실행 데이터/API는 보존하고 새 제작 UI를 v2 워크플로에 연결한다.

## 확정한 제품 방향

- 한 줄 입력과 선택적 참고 이미지로 시작한다. 장수·말투는 접힌 옵션에 둔다.
- AI가 목적·독자·채널과 제외 조건을 읽는다. 명시한 목적은 재질문하지 않는다. 목적이 불명확할 때만 3개 내외의 선택지 + 직접 입력 + 알아서 추천을 제시한다.
- 목적이 정해지면 필요한 경우 실제 웹 근거를 조사한다. 제공업체가 반환한 검색 출처만 기록하고, 근거 없는 구체적 주장은 제외하거나 추가 확인 항목으로 남긴다. 정보형 목적에는 가격·구매 CTA를 임의로 넣지 않는다.
- 장별 역할·제목·핵심 메시지의 기획표를 먼저 보여 준다. 사용자는 수정 의견을 적거나 승인한다.
- 같은 표지 내용을 디자인 시스템의 세 가지 실제 레이아웃으로 비교한다. 별도 설문 대신 표지를 선택한다. 업로드 이미지 또는 선택한 AI 이미지로 실제 미리보기를 만든다.
- 이미지 생성은 기존 Higgsfield 작업/원장/상태 조회를 재사용한다. 사용자가 비용이 표시된 버튼을 눌렀을 때만 실행한다. ‘알아서 추천’은 추가 이미지 과금을 승인하는 의미가 아니다. 각 카드 이미지 사용을 권장하고 일괄 채우기를 제공한다. 의도적 텍스트 카드는 출력 검수에서 예외 사유를 남긴다.
- 본문 작성 → 내용 검수 → 필요한 보정으로 진행한다. 수정할 문제가 없으면 불필요한 재작성은 생략한다. 자동 보정은 2회 이내.
- 완성 원고에서 카드 선택, 문구 직접 편집, 순서 변경, 이미지 업로드/교체, 특정 카드만 자연어 수정이 가능하다. 서버는 선택한 카드 ID만 패치하여 나머지 카드의 모든 필드를 보존한다.
- 전체 조건 변경은 현재 모델/이미지 작업을 이전 버전에 묶고 새 계획으로 돌아간다. 원본과 이전 결과는 버전 기록에 남긴다.
- 브라우저 렌더러로 글자 잘림·이미지 디코딩·실제 규격을 검사하여 PNG/ZIP을 만든다. 서버가 ZIP의 장수, PNG 규격·압축 데이터 및 프로젝트 버전을 확인하고 보관한 뒤에만 ‘완료’로 표시한다.

## 화면 구성 / UI·UX

기존 앱의 어두운 작업 환경과 라임 액센트를 유지한다. 새 색상을 무작정 추가하지 않고 기존 토큰으로 통일한다.

- 바탕 `--bg #0a0a0b`, 작업 패널 `--s1 #151719`, 입력/선택 `--s3 #222629`, 기본 글자 `--tx #edefef`, 보조 글자 `--tx2 #a8aeaf`, 행동 강조 `--accent #d1fe17`.
- 제목: 기존 Pretendard/Inter 디스플레이 역할, 28–32px. 본문·질문: Pretendard 14–16px, 줄간격 1.7. 카드 번호/버전: 기존 유틸리티 글꼴·tabular-nums 11–12px. 새로운 폰트 다운로드 없음.
- 화면의 중심 장치: **현재 질문과 선택 카드가 나란히 있는 작업 책상**. 활동 로그가 주 콘텐츠를 밀어내지 않도록 기록은 접힌 영역으로 둔다.

```text
[AI와 함께 제작]   [현재 단계]                  [편집기] [작업 종료]
[목적: 정보 전달 · 확정] [독자: 입문자 · 추정] [5장 · 기본] [조건 변경]
┌ 제작 대화 340px ──────┬ 카드 작업 영역 ──────────────────┐
│ 지금 필요한 질문      │ 표지 시안 3개 / 선택 카드 확대    │
│ 선택지·직접입력·위임   │                                  │
│ 다음 행동 버튼        │ [01] [02] [03] [04] [05]          │
│ 근거·확인할 내용      │ 선택 카드 문구 / 이미지 / 수정 의견 │
│ [활동 기록 펼치기]     │ [검수 후 PNG·ZIP 준비]             │
└─────────────────────┴──────────────────────────────────┘
```

모바일에서는 현재 질문을 먼저, 미리보기와 카드 목록을 다음에 표시한다. 썸네일만 가로 스크롤하며 페이지 전체가 가로로 넘치지 않게 한다. 주요 버튼은 현재 행동 하나를 강조한다. 로딩 중에는 실제 단계와 대기 이유를 표시하며 가상 진행률·모델명·호출 인자·내부 추론 원문을 사용자 대화에 노출하지 않는다.

설계 자체 검토: ‘로그가 길게 쌓이는 관리자 화면’ 대신 ‘지금 선택할 항목 + 실제 카드’ 중심으로 수정했다. 숫자는 실제 카드 순서·버전·검수 장수에만 사용한다. 표지 비교는 장식용 그림이 아닌 출력에 사용하는 동일 컴포넌트이다.

## 구현 구조와 일관성

- `card_workflows`: 실행 ID, 프로젝트 ID, 소유자, JSON 제작 상태, revision, 단계 잠금/만료. `card_workflow_versions`: 제작 문서 스냅샷과 변경 이유. 프로젝트와 실행은 별개이며 완료 후 수정은 새 실행으로 분리한다.
- 제작 명세 값마다 `user_explicit`, `user_confirmed`, `ai_assumed`, `default` 출처를 둔다. 질문에는 요청 ID와 revision, 사용자 응답에는 고유 response ID를 둔다.
- 허용 단계: 해석, 조사, 기획, 작성, 검수, 수정. 서버가 조건에 따라 다음 단계/사용자 대기/도구 대기/예산 중단을 결정한다. 질문을 기다리는 동안 모델 호출 없음.
- 한 HTTP 요청은 모델 호출 1회만 실행하고 DB에 결과를 확정한다. 기존 원장과 사용자 인증/관리자 IP 정책을 그대로 적용한다. 새로고침 시 질문·시안·카드·다운로드를 복원한다.
- 기본 텍스트 실행 비용 1 크레딧. 모델 최대 12회, 활성 모델 실행 600초, 보정 최대 2회, 이미지 최대 12개. 이미지 비용은 별도 명시. 한도에서는 현재 결과를 보존하고 중단 이유와 계속할 방법을 제공한다.
- 모델 호출 실패는 원시 오류/키를 노출하지 않는다. 출력 파일 실패는 편집 가능한 결과를 남기고 재시도하게 한다. 취소·명세 변경 후 늦은 응답은 lease와 revision 검사로 폐기한다.
- 참고 이미지는 계정 소유 업로드만 사용한다. 외부 URL은 링크/자료로 취급하고 서버에서 임의 URL을 무제한 fetch하지 않는다. 모델의 웹 도구 결과는 지시문이 아닌 자료다.
- 상품 API/브랜드 프로필, SNS 자동 게시·예약은 원본 문서의 후속 범위로 남긴다.

## 검증 계획

1. 식물 한 줄 → 목적 질문 → ‘정보 전달’ → 실제 근거와 5장 기획 → 표지 선택 → 카드 제작·검수 → PNG 5개와 ZIP. 가격·구매 CTA 없이 저장 안내로 마무리한다.
2. 목적/대상/장수를 상세히 입력하면 목적 재질문 생략. 위임은 추정 출처를 유지하고 자동 진행한다.
3. 선택 대기에서 새로고침, 중복 response ID, 오래된 질문, 다른 계정 접근을 검증한다.
4. ‘3장만 짧게’ 이후 1·2·4·5장 JSON/미디어 해시가 동일한지 확인한다.
5. 생성 도중 조건 변경과 취소, 예산 한도, 검색/생성 실패, 늦은 응답, 파일 손상/장수·규격 불일치에서 허위 완료가 없는지 테스트한다.
6. 데스크톱/모바일, 키보드 포커스, 업로드, 실제 이미지 작업 재조회, 파일 다운로드 응답 및 PNG 디코딩을 검증한다.

## 구현 결과와 운영 경계

- 화면: `src/editors/card-workflow-creator.tsx`, `card-workflow.css`. 진행 중에는 형식 선택 헤더를 접어 작업실에 집중하며, 같은 `ProjectSlide`를 시안·미리보기·출력에 재사용한다.
- 상태/정책: `src/projects/card-workflow.ts`, `src/service/card-workflow.ts`. v1 `card-agent` API는 유지하고 새 화면은 `card-workflow` API를 사용한다. `responseId`, 질문 ID, revision, 서버 lease로 중복 및 늦은 응답을 막는다.
- 모델: `src/service/workflow-model.ts`. 관리자가 저장한 모델/effort와 Responses API의 구조화 출력을 사용한다. 실제 웹 검색에서 반환된 URL만 출처로 인정한다. 의도 응답이 주제 선택으로 벗어나면 범용 목적 3개로 안전하게 되돌린다. 공개 메시지 출력만 읽고 비공개 추론 출력은 저장하지 않는다.
- 이미지: `src/service/workflow-images.ts`. 장별 영문 피사체 프롬프트와 기존 Higgsfield 생성/원장을 재사용한다. UI에 표시된 견적과 서버 비용이 같아야 접수하며, 불명확한 접수는 자동 재제출하지 않는다. 별도 이미지 크레딧을 소비하는 행동은 사용자가 선택한다.
- 파일: `src/service/workflow-export.ts`. ZIP 내용과 현재 프로젝트 문서 일치, PNG 장수·CRC·규격·압축 픽셀 데이터를 검사한다. 완료 결과를 `assets.project_id`에 연결하여 사용자/관리자의 카드뉴스 라이브러리 필터에서 조회한다. 이미 보관된 파일은 편집기 수정 이후에도 해당 버전의 파일로 유지된다.
- 실행 기본 한도: 모델 12회 / 활성 10분 / 자동 보정 2회 / 이미지 8회. 한도에 도달하면 현재 결과를 보존한다. 명시적으로 재개하면 총 모델 20회 / 활성 15분까지 확장한다. 사용자를 기다리는 동안 모델 호출은 없다. API는 HTTP 요청 1개당 모델 호출 1번이며, 새로고침 후 브라우저가 저장된 단계에서 이어간다.
- 이미지 의미/사실관계는 자동으로 완벽히 판단하지 않는다. 공개 진행 요약·검수 의견·출처와 실제 카드 미리보기를 보고 사용자가 최종 확인한다. 웹 검색 실패에는 재시도 또는 미확인 사실을 제외하는 경로가 있다.
- 기존 편집기와 동시에 수정하면 프로젝트 version 충돌로 덮어쓰기를 막는다. 이전 카드 버전 복원은 카드 문서를 복원하며, 현재 목적/제외 조건은 유지한다. 모델/이미지 완료 전에 명세를 바꾸면 이전 응답을 현재 카드에 자동 적용하지 않는다.

API 참고: [Responses 구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs), [웹 검색 도구](https://developers.openai.com/api/docs/guides/tools-web-search).
