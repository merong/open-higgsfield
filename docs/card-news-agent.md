# 카드뉴스 에이전트

## 사용자 흐름

`/projects/new?format=card-news` → **AI와 함께 제작**에서 주제·메모·일부 원고를 입력한다. 기존 9종 템플릿과 직접 구성 기능은 유지한다.

1. **의도 정리**: AI가 독자, 목적, 가정과 서로 다른 기획 방향 3개를 제안한다. 사용자는 추천을 그대로 선택하거나 다른 방향과 보충 의견을 전달한다. 필요한 확인 질문은 선택 사항 1개로 제한한다.
2. **초안 작성**: 사용자 원문, 선택한 방향, 추가 의견으로 모든 카드 제목·본문·이미지 프롬프트·캡션을 작성한다.
3. **편집 검수**: 별도 모델 호출로 의도 반영, 흐름, 중복, 가독성, 과장·미확인 사실, 이미지 구상의 일관성을 검토한다.
4. **원고 개선**: 검수 의견과 원문을 함께 전달해 전체 원고를 개선하고 실제 수정 사항 및 남은 확인 사항을 반환한다.
5. 사용자는 전체 원고를 확인한다. 추가 의견으로 **1회 더 검수·개선**하거나 **프로젝트에 저장하고 편집하기**를 선택한다. 이미지 생성과 내보내기는 기존 편집기를 이용한다.

활동 패널에는 실제 접수·시작·완료 단계, 의도 요약, 사용자 결정, 검수 의견과 수정 결과를 표시한다. 임의 타이머로 단계를 연출하지 않는다. 원시 reasoning 블록과 숨겨진 사고 과정은 저장하거나 노출하지 않는다. 토큰 단위 스트리밍 대신 DB에 확정된 단계 상태를 조회한다.

## 실행 및 저장

- `card_agent_runs`: 사용자 소유의 진행 상태와 구조화된 결과, 이벤트, revision, 작업 잠금 토큰과 만료 시간. 스키마 추가 후 개발 서버를 재시작해야 한다.
- `generation_jobs`: 기존 `outline` 분류와 `agent:true`로 원장 및 관리자 생성 내역에 연결한다. 최종 저장 시 프로젝트 ID를 기록한다.
- `POST /api/workspace/card-agent`: 입력 검증, 계정당 동시 작업 1개, 시작 키 중복 방지, 1 크레딧 예약. 당시 관리자 모델/effort를 작업에 고정한다. 키는 응답/작업 데이터에 포함하지 않는다.
- `GET /api/workspace/card-agent`: 현재 사용자 미완료 작업 복구. `GET /:id`: 해당 소유자만 상태 조회.
- `POST /:id`의 `action:step`: 요청한 revision의 pending 단계만 원자적으로 점유한다. 한 HTTP 요청에서 한 번의 Responses API 호출(45초 제한)을 실행한다. 완료된 구조화 결과를 다음 요청의 입력으로 전달한다. `store:false` 사용.
- `action:direction|revise|save|cancel`: 방향 확정, 제한된 추가 수정, 프로젝트 저장, 취소. 변경 가능한 상태 및 revision을 검사한다. 취소는 실행 중에도 가능하다.
- 브라우저가 열려 있는 동안 다음 pending 단계를 자동 실행한다. 다른 페이지로 이동하면 이미 요청한 단계만 완료하고 다음 단계는 재방문 시 이어간다. 분리된 백그라운드 워커/서버리스 fire-and-forget을 사용하지 않는다.
- 네트워크 응답 유실 시 최신 상태를 읽고 이어간다. stale revision 재전송은 다음 단계나 모델을 재실행하지 않는다. 75초 잠금이 만료되면 다음 조회에서 실패·환불하고 늦은 응답을 폐기한다. 7일 이상 방치된 미완료 작업도 다음 조회에서 만료·환불한다. 별도 만료 스케줄러는 없다.
- 전체 4회 모델 호출 + 추가 수정 시 2회까지, 합계 최대 6회. 단계별 추가 앱 크레딧 차감은 없다. OpenAI 공급자 사용료는 등록한 키에 실제 API 사용량만큼 별도로 발생한다.
- 성공 저장은 예약 확정, 실패·취소·만료는 1회 환불. 트랜잭션과 작업 잠금으로 중복 저장, 중복 차감·환불, 취소 후 결과 부활을 방지한다.

## 품질과 한계

AI가 제시한 편집 평가이며 사실 검증 보증은 아니다. 실시간 웹 검색은 하지 않는다. 최신 뉴스에는 원문·날짜·출처를 입력해야 하며 불명확한 사실은 확인 필요로 남기도록 지시한다. 화면에 이 한계를 명시한다. 고유명사와 명시된 카드 원고는 보존하도록 지시하고 다음 단계마다 원문을 다시 전달한다.

각 응답의 구조와 길이, 장수, 첫 표지/마지막 CTA, 비어 있지 않은 제목·본문·이미지 프롬프트 및 기존 프로젝트 검증을 적용한다. 중복 제목·긴 문구·확인 필요 표시도 별도로 점검해 사용자에게 안내한다. 모델이 작성한 원시 HTML은 렌더링하지 않는다.

## 검증

- `test/card-agent.test.ts`: 실제 API 대신 결정적 응답으로 4단계/6단계 맥락 전달, 원문 보존, 방향 선택, 추가 수정 한도, 단일 크레딧, 중복 시작/단계/저장, 다른 사용자 접근 차단, 잘못된 상태 변경, 취소·만료와 늦은 응답, 실패 단일 환불, 비밀/추론 비노출을 검증한다.
- 2026-09-20: 전체 자동 테스트 **52개**, TypeScript 검사, 프로덕션 빌드 통과.
- 등록된 **GPT-5.6 Terra / low**로 실제 4단계 + 추가 수정 2단계, 총 **6회**를 수행했다. 기획 방향 선택, 보충 의견, 브라우저 새로고침 복구, 초안/검수/개선 활동 표시 및 5장 프로젝트 저장을 확인했다.
- 실제 검수에서 초안에 빠진 복사 가능한 메일 요청 문장을 지적했고, 개선 결과의 3장에 반영되었다. 추가 의견의 회의록 요청 문장은 4장에 반영되었다. 표지와 지정한 2장 문구도 유지되었다. 단일 예제 검증이며 모든 주제의 품질을 보증하지 않는다.
- 실계정 잔액 **549 → 548**, 원장 `hold -1`, `confirm 0`. 중복 저장은 같은 프로젝트 ID를 반환하고 추가 차감하지 않았다. 관리자 활동 내역에도 표시된다.
- 실제 API 접근 검사: 비로그인 **401**, 다른 사용자 조회·수정 **404**, 동일 출처 없는 쓰기 **403**. 등록 키와 세션 토큰은 기록하지 않았다.
- 모바일 너비 390px에서 콘텐츠 너비 390px, 가로 넘침 없음. 데스크톱 방향 선택, 활동 패널, 원고 확인, 편집기 연결을 확인했다. 이번 검증은 문구·이미지 프롬프트 작성까지이며 실제 이미지를 생성하지 않았다.
