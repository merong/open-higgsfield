# 에이전틱 제작 품질·진행 상태 개선

2026-09-22

## 점검에서 확인한 문제

- 카드뉴스는 원고 검수·부분 보정이 있으나 검수 기준과 수정 전후의 이력이 사용자에게 충분히 보이지 않는다.
- 랜딩·제품 상세는 원고 검수 후 지적을 표시하고 종료한다. 수정 가능한 오류도 사용자가 하나씩 다시 요청해야 한다.
- 릴스는 대본·콘티 생성과 승인 사이에 독립적인 내용 검수 단계가 없다.
- 기다리는 화면의 표현이 기능마다 다르고, 일부는 점멸하는 점과 포괄적인 한 문장뿐이다.

## 구현 방향

1. 원고 검수를 의도 반영, 사실·원문 보호, 흐름·차별성, 이미지·메시지 조화, 읽기·전달 밀도의 다섯 기준으로 구조화한다. 실제 픽셀·재생 품질은 기존 출력 검수와 구분한다.
2. 랜딩·제품 상세 및 릴스에 검수 → 오류가 있는 부분만 보정 → 재검수를 연결한다. 최대 두 번만 자동 보정하며 매번 한도와 수정 범위를 확인한다. 단순 취향·확인되지 않은 사실은 사용자 확인 사항으로 남긴다.
3. 사용자 지정 수정은 선택한 범위 안에서만 수행한다. 원본 이미지, CTA, 상품 정보, 잠긴 문구와 시간은 프로그램에서도 보호한다. 검수·수정 이력을 다음 모델 입력으로 전달해 같은 지적의 반복을 줄인다.
4. 공통 Thinking 패널에 현재 단계, 실제 호출 횟수, 경과 시간, 이번 작업의 점검 대상과 가장 최근 완료 메시지를 표시한다. 상태와 메시지는 서버의 저장된 단계/이벤트를 기준으로 한다. 타이머로 가짜 진행이나 완료율을 만들지 않는다.
5. 텍스트와 결과 준비 영역에 shimmer를 적용하며 화면 읽기 프로그램에 단계 변경을 알린다. 움직임 줄이기 설정을 존중한다. 비공개 추론 원문은 요청·보관·노출하지 않는다.

## 검증

- 기존 전체 기능 테스트로 인증·크레딧·에셋·관리자·네 포맷·출력의 회귀를 확인한다.
- 오류 발견 → 범위 보정 → 재검수, 반복 오류 한도, 보호된 필드, 중복 요청/취소, 예산 부족을 테스트한다.
- 실제 UI에서 네 포맷 진행 표시, 상태 복구, 모바일, 저장된 생성 결과를 확인한다.
- 등록된 모델로 작은 텍스트 제작 예제를 검증한다. 이미지·영상 재생성은 품질 판단상 필요한 범위만 수행하며 기존 사용자 작업은 보존한다.

## 실제 검증 후 반영

- 공개 원고와 촬영·배치 메모를 분리하고, 문구 검수와 이미지 생성 실행을 혼동하지 않도록 했다.
- 자동 보정 중 반환된 빈 이미지 프롬프트·시간 변경은 보호된 저장값으로 대체한다.
- 책·노트 금지 및 가로 헤더 구도 강제처럼 장면 의도와 충돌하는 생성 지시를 정리했다.
- 검증 범위, 실제 응답 비교와 후속 우선순위는 [전체 점검 결과](agentic-quality-review.md)에 기록했다.
