# 제품 상세 페이지 제작

## 목적과 범위
온라인 판매자가 상품 자료를 입력하고 AI와 구매자가 궁금해할 순서를 결정하여 반응형 제품 상세 페이지를 만든다. 네 번째 프로젝트 형식 `product-detail`로 제공한다. 계정, 크레딧, 저장, 관리자 필터, 라이브러리는 기존 기반을 사용한다. 결과는 이미지·글꼴을 포함한 HTML ZIP이며 구매 버튼은 사용자가 입력한 판매처로 연결한다.

## UX
1. 시작: 상품명, 카테고리, 가격, 옵션, 규격, 사용법, 배송·반품 자료와 고객·차별점 메모를 입력한다. 비어 있는 정보는 추정하지 않는다.
2. 방향: AI가 대상 고객, 구매 고민, 판매 포인트를 제안한다. 상품 정보는 사용자가 입력한 원문을 유지한 채 수정·확정한다.
3. 기획: 대표 소개 → 구매 이유 → 디테일·사용법 → 규격 → 배송·FAQ → 구매 연결. 자료와 의도에 따라 3~8개 섹션을 구성한다. 이미지 포함 여부·장면·비율도 승인한다.
4. 초안: 확정 상품 정보는 고정 데이터로 렌더링하여 AI 문구가 가격·규격·정책을 덮어쓰지 못하게 한다. 부족한 상품 정보와 미연결 구매 주소를 검수에 표시한다.
5. 이미지: 초안 완성 후 업로드 사진 기반 ‘섹션 이미지 자동 생성’을 한 번 클릭하여 후보를 일괄 제작한다. [상세 흐름](product-section-auto-images.md). 기존 전체 이미지 모달의 큐·진행·모델/프롬프트 수정·명시적 적용을 재사용한다. 실제 상품 원본은 편집기에서 업로드하거나 라이브러리에서 선택한다. AI 연출 이미지는 실제 외형을 보장하지 않으므로 상품 사진과 대조하는 안내를 제공한다.
6. 편집: 상품 정보, 섹션별 문구, 순서, 이미지, 구매 링크를 자동 저장한다. 모바일·데스크톱 미리보기와 HTML ZIP을 제공한다.

## 시각 설계
기존 스튜디오 토큰의 배경·표면·글자·강조색을 사용한다. 편집 도구는 Pretendard, 출력물은 선택된 디자인 프리셋을 따른다. 상품 정보는 꾸밈보다 비교 가능성에 집중한다.

시그니처는 왼쪽 상품 이미지와 오른쪽 상품명·한 줄 가치·가격·옵션·구매 버튼의 구매 요약이다. 본문은 넓은 상품 디테일 사진, 혜택 카드, 규격 정의 목록, 배송·반품 2열 안내로 구분한다. 모바일에서는 이미지→요약→상세 순서로 한 열이 된다. 실제 사진의 전체 형태를 볼 수 있게 상품 대표 이미지는 contain을 사용한다.

검토: 랜딩의 브랜드 이야기를 복제하기만 하는 구성은 피하고, 상품 선택에 필요한 규격·옵션·정책을 독립 데이터 및 컴포넌트로 만든다. 허구의 할인율, 별점, 구매 수, 재고·카운트다운은 추가하지 않는다.

## 구현과 검증
- 기존 페이지 워크플로우를 형식별 전략으로 확장: 작업 재개를 형식별로 분리하고 잘못된 형식 인계를 차단한다.
- 상품 정보 서버 검증, 프로젝트 JSON 저장, 기존 데이터 호환.
- 승인·동시성·환불·이미지 적용은 기존 트랜잭션을 재사용한다.
- 제품 기획·원고·선택 수정·검수·인계 통합 테스트, 입력 escaping/링크/소유권/관리자 필터 테스트.
- 전체 테스트·타입 검사·빌드 및 실제 브라우저에서 직접 구성/AI 제작/모바일/ZIP 확인.
