# OpenHiggsfield 콘텐츠 포맷 확장 기획서

- 작성일: 2026-09-18
- 상태: 설계 합의 완료, 구현 계획 작성 전
- 범위: 전체 확장의 구조와 로드맵(개요 수준) + 카드뉴스(구현 가능한 수준)
- 경로 표기: 코드 경로는 모두 `open-higgsfield/` 저장소 기준입니다.

## 1. 목표와 범위

OpenHiggsfield는 지금 "프롬프트 한 줄 → 모델 요청 하나 → 이미지·영상 → 갤러리"로 동작하는 생성 스튜디오입니다. 이것을 인스타그램·쓰레드에 올릴 **카드뉴스**, **릴스**, 그리고 **랜딩 페이지**를 만드는 고객 대상 서비스로 확장합니다. 기존 생성 기능을 버리지 않고, 그 위에 한 층을 올리는 방식으로 접근합니다.

### 이번 기획서가 다루는 것

- 세 포맷과 서비스 기반을 아우르는 전체 구조, 화면 구조, 로드맵
- 세 포맷이 함께 쓰는 공통 기반(프로젝트·슬롯 모델, 포맷 레지스트리, 채널 프리셋, 카피 생성)
- 카드뉴스의 상세 설계

### 이번 기획서가 다루지 않는 것

- 서비스 기반(계정, DB, 크레딧, 결제)의 상세 설계. 9장에 개요만 두고, 별도 기획서로 작성합니다.
- 릴스와 랜딩 페이지의 상세 설계. 9장에 개요만 두고, 차례가 오면 각각 기획합니다.
- 인스타그램·쓰레드 직접 게시, 예약 게시, 계정 단위 브랜드 키트, 다국어. 모두 이후 단계입니다.

## 2. 합의한 결정

| 항목 | 결정 |
| --- | --- |
| 기획 범위 | 전체 기획서 한 장 + 카드뉴스만 상세화 |
| 주 사용자 | 고객에게 제공하는 서비스(계정, 서버 저장) |
| 비용 구조 | 운영자의 플랫폼 키로 호출하고, 고객에게는 크레딧으로 과금 |
| 게시 범위 | 1차는 파일 내보내기까지. 직접 게시는 이후 단계 |
| 카드뉴스 제작 흐름 | 주제 한 줄 → LLM 구성안 → 덱 초안 → 슬라이드별 수정 |
| 슬라이드의 글자 | 이미지 모델이 그리지 않고, 배경 이미지 위에 별도 레이어로 얹음 |
| 편집 깊이 | 템플릿 기반. 자유 배치 편집기는 만들지 않음 |
| 대상 시장 | 한국 우선. UI를 한국어로 바꾸고, 다국어는 나중에 |
| 구조 접근안 | 기존 생성 엔진 위에 프로젝트 층을 추가(B안) |
| 편집기 레이아웃 | H1: 왼쪽 스토리보드 목록, 오른쪽 큰 캔버스 |
| 기본 스타일 | 기본 고딕(Pretendard, 남색과 노랑) |

## 3. 현재 코드에서 기획에 영향을 주는 사실

- **결과물을 묶는 단위가 없습니다.** 히스토리는 `RunRecord`의 평평한 목록이고 60장 상한이 있습니다(`src/openhiggsfield/history.ts`).
- **글을 만드는 모델이 없습니다.** 카탈로그 38개는 모두 image 또는 video입니다.
- **글자를 얹거나 여러 장을 묶어 내보내는 기능이 없습니다.** 내보내기는 단일 파일 다운로드뿐입니다.
- **결과물 URL은 플랫폼 CDN 소유입니다.** 보존 기간을 모르고, 다운로드는 그 CDN의 CORS에 의존합니다(`download.ts`).
- **4:5를 지원하는 모델이 없습니다.** 다만 image 모델 8개는 모두 3:4를 지원합니다(generic 6개는 `IMAGE_ASPECT`, Soul 2개는 `SOUL_ASPECT`). video 모델은 모두 9:16을 지원합니다.
- **`GenerationPlane`이 단일 계약입니다.** `assemblePlane → submitGeneration → toPlatform → watchRequest` 경로는 입력이 어디서 오든 같습니다. 새 기능은 이 계약의 새 소비자로 붙일 수 있습니다.
- **폴링은 일부러 묶여 있습니다.** Next는 클라이언트당 서버 액션을 한 번에 하나씩 처리하므로, `poll.ts`가 모든 진행 중 요청을 한 번의 호출로 묻습니다. 새 기능도 요청별 폴링 액션을 추가하면 안 됩니다.
- **`SettingPill`과 `SettingPopover`는 `useSettings()` 스토어를 직접 읽습니다**(`settings.tsx`). 편집기에서 재사용하려면 분리가 필요합니다.
- **디자인 토큰 33개가 `openhiggsfield.css`의 `.ohf` 블록에 선언되어 있습니다.** UI 글꼴은 `--font-ui` 한 곳에서 정해집니다.
- **`/api/blob`은 인증이 없습니다.** 업로드 경로는 `ohf_device` 쿠키로만 나뉩니다.
- **테스트 러너와 린터가 없습니다.** 정적 검사는 strict `tsc`뿐입니다.

## 4. 전체 구조

### 4.1 코드의 층

기존 규칙은 "`generation/`에는 UI를 두지 않고, UI는 따로 둔다"입니다. 새 코드도 같은 규칙을 따릅니다.

| 경로 | 역할 | 변화 |
| --- | --- | --- |
| `src/generation/` | 생성 엔진 | 거의 그대로 둡니다. `credentials.ts`만 운영자 키와 크레딧 차감으로 바뀝니다. |
| `src/service/` | 계정, DB, 크레딧 원장, 단가표 | 새로 만듭니다. UI 없음. |
| `src/projects/` | 프로젝트·슬롯 모델, 포맷 레지스트리, 프리셋, 구성안 생성, 저장소 | 새로 만듭니다. UI 없음. |
| `src/render/` | 슬라이드 템플릿과 렌더러(브라우저·서버 공용) | 새로 만듭니다. |
| `src/openhiggsfield/` | 스튜디오 UI | 전역 바가 추가되고, 키 모달이 빠집니다. |
| `src/editors/` | 포맷별 편집기 UI. `card-news/`부터 시작 | 새로 만듭니다. |
| `src/shell/` | 전역 바(스튜디오와 프로젝트가 함께 씀) | 새로 만듭니다. |
| `src/i18n/` | 한국어 UI 문자열(`ko.ts`) | 새로 만듭니다. `data.ts`의 영어 라벨을 옮겨 옵니다. |

### 4.2 화면 구조

- `/`: 기존 스튜디오. 그대로 둡니다.
- `/projects`: 프로젝트 목록과 새로 만들기.
- `/projects/new`: 포맷 선택과 브리프 입력.
- `/projects/[id]`: 포맷별 편집기.
- `/login`, `/account`: 로그인, 크레딧과 결제 내역.
- 전역 바: `Studio | Projects` 전환, 크레딧 잔액, 계정 메뉴.
- 플랫폼 키 입력 모달은 없앱니다. 크레딧 부족 모달이 그 자리를 대신합니다.

### 4.3 로드맵

| 단계 | 내용 |
| --- | --- |
| 0 | 서비스 기반(얇게): 계정, 서버 DB, 크레딧 원장(결제 없이 수동 충전), 운영자 키 전환, `/api/blob` 인증 |
| 1 | 공통 기반 + 카드뉴스 |
| 2 | 결제 연동(국내 PG). 심사에 시간이 걸리므로 1단계와 병행해 일찍 신청합니다. |
| 3 | 릴스 |
| 4 | 랜딩 페이지 |
| 이후 | 직접 게시, 계정 단위 브랜드 키트, 다국어 |

0단계를 먼저 하는 이유는 두 가지입니다.

- 운영자 키로 이미지와 카피를 생성하는 기능을 인증 없이 열면, 누구나 운영자 비용으로 호출할 수 있습니다.
- 프로젝트 데이터를 IndexedDB에 만들었다가 서버로 옮기는 이중 작업을 피합니다.

카드뉴스 설계는 서비스 기반의 인터페이스 세 개(5.5절)에만 의존합니다. 0단계의 세부 선택이 바뀌어도 카드뉴스 설계는 유효합니다.

## 5. 공통 기반

### 5.1 프로젝트와 슬롯

세 포맷이 같은 모양을 씁니다. 슬롯은 카드뉴스에서는 슬라이드, 릴스에서는 장면, 랜딩 페이지에서는 섹션입니다.

```ts
// src/projects/types.ts
type FormatId = "card-news" | "reels" | "landing";

interface Project {
  id: string;
  ownerId: string;
  format: FormatId;
  title: string;
  brief: Brief;
  preset: ChannelPresetId;
  style: ProjectStyle;
  slots: Slot[];                 // 배열 순서 = 슬라이드 순서
  caption?: { body: string; hashtags: string[] };
  createdAt: number;
  updatedAt: number;             // 저장 충돌 감지에 씀
}

interface Brief {
  topic: string;                 // 필수
  audience?: string;
  tone: "friendly" | "expert" | "witty" | "calm";
  slideCount: number;
  mustInclude?: string;
}

interface Slot {
  id: string;
  kind: string;                        // 포맷이 정의. 카드뉴스에서는 템플릿 id
  text: Record<string, string>;        // 템플릿이 선언한 글 필드
  options: Record<string, unknown>;    // 템플릿이 선언한 조절값
  gen?: { prompt: string };            // 배경 이미지 프롬프트
  pending?: { requestId: string; startedAt: number; holdId: string };
  media?: { assetId: string; url: string; persisted: boolean; crop?: { x: number; y: number } };
  error?: { code: "failed" | "nsfw" | "timeout"; message: string };
}
```

- 목록형 글 필드(예: 목록 템플릿의 `items`)는 줄바꿈으로 이어 붙인 문자열 하나로 저장합니다.
- 모델은 슬롯이 아니라 프로젝트의 `style.modelId`에 둡니다. 슬라이드마다 다른 모델을 쓰는 기능은 만들지 않습니다.
- 프로젝트 하나를 JSON 문서 하나로 저장합니다. 슬롯은 최대 20개이고 항상 함께 읽으므로 테이블을 나누지 않습니다.

### 5.2 포맷 레지스트리

지금 앱의 "카탈로그가 진실이고 UI는 거기서 파생된다"는 규칙을 포맷에도 적용합니다.

```ts
// src/projects/formats/index.ts
interface FormatEntry {
  id: FormatId;
  label: string;
  presets: ChannelPresetId[];
  defaultPreset: ChannelPresetId;
  slots: { min: number; max: number; default: number };
  slotKinds: SlotKindEntry[];
}

interface SlotKindEntry {
  id: string;
  label: string;
  fields: Record<string, TextFieldSpec>;
  options: Record<string, SettingField>;   // 카탈로그의 SettingField를 재사용
  media: "required" | "optional";
}

interface TextFieldSpec {
  label: string;
  maxChars: number;              // 목록형이면 항목 하나의 제한
  required: boolean;
  multiline?: boolean;
  list?: { min: number; max: number };
}
```

이 선언 하나를 세 곳에서 씁니다.

- 편집기의 옵션 UI를 기존 settings pill·popover 컴포넌트로 그립니다.
- LLM이 돌려준 구성안을 서버에서 검증합니다.
- 입력란의 글자 수 제한과 초과 경고를 적용합니다.

**선행 리팩터링**: `SettingPill`과 `SettingPopover`가 `useSettings()`를 직접 읽지 않고, 값과 변경 함수를 props로 받도록 바꿉니다. 스튜디오 쪽에는 스토어를 연결하는 얇은 래퍼를 둡니다.

### 5.3 채널 프리셋과 4:5 처리

프리셋은 최종 캔버스 크기와 생성 화면비 후보를 함께 선언합니다.

| 프리셋 | 캔버스 | 생성 화면비 후보(앞에서부터) |
| --- | --- | --- |
| `ig-feed-4x5` (기본) | 1080×1350 | 4:5, 3:4, 1:1, 9:16 |
| `ig-feed-3x4` | 1080×1440 | 3:4, 4:5, 1:1 |
| `ig-square` | 1080×1080 | 1:1, 3:4, 4:3 |
| `ig-vertical-9x16` | 1080×1920 | 9:16 |

- `resolveAspect(preset, model)`은 후보를 앞에서부터 보며, 모델의 카탈로그 `aspectRatio` 목록에 있는 첫 값을 고릅니다. `auto`는 고르지 않습니다.
- 맞는 후보가 하나도 없는 모델은 프로젝트의 모델 목록에서 뺍니다.
- 지금은 image 모델 8개가 모두 3:4를 지원하므로, 4:5 프리셋에서는 3:4로 생성합니다. 3:4를 4:5로 자르면 높이의 6.25%만 잘립니다. 자를 위치는 `media.crop`에 저장하고 기본값은 가운데입니다.
- 쓰레드는 같은 화면비를 쓰므로 프리셋을 따로 두지 않습니다.
- 슬롯 수 상한은 프리셋에 값으로 둡니다. 인스타그램과 쓰레드 모두 슬라이드 20개로 알고 있으나, 구현 시점에 다시 확인합니다(아래 "10. 구현 전에 확인할 항목" 참고).

### 5.4 에셋 영속화

저장해 둔 프로젝트의 이미지가 나중에 깨지면 유료 서비스로서 치명적입니다. **슬롯에 채택한 에셋은 Vercel Blob으로 복사합니다.**

- 생성이 완료되어 슬롯에 들어갈 때 서버가 CDN에서 파일을 받아 Blob에 저장합니다.
- 복사가 끝나면 `media.url`을 Blob 주소로 바꾸고 `persisted: true`로 표시합니다.
- 이렇게 하면 내보내기와 미리보기가 플랫폼 CDN의 CORS와 보존 기간에 의존하지 않습니다.
- 채택하지 않은 대안 이미지는 지금처럼 히스토리에 CDN 링크로만 남깁니다.

### 5.5 서비스 기반에 요구하는 인터페이스

```ts
currentUser(): Promise<User | null>

credits.quote(plane: GenerationPlane): number
credits.hold(userId, amount, key): Promise<HoldId>      // key로 중복 차감 방지
credits.confirm(holdId): Promise<void>
credits.release(holdId): Promise<void>

interface ProjectRepo {
  list(ownerId): Promise<ProjectSummary[]>
  get(id, ownerId): Promise<Project | null>
  create(project): Promise<Project>
  update(project, baseUpdatedAt): Promise<Project>      // updatedAt이 다르면 거부
  delete(id, ownerId): Promise<void>
}
```

`ProjectRepo`는 메모리 구현을 함께 제공합니다. 기존 `memoryKv`와 같은 목적입니다.

### 5.6 카피 생성

- 서버 액션이 Claude API를 구조화 출력(JSON 스키마)으로 호출합니다.
- 환경변수: `ANTHROPIC_API_KEY`, `OUTLINE_MODEL`(기본 `claude-sonnet-5`).
- LLM 클라이언트는 주입 가능하게 만들어, 테스트에서 가짜로 바꿉니다.
- 고객이 쓴 글(`topic`, `mustInclude`)이 LLM에 들어가지만, 도구 호출이 없고 출력은 스키마와 레지스트리로 검증하므로 위험이 낮습니다.

## 6. 카드뉴스 상세

### 6.1 제작 흐름

1. **브리프**: `/projects/new`에서 포맷을 고르고 주제를 씁니다. 주제만 필수이고, 대상 독자·톤·장수(4~10, 기본 8)·채널 규격·꼭 넣을 내용은 기본값이 있습니다. 브리프의 장수는 LLM에 요청하는 수입니다. 편집기에서는 프리셋의 상한까지 슬라이드를 더 추가할 수 있습니다.
2. **구성안 생성**: LLM이 슬라이드별 템플릿·문구·이미지 프롬프트, 덱의 이미지 스타일 문구, 캡션과 해시태그를 한 번에 돌려줍니다.
3. **구성안 검토**: 글만 채워진 상태로 편집기가 열립니다. 캔버스는 스타일의 단색 배경 위에 글을 얹어 보여 주므로, 이미지가 없어도 덱을 읽어 볼 수 있습니다. 고객이 문구를 고치고, 순서를 바꾸고, 줄을 추가·삭제합니다.
4. **이미지 생성**: "남은 N장 생성"을 누르면 빈 슬라이드를 한꺼번에 생성합니다. 누르기 전에 크레딧 합계를 보여 줍니다.
5. **다듬기**: 슬라이드별로 템플릿, 옵션, 배경을 조절합니다. 스타일 패널에서 덱 전체의 글꼴과 색을 바꿉니다.
6. **내보내기**: PNG 묶음(ZIP)과 캡션을 받습니다.

크레딧이 크게 나가는 것은 4단계뿐입니다. 고객은 글을 확정한 뒤에 이미지 비용을 씁니다.

### 6.2 편집기 레이아웃 (H1)

원칙은 **"왼쪽은 글, 오른쪽은 그림"**입니다.

```
┌ 전역 바: [Studio | Projects]                     크레딧 1,240  [계정] ┐
├ ← 프로젝트  제목  [카드뉴스] [4:5]                 [스타일] [내보내기] ┤
├──────────────────────────────────────┬───────────────────────────────┤
│ ① 브리프 바: 주제 · 장수 · 톤  [구성안 다시 뽑기] │ ③ [슬라이드 | 휴대폰]   ‹ 1/8 › │
├──────────────────────────────────────┤                               │
│ ② 스토리보드 목록                      │        큰 캔버스 (4:5)         │
│ ▌1 [썸네일] 표지  제목 / 부제   [프롬프트] │                               │
│  2 [썸네일] 본문  제목 / 본문   [프롬프트] │                               │
│  3 [생성중] 목록  제목 / 항목   [프롬프트] ├───────────────────────────────┤
│  4 [ 빈칸 ] 인용  인용문 / 출처 [프롬프트] │ ④ 템플릿: 표지 본문 목록 인용 CTA │
│  …                                   │    옵션: 위치 · 크기 · 어둡게     │
├──────────────────────────────────────┤    [다시 생성 · N] [에셋에서 고르기]│
│ ⑤ 실행 띠: 빈 슬라이드 4장  [+ 슬라이드] [남은 4장 생성 · 16 크레딧] │          │
└──────────────────────────────────────┴───────────────────────────────┘
```

| 영역 | 역할 |
| --- | --- |
| ① 브리프 바 | 주제·장수·톤을 고쳐 구성안을 다시 뽑습니다. 스튜디오의 프롬프트 바와 같은 자리입니다. |
| ② 스토리보드 목록 | 슬라이드 한 장이 한 줄입니다. 문구와 배경 프롬프트를 줄에서 바로 고칩니다. 줄을 고르면 왼쪽에 라임색 막대가 생기고 캔버스에 그 슬라이드가 나옵니다. 끌어서 순서를 바꿉니다. 줄마다 "다시 쓰기", 복제, 삭제가 있습니다. |
| ③ 큰 캔버스 | 내보낼 결과와 같은 렌더러로 그립니다. `휴대폰`으로 바꾸면 인스타그램처럼 옆으로 넘겨 봅니다. |
| ④ 보이는 방식 | 템플릿과 옵션, 배경 교체입니다. 배경은 다시 생성하거나 스튜디오 에셋에서 고릅니다(기존 asset picker 재사용). 캔버스에서 배경 이미지를 끌어 자를 위치(`media.crop`)를 맞춥니다. 슬라이드 한 장만 PNG로 받을 수도 있습니다. |
| ⑤ 실행 띠 | 빈 슬라이드를 한 번에 생성합니다. 오류와 실행 취소도 새 레이어 없이 여기에 표시합니다. 지금 컴포저의 규칙과 같습니다. |

세부 규칙은 다음과 같습니다.

- 목록과 캔버스의 경계를 끌어 비율을 조절할 수 있습니다. 기본은 56:44이고, 조절한 값은 브라우저에 기억합니다.
- 약 1100px보다 좁은 화면에서는 캔버스 패널을 접고 버튼으로 엽니다. 1차는 데스크톱 우선입니다.
- 한 화면에 강조(라임색) 버튼은 하나만 둡니다. 생성할 슬라이드가 남아 있으면 "남은 N장 생성"이, 모두 채워지면 "내보내기"가 강조 버튼입니다.
- 생성 중에도 편집기는 잠기지 않습니다. 지금 스튜디오의 규칙과 같습니다.
- 줄은 기본, hover, 선택, 편집 중, 생성 중, 실패, 글자 수 초과, 끄는 중의 모든 상태를 갖춥니다.
- 키보드: ↑↓로 줄 이동, ⌘Enter로 남은 슬라이드 생성.

### 6.3 슬롯 상태

프로젝트에 "진행 단계" 필드를 두지 않고, 슬롯에서 계산합니다. 우선순위는 위에서부터입니다.

| 조건 | 상태 | 썸네일 |
| --- | --- | --- |
| `pending`이 있음 | 생성 중 | 스켈레톤 + 라임색 점 |
| `error`가 있음 | 실패 | 오류 표시 + "다시 시도" |
| `media`가 있음 | 완성 | 이미지 |
| 그 외 | 빈 슬롯 | 점선 빈칸 |

- 이미지를 다시 생성하는 동안에는 `pending`과 `media`가 함께 있습니다. 새 이미지가 도착할 때까지 캔버스는 이전 이미지를 계속 보여 줍니다.
- "남은 N장"은 `gen.prompt`가 있고 `media`와 `pending`이 없는 슬롯의 수입니다. 프롬프트가 빈 CTA는 세지 않습니다. 실패한 슬롯은 포함하며, 다시 생성을 시작할 때 `error`를 지웁니다.
- 새로고침하거나 다시 열면 `pending.requestId`로 폴링을 이어 갑니다. 제한 시간은 `startedAt`에서 계산하므로 원래 값이 유지됩니다.

### 6.4 템플릿 5종

| 템플릿 | 글 필드(최대 글자 수) | 옵션(기본값) | 이미지 |
| --- | --- | --- | --- |
| `cover` 표지 | 꼬리표 12(선택), 제목 28, 부제 24(선택) | 위치 위·가운데·아래(아래), 제목 크기 작게·보통·크게(크게), 어둡게 0~80(40) | 필요 |
| `body` 본문 | 제목 24, 본문 90 | 위치(아래), 어둡게(55) | 필요 |
| `list` 목록 | 제목 20, 항목 3~5개에 항목당 24 | 번호 표시(켬), 어둡게(75) | 선택 |
| `quote` 인용 | 인용문 60, 출처 20(선택) | 위치(가운데), 어둡게(60) | 선택 |
| `cta` CTA | 제목 24, 부제 30(선택) | 위치(가운데), 어둡게(60) | 선택. 기본은 단색 배경 |

- 어둡게는 `{ type: "range", min: 0, max: 80, step: 5 }`로 선언합니다.
- 모든 템플릿 아래쪽에 계정 핸들과 쪽 번호(`3 / 8`)가 들어갑니다. 스타일에서 끌 수 있습니다.
- 줄바꿈은 어절 단위로 하고, 제목은 줄 길이를 고르게 맞춥니다.
- 표지는 가장자리에 안전 여백을 둡니다. 인스타그램 프로필 그리드에서 가장자리가 잘려도 제목이 잘리지 않게 하기 위해서입니다.
- 구성안 규칙: 첫 슬라이드는 표지, 마지막 슬라이드는 CTA입니다.

### 6.5 스타일

```ts
interface ProjectStyle {
  styleId: "basic" | "editorial" | "impact" | "soft";
  palette: { bg: string; text: string; accent: string };
  fontPair: "pretendard" | "serif" | "impact" | "soft";
  handle?: string;            // 예: "@sunny.skin.lab"

  imageStyle: string;         // 예: "따뜻한 필름 톤, 자연광, 여백 많은 구도"

}
```

| 스타일 | 글꼴 | 색 | 어울리는 주제 |
| --- | --- | --- | --- |
| 기본 고딕 (기본값) | Pretendard | 남색, 흰색, 노랑 | 범용 |
| 에디토리얼 | Noto Serif KR 제목 + Pretendard 본문 | 크림, 짙은 갈색, 벽돌색 | 매거진, 뷰티, 라이프스타일 |
| 임팩트 | Black Han Sans 제목 + Pretendard 본문 | 검정, 흰색, 주홍 | 정보성, 뉴스, 할인 공지 |
| 부드럽게 | Gowun Dodum | 세이지, 짙은 초록, 초록 | 육아, 웰니스, 카페 |

- 스타일을 고른 뒤 색 세 개는 직접 바꿀 수 있습니다.
- 글꼴은 모두 OFL 라이선스라서 상업 이용과 이미지 출력에 제약이 없습니다.
- 로고 넣기와, 스타일을 계정에 저장해 재사용하는 기능은 브랜드 키트 단계로 미룹니다.

### 6.6 구성안 생성

```ts
// LLM이 돌려주는 모양
interface Outline {
  title: string;
  imageStyle: string;
  slides: { kind: string; text: Record<string, string>; imagePrompt?: string }[];
  caption: { body: string; hashtags: string[] };
}
```

- 서버 액션 `draftOutline(projectId)`가 브리프와 포맷 레지스트리(템플릿 목록, 필드, 글자 수 제한)를 LLM에 주고 `Outline`을 받습니다.
- `validateOutline`이 템플릿 id, 필수 필드, 글자 수, 목록 항목 수, "첫 장 표지·마지막 장 CTA" 규칙을 검사합니다.
- 제한을 넘은 슬라이드는 그 슬라이드만 한 번 자동으로 다시 쓰게 합니다. 그래도 넘으면 글을 자르지 않고 그대로 넣고, 그 줄에 글자 수 초과 경고를 표시합니다.
- 이미지 프롬프트는 영어로 받습니다. 이미지 모델이 영어 프롬프트를 더 잘 따르기 때문입니다. 고객은 줄에서 한국어로 고쳐 써도 됩니다.
- 캡션 본문은 400자 안쪽, 해시태그는 5~10개를 목표로 요청합니다. 쓰레드의 글자 수 제한에도 들어가는 길이입니다.
- `rewriteSlot(projectId, slotId, instruction)`은 같은 경로로 슬라이드 하나만 다시 씁니다. "더 짧게", "숫자를 넣어서" 같은 지시를 받습니다.
- "구성안 다시 뽑기"는 슬롯 전체를 덮어씁니다. 이미 생성한 이미지를 잃을 수 있으므로, 실행 띠에 실행 취소를 띄웁니다.

### 6.7 이미지 생성

슬롯에서 `GenerationPlane`을 조립해 기존 파이프라인에 넘깁니다.

```ts
// src/projects/plane.ts
function slotPlane(project: Project, slot: Slot): GenerationPlane
```

- `model`: `project.style.modelId`
- `prompt.text`: 슬롯 프롬프트 + 덱의 `imageStyle` + 글 위치에 따른 여백 문구 + "글자, 로고, 워터마크 없음"
  - 여백 문구는 템플릿의 위치 옵션에서 만듭니다. 글이 아래에 오면 "아래 3분의 1에 여백"을 요청합니다.
  - 글자는 별도 레이어로 얹으므로, 이미지 안에 글자가 생기지 않게 막아야 합니다.
- `settings`: `parseSettings`로 기본값을 채우고, `aspectRatio`는 `resolveAspect` 결과로, 결과 개수 키(`numImages` 또는 `batchSize`)는 1로 고정합니다.
- `media`: 비워 둡니다. 표지 이미지를 나머지 슬라이드의 reference로 넣어 통일감을 높이는 방법은 1차 범위에서 뺍니다.

서버 액션은 두 개입니다.

- `generateSlots(projectId, slotIds)`: **액션 하나가 모든 슬롯을 서버에서 병렬로 제출합니다.** Next가 클라이언트당 서버 액션을 하나씩 처리하므로, 슬롯마다 액션을 부르면 줄이 섭니다. 슬롯마다 견적 → 크레딧 예약 → `submitGeneration` → `pending` 기록 순서로 처리합니다.
- `settleSlot(projectId, slotId)`: 클라이언트의 `watchRequest`가 끝나면 부릅니다. **서버가 플랫폼 상태를 직접 다시 확인한 뒤** 처리합니다. 클라이언트가 보낸 결과는 믿지 않습니다.
  - `completed`: 에셋을 Blob으로 복사하고, `media`를 채우고, 예약을 확정합니다.
  - `failed`, `nsfw`, 시간 초과: `error`를 채우고 예약을 해제합니다.

고객이 탭을 닫아 `settleSlot`이 불리지 않은 경우를 위해, 서버는 크레딧 잔액을 조회할 때 오래된 예약의 플랫폼 상태를 확인해 정리합니다. 별도의 예약 작업(cron)은 두지 않습니다.

슬롯 생성 결과도 기존 에셋 풀에 들어갑니다. 스튜디오의 Assets 보기에서 보이고, 반대로 스튜디오에서 만든 이미지를 슬롯 배경으로 고를 수 있습니다.

### 6.8 렌더러

**원칙: 미리보기와 내보내기가 같은 레이아웃 엔진을 씁니다.** 편집 중에 본 줄바꿈과 내려받은 PNG의 줄바꿈이 다르면 고객은 결과물을 믿지 못합니다.

- **권장: Satori**(JSX를 SVG로 바꾸는 라이브러리)를 브라우저와 서버 양쪽에서 씁니다.
  - 템플릿은 `src/render/card-news/templates/`의 컴포넌트 다섯 개입니다. `(slot, style, preset) → JSX`인 순수 함수입니다.
  - 브라우저: 글자 레이어만 SVG로 그려서, CSS로 깐 배경 이미지와 어둡게 레이어 위에 얹습니다. 입력할 때마다 다시 그립니다.
  - 서버: 같은 템플릿에 배경까지 넣어 Satori로 그린 뒤 PNG로 변환합니다.
  - 헤드리스 브라우저가 필요 없어서 Vercel에서 가볍고 빠릅니다.
- **제약**: 템플릿의 CSS는 flexbox 범위 안에서만 씁니다. 글꼴은 woff2가 아닌 형식으로 직접 공급합니다. 한글 글꼴은 용량이 크므로 상용 한글 2,350자와 기호로 부분집합을 만듭니다.
- **구현의 첫 작업은 스파이크입니다.** Satori가 아래 세 가지를 제대로 처리하는지 확인합니다. 지원하는 것으로 알고 있으나 검증하지는 못했습니다.
  - 한글의 어절 단위 줄바꿈(`word-break: keep-all`)
  - 제목의 줄 길이 맞춤(`text-wrap: balance`)
  - 이모지 표시
- **대안**: 스파이크가 실패하면 서버의 헤드리스 Chrome으로 스크린샷을 찍습니다. CSS 제약이 없는 대신 무겁고 느리며, 브라우저마다 미리보기 줄바꿈이 조금 다를 수 있습니다. 이 경우 내보내기 창의 썸네일을 실제 렌더링 결과로 보여 주어 차이를 미리 확인하게 합니다.

### 6.9 내보내기

- `GET /api/projects/[id]/export?format=png|jpg`: 인증된 route handler입니다. 프로젝트를 읽어 슬라이드를 프리셋 캔버스 크기로 렌더링하고, `01.png`~`NN.png`와 `caption.txt`를 ZIP으로 묶어 스트림으로 내려 줍니다. 파일을 돌려줘야 하므로 서버 액션이 아니라 route handler로 만듭니다.
- `GET /api/projects/[id]/slides/[n]`: 슬라이드 한 장만 받습니다.
- 내보내기 창에서 캡션과 해시태그를 고치고 복사합니다.
- 이미지가 없는 슬라이드는 단색 배경으로 나갑니다. 일부러 이미지를 넣지 않는 템플릿도 있으므로 막지 않고 알려만 줍니다.
- 내보내기에는 크레딧을 쓰지 않습니다.

### 6.10 오류 처리

| 상황 | 처리 |
| --- | --- |
| 구성안 LLM 호출이 실패하거나 시간 초과 | 브리프를 보존하고, 실행 띠에 오류와 "다시 시도"를 띄웁니다. 크레딧은 성공했을 때만 차감합니다. |
| LLM 출력이 글자 수 제한을 넘음 | 넘은 슬라이드만 한 번 자동으로 다시 씁니다. 그래도 넘으면 그대로 넣고 그 줄에 경고를 표시합니다. |
| 이미지 생성이 `failed` 또는 `nsfw`로 끝남 | 그 줄에만 오류를 표시하고 예약한 크레딧을 해제합니다. `nsfw`이면 프롬프트를 고치라고 안내합니다. 다른 줄은 영향을 받지 않습니다. |
| 크레딧 부족 | 생성 전 견적 단계에서 막고, 부족한 양을 알려 주고, 충전 화면으로 안내합니다. |
| 같은 요청이 두 번 차감될 위험 | 슬롯 ID와 시도 번호로 만든 키로 예약의 중복을 막습니다. |
| 채택한 에셋의 Blob 복사가 실패 | 슬롯은 CDN 주소로 채택하고 `persisted: false`로 둡니다. 다음 저장이나 내보내기 때 복사를 다시 시도합니다. |
| 두 탭에서 같은 프로젝트를 수정 | `updatedAt`이 다르면 저장을 거부하고, "다른 탭에서 수정됨 · 새로 불러오기"를 실행 띠에 띄웁니다. |
| 폴링이 연속 3회 실패 | 기존 `poll.ts`의 동작을 따릅니다. 슬롯의 `pending`은 남겨 두므로 다시 열면 이어서 확인합니다. |
| 내보내기 렌더링 실패 | 몇 번째 슬라이드에서 실패했는지 알려 줍니다. |

자동 저장은 입력이 멈춘 뒤 짧은 지연을 두고 실행합니다. 저장도 서버 액션이므로 폴링 호출과 같은 줄에 섭니다. 폴링은 4초 간격의 짧은 호출이라 체감 지연은 작을 것으로 보지만, 구현할 때 확인합니다.

### 6.11 크레딧

- 이미지: 모델별 단가표(`src/service/pricing.ts`)로 견적을 냅니다. 단가표는 카탈로그에 넣지 않습니다. 카탈로그는 플랫폼의 사실이고 가격은 사업상 결정이기 때문입니다.
- 구성안 생성과 다시 뽑기: 소액을 차감합니다. 이미지와 같은 예약 → 확정 경로를 쓰므로, LLM 호출이 실패하면 예약을 해제합니다.
- 슬라이드 하나 다시 쓰기: 무료로 하고 속도 제한만 겁니다.
- 내보내기: 무료입니다.
- 실제 수치는 서비스 기반 기획에서 정합니다. 목업에 쓴 "4 크레딧"은 예시입니다.

### 6.12 기존 디자인 원칙과의 관계

- **강조색은 상태에만 씁니다.** 편집기에서 라임색은 선택한 줄의 막대, 선택한 템플릿 칩, 강조 버튼 하나, 생성 중 표시에만 씁니다.
- **움직임은 상태를 전합니다.** 썸네일이 도착할 때 갤러리와 같은 도착 모션을 씁니다. 장식용 반복 애니메이션은 넣지 않습니다.
- **UI를 한국어로 바꿉니다.** 문자열을 `src/i18n/ko.ts` 한곳에 모읍니다. `data.ts`의 영어 라벨도 이쪽으로 옮깁니다. 다국어로 확장할 여지를 남기기 위해서입니다.
- **앱 글꼴을 Pretendard로 바꿉니다.** 지금 원칙은 "Inter만 쓴다"인데 Inter에는 한글이 없습니다. Pretendard의 영문·숫자는 Inter 기반이므로, 단일 서체와 고정폭 숫자라는 원칙은 유지됩니다. 고칠 곳은 `--font-ui` 한 군데입니다.
- **토큰을 분리합니다.** `.ohf`에 선언된 디자인 토큰을 별도 파일로 빼서, 스튜디오와 편집기가 함께 씁니다. 편집기 스타일시트도 `.ohf` 아래에 `ohf-` 접두어로 씁니다.
- 슬라이드 안의 글꼴과 색은 고객의 콘텐츠이므로 앱의 디자인 원칙을 적용하지 않습니다.

## 7. 테스트

Vitest를 도입하고 단위 테스트까지만 합니다. 화면 전체를 자동으로 돌리는 E2E 테스트는 1차 범위에서 빼고 수동 확인 목록으로 대신합니다.

- `validateOutline`: 템플릿 id, 필수 필드, 글자 수, 목록 항목 수, 첫 장·마지막 장 규칙
- `resolveAspect`: 후보 순서, `auto` 제외, 맞는 후보가 없는 모델
- `slotPlane`: 프롬프트 조립, 화면비, 결과 개수 1 고정
- 슬롯 상태 계산과 "남은 N장" 계산
- `ProjectRepo` 메모리 구현: 저장 충돌 거부
- 크레딧 예약·확정·해제와 중복 키
- 템플릿 렌더링 스냅샷. Satori는 같은 입력에 같은 SVG를 내므로 스냅샷 비교가 가능합니다.
- 구성안 생성: 가짜 LLM 클라이언트로 정상, 제한 초과 후 재작성, 호출 실패를 확인

## 8. 1단계의 구현 순서

1. 렌더러 스파이크: Satori의 한글 줄바꿈, 줄 길이 맞춤, 이모지, 글꼴 부분집합 용량을 확인하고 렌더러를 확정합니다.

## 9. 나머지 조각의 개요

### 9.1 서비스 기반 (0단계, 별도 기획 필요)

- **인증**: 이메일 매직링크와 카카오·구글 소셜 로그인. 라이브러리는 상세 기획에서 고릅니다.
- **DB**: Postgres. 테이블은 사용자, 프로젝트(JSON 문서), 에셋, 크레딧 원장, 생성 요청입니다.
- **크레딧**: 원장은 추가만 가능한 구조로 둡니다. 예약 → 확정 또는 해제의 세 동작을 제공합니다.
- **운영자 키**: 환경변수로 옮깁니다. `credentials.ts`가 쿠키 대신 환경변수에서 읽고, 키 입력 모달은 없앱니다.
- **남용 방지**: 가입 시 무료 크레딧은 소량, 사용자별 동시 생성 수와 속도 제한, `/api/blob` 인증과 사용자별 용량 상한.
- **히스토리**: IndexedDB에서 서버의 에셋 테이블로 옮깁니다. 기존 로컬 히스토리를 서버로 이전하는 기능은 만들지 않는 것으로 가정했습니다.
- **결제**: 국내 PG를 통한 크레딧 충전형으로 시작합니다. 구독은 이후로 미룹니다.
- **준비할 문서**: 이용약관, 개인정보처리방침, 생성물 저작권 고지, 환불 정책.

### 9.2 릴스 (3단계)

- 슬롯은 장면입니다. 장면마다 프롬프트, 9:16 영상 클립, 자막 한 줄을 가집니다.
- LLM이 "첫 3초 훅 → 전개 → CTA" 구조로 장면을 짭니다.
- 영상은 이미지보다 훨씬 비쌉니다. 장면별 이미지로 스토리보드를 먼저 확인하고, 확정한 장면만 영상으로 만듭니다. 카탈로그에 이미 있는 `start` 역할을 그대로 씁니다.
- 편집기 골격은 H1과 같습니다. 목록은 장면, 캔버스는 세로 플레이어입니다.
- 새로 필요한 것: 클립 이어 붙이기, 자막 입히기, 배경음, 커버 이미지 선택.
- 미정: 합성을 서버의 ffmpeg로 할지 브라우저에서 할지, 배경음의 라이선스.

### 9.3 랜딩 페이지 (4단계)

- 슬롯은 섹션입니다(히어로, 특징, 후기, 가격, FAQ, CTA). 템플릿은 섹션 컴포넌트입니다.
- 렌더링은 Satori가 아니라 실제 반응형 HTML로 합니다. 미리보기는 iframe에서 데스크톱 폭과 모바일 폭을 전환합니다.
- 1차 내보내기는 정적 HTML ZIP입니다. 호스팅, 커스텀 도메인, 폼 수집은 그 뒤 단계입니다.
- 가장 작은 첫 버전으로 인스타그램 프로필에 거는 링크 페이지가 적당합니다. 카드뉴스·릴스와 같은 고객이 바로 씁니다.
