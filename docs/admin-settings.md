`/login`은 아이디와 이메일 모두 지원한다. `/admin/users`에서 사용자 검색, `/admin/credits`에서 크레딧 지급 및 사용자별/전체 사용 내역을 확인한다. 지급에는 양의 정수 금액과 사유가 필요하며 처리한 관리자와 중복 방지 키를 함께 기록한다. 일반 사용자는 `/account`에서 본인 내역만 볼 수 있다.

## 관리자 접속 IP

`pnpm dev`와 `pnpm start`는 `scripts/server.mjs`를 사용한다. 서버가 실제 TCP 접속 IP를 서명하고 관리자 로그인과 이후 요청마다 이를 검사한다. 임의의 `X-Forwarded-For`, `X-Real-IP`, 서명 위조로 권한을 얻을 수 없다. `next dev`를 직접 실행하면 유효한 서명이 없어 관리자 접근이 거절된다.

기본 허용 목록은 루프백과 서버 PC의 네트워크 인터페이스 주소다. 정확한 주소를 고정하려면 `.env.local`의 `ADMIN_ALLOWED_IPS`에 쉼표로 구분한 IP를 지정한다. 현재 목록은 관리자 화면 하단에 표시된다. 허용 IP 이외에서는 올바른 관리자 비밀번호와 기존 세션을 가지고 있어도 접근할 수 없다.

현재 방식은 Node 서버 직접 접속을 전제로 한다. 리버스 프록시는 접속 IP를 프록시 주소로 바꾸므로 이 구성을 그대로 프록시 뒤에 배포하지 않는다. 원격 배포 시 신뢰 프록시와 실제 클라이언트 IP 검증 정책을 먼저 구성해야 한다. 운영에서는 PostgreSQL과 HTTPS도 필요하다.

## 관리자 전용 환경설정

관리자 로그인 후 `/admin/settings`에서 `API Key ID:API Key Secret` 형식으로 키를 저장한다. ID만으로는 인증할 수 없다. 입력란은 비밀번호형이며 저장 후 비운다. 설정 조회에는 등록 여부, 저장 시각, 키 출처만 포함한다. 일반 사용자는 메뉴가 보이지 않고 직접 접근해도 설정 페이지와 API 모두 차단된다.

저장한 키는 모든 로그인 사용자의 스튜디오·카드뉴스·릴스·랜딩 생성에 사용된다. 작업마다 사용자 잔액과 소유권을 검사한다. 키를 교체해도 이미 접수한 작업은 접수 당시 암호화한 키로 상태를 조회한다. 관리자 키 삭제 시 환경 변수 `HF_OPERATOR_API_KEY`가 있으면 해당 키로 전환된다.

키는 AES-256-GCM으로 암호화한다. 개발 환경에서는 `.data/secrets/provider.key`를 자동 생성하고 운영에서는 32바이트 Base64 `PROVIDER_ENCRYPTION_KEY`를 요구한다. 암호화 키는 DB와 함께 안전하게 백업하며 Git에 넣지 않는다. 기존 데이터를 보존하려면 암호화 키를 임의로 교체하지 않는다.

연결 점검은 상태 조회만 수행하며 유료 생성을 실행하지 않는다. 이전 요청 조회 성공은 인증 확인으로 표시하지만 요청이 없어 받은 404는 서버 응답 확인으로만 표시한다. 실제 모델 권한·잔액·결과 생성 여부는 별도 생성 테스트가 필요하다. [공식 Higgsfield 문서](https://docs.higgsfield.ai/docs/how-to/introduction)와 [공식 SDK 인증 안내](https://github.com/higgsfield-ai/higgsfield-js)를 기준으로 서버에서만 인증 헤더를 전송한다.

## 검증 범위

- 로컬 HTTP/인앱 브라우저: 일반 계정과 관리자 로그인, 설정 접근 분리, 관리자 원장, 실제 DB 지급 및 중복 지급 방지를 확인했다.
- 등록된 실제 Higgsfield 키로 스튜디오 Soul 2 이미지 1건, 카드뉴스 이미지 1건, 랜딩 이미지 1건, Kling 3.0 Turbo 릴스 영상 1건을 생성했다. 4건 모두 완료, 프로젝트 자동 적용·저장 및 상태 조회 인증 성공을 확인했다. 앱 크레딧 44를 사용해 관리자 잔액은 156이다. 공급자 청구액은 조회하지 않았다.
- 실제 생성 에셋으로 PNG 1080×1350, WebM VP9 720×1280, 이미지·글꼴을 포함한 HTML ZIP 출력을 확인했다. 기록은 `docs/qa/live-api-validation.json`과 `live-*` 파일에 보관한다. 나머지 모델 전체, AI 텍스트 구성안, 운영 배포는 이번 검증에 포함하지 않는다.


## 생성 결과와 내 라이브러리

관리자 왼쪽 메뉴의 **전체 에셋**에서 `/admin/results`로 이동한다. 사용자 목록의 **결과 보기**는 해당 사용자의 ID로 범위를 고정한다. 결과 페이지에서는 사용자 아이디/이름/이메일 검색, 기능, 파일 형식, 프로젝트/파일명/프롬프트 검색을 조합할 수 있다.

사용자는 **마이페이지 첫 화면의 내 라이브러리**(`/account`, 기존 `/account/library`는 자동 이동)에서 본인 결과를 조회하고 이미지·영상·오디오를 직접 업로드한다. 기존 파일당 50MB·계정당 500MB 한도를 적용하고 서버가 소유자를 지정한다. 업로드에는 생성 크레딧을 사용하지 않는다. 카드 상세에서 이미지 확대, 영상/오디오 재생, 원본 열기/저장을 지원한다.

생성 결과는 완료된 `generation_jobs`에서 모든 이미지와 영상을 펼쳐 조회한다. 스튜디오 이미지/영상, 카드뉴스, 릴스, 랜딩 페이지로 분류하며 삭제된 프로젝트의 완료 결과도 유지한다. 보관 파일은 `assets`의 업로드·출력·생성 사본이다. 동일 생성의 원본과 저장 사본이 각각 표시될 수 있으며 기능 필터로 구분한다. 24개 단위로 페이지를 제공해 기존 에셋 선택기의 100건 제한과 무관하게 전체를 조회한다. 별도 DB 복제나 스키마 변경은 필요하지 않다.

일반 사용자 API는 전달된 사용자 필터를 신뢰하지 않고 로그인 사용자로 범위를 고정한다. 관리자 목록·다른 사용자의 파일 조회는 관리자 역할 및 기존 로컬 IP 검사를 통과해야 한다. 공급자 링크의 만료와 서버 계정 도입 전 브라우저에만 남은 기록은 이 목록이 해결하지 않는다. 생성 중·실패 요청은 결과 목록 대신 기존 생성 내역에서 확인한다.

검증: 전체 19개 자동 테스트 및 프로덕션 빌드 통과. 일반 사용자 업로드/새로고침, 관리자 복합 필터, 다른 사용자 파일 404 및 관리자 API 403, 비로그인 401을 확인했다. 390px 모바일에서 가로 넘침이 없었다. 증거는 `docs/qa/library-*`에 보관한다. user1에 업로드 검증용 `live-card.png` 1건을 남겼으며 이번 검증은 유료 생성을 실행하지 않았다.


## 마이페이지 사이드바 개편

마이페이지 첫 화면에 에셋 목록을 표시하며 업로드는 상단 버튼으로 여는 창에서 처리한다. 왼쪽 메뉴는 내 라이브러리, 내 프로젝트, 생성 내역, 크레딧, 계정 정보, 알림 설정, 결제 및 구독으로 구성했다. 모바일에서는 같은 메뉴를 가로로 넘길 수 있다. 로그아웃은 사이드바에 유지한다.

프로젝트 목록·검색, 생성 상태 필터, 크레딧 잔액·최근 100건 원장, 계정 정보 조회는 실제 API에 연결한다. 알림 설정·결제/구독·프로필 수정·이메일 인증·비밀번호 변경은 준비 중인 디자인 목업이며 입력과 실행 버튼을 비활성화했다. 예시 상태와 실제 계정 데이터를 구분해 표시한다. 원장과 생성 요청은 기존 API의 최근 100건 범위를 유지하고, 에셋 라이브러리는 전체 페이지 조회를 지원한다.

검증은 메뉴 이동, 첫 화면 에셋 목록, 생성 상태 필터, 크레딧 원장, 업로드 창 저장, 준비 중 버튼 비활성화 및 모바일 레이아웃을 포함한다. 타입 검사와 프로덕션 빌드를 통과했다.


## 관리자 사이드바와 운영 페이지

사용자 마이페이지와 같은 디자인 토큰·사이드바 구조를 적용한다. 데스크톱은 왼쪽 고정 메뉴, 좁은 화면은 가로 스크롤 메뉴를 제공한다. 모든 메뉴는 실제 서버 데이터와 연결되어 있다.

| 메뉴 | 경로 | 기능 |
| --- | --- | --- |
| 대시보드 | `/admin` | 사용자·활성 프로젝트·생성 요청·보관 파일/용량 집계, 크레딧 잔액과 누적 지급·예약·환불, 최근 요청, 허용 IP |
| 사용자 관리 | `/admin/users` | 아이디/이름/이메일 검색, 권한 필터, 가입 정보와 작업 수, 사용자 상세에서 프로젝트·생성·에셋·크레딧 연결 |
| 프로젝트 관리 | `/admin/projects` | 사용자/제목/포맷/활성·삭제 보관 필터, 읽기 전용 기획·슬라이드 구성 상세 |
| 생성 내역 | `/admin/activity` | 사용자/기능/상태/모델·프롬프트·요청 ID 검색, 요청 상세와 크레딧, 접수 확인 필요 상태 안내 |
| 전체 에셋 | `/admin/results` | 모든 생성 결과와 사용자 업로드·보관 파일, 사용자/기능/형식/검색 필터와 미리보기 |
| 크레딧 관리 | `/admin/credits` | 대상 검색, 크레딧 지급, 사용자·유형별 원장과 지급 관리자, 중복 지급 방지 |
| API 환경설정 | `/admin/settings` | 기존 공용 키 저장·교체·삭제 및 연결 점검. `/settings`는 새 주소로 이동 |

사용자·프로젝트·생성 요청은 25건, 에셋은 24건, 크레딧 원장은 50건씩 조회한다. 사용자 상세의 연결은 정확한 사용자 ID로 범위를 고정한다. 프로젝트 구성은 관리자가 읽기 전용으로 검토하며 사용자 편집 API의 소유권 검사를 그대로 유지한다. 생성 상태는 DB에 기록된 상태이며 새로고침은 공급자 재생성이나 유료 호출을 하지 않는다. `진행 중 전체`는 접수 중과 생성 중을 모두 포함한다.

추가 조회 API는 `/api/workspace/admin/dashboard`, `/users`, `/projects`, `/activity`다. API 경계의 관리자/IP 검사와 서비스 내부 역할 검사를 함께 적용한다. 비밀번호 해시, 공급자 키, 저장된 인증 정보는 반환하지 않는다. 기존 테이블을 조회하며 새로운 중복 집계 테이블은 만들지 않는다.

2026-09-19 검증: 자동 테스트 24개와 TypeScript 검사 통과. 실 DB에 대한 관리자 API 6종은 관리자 200, 일반 사용자 403, 비로그인 401을 확인했다. 관리자 페이지 7종은 관리자 200, 일반 사용자 및 비로그인 이동 처리, 기존 설정 URL 이동과 잘못된 필터 400을 확인했다. 브라우저에서는 사용자 검색·상세·크레딧 대상 유지, 프로젝트 포맷 필터·구성, 릴스 요청 상세, 사용자 업로드 에셋 검색, 등록된 키 상태 및 모바일 390px 메뉴·필터·표를 확인했다. HTTP 기록은 `docs/qa/admin-navigation-http.json`, 화면은 `docs/qa/admin-*.png`에 보관한다. 이번 관리자 메뉴 개편 검증에서는 새 유료 생성을 실행하거나 실제 계정 크레딧을 변경하지 않았다.
