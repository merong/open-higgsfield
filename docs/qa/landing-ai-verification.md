# 랜딩 AI 제작 검증 — 2026-09-21

## 구현 결과

[사전 기획안](../landing-ai-production-plan.md)에 따라 랜딩 전용 의도 보드, 방문자의 질문에 따른 섹션 기획·승인, 원고 생성·검수, 단일 섹션 수정, 저장·재개, 기존 랜딩 편집기 인계를 구현했다. 도움말도 현재 흐름으로 갱신했다.

- 의도 보드: 방문자 / 고민 / 가치 / 행동, 입력에서 확인된 항목과 AI 제안 구분, 행동 선택·직접 입력, 버튼 문구·주소, 실제 자료, 브랜드·유입·톤·스타일.
- 기획: 중간 섹션 순서 변경·삭제, 질문·제목·메시지 편집, 의견으로 재기획, 방향으로 되돌아가기. 승인 뒤에만 본문 생성.
- 원고: 승인한 ID·순서 유지, 확정 CTA의 서버 적용, 별도 검수 호출, 선택 범위를 벗어나는 AI 응답 거부, 버전별 스냅샷.
- 저장: 사용자 소유권, revision/lease, 중복 요청·과금 방지, 초안 이전 취소·프로젝트 보관 시 예약 환불, 호출 한도·오류 시 명시적 재시도.
- 인계: 검수 내용 확인 후 프로젝트 편집기에서 이미지·문구·링크를 완성하고 기존 ZIP 출력 이용. 검수 요청 실패/한도 초과로 일시 중단됐더라도 저장된 원고가 있으면 확인 후 수동 편집으로 인계할 수 있다.
- 출력 보완: 특징 섹션의 `제목|설명` 형식 지원, 긴 기존 문구는 축약 없이 본문으로 렌더링.

## 자동 검증과 실행 상태

- `node --import tsx --test test/*.test.ts`: **94/94 통과**. 신규 랜딩 테스트 11개 포함.
- `corepack pnpm exec tsc --noEmit`: 통과.
- `LOCAL_DATABASE_DIR=memory:// corepack pnpm build`: 통과.
- 소유권, 승인 게이트, 중복 예약·환불, 버전 충돌, 취소 후 늦은 응답 무시, 호출 한도, 선택 섹션 보존, 완료 후 변경 금지, 보관 시 취소, 특징 HTML 이스케이프·원문 보존을 검증했다.
- 기존 카드뉴스·숏폼 테스트도 회귀 통과. 테스트와 빌드는 메모리 DB 사용, 실행 중인 DB 파일에 별도 연결하지 않았다.
- 개발 클라이언트 초기화 문제가 있어 생성 캐시를 임시 폴더로 옮겨 재구축했다. 소스·사용자 DB는 유지했다.
- 초기화 전 로그인 폼의 기본 GET 제출을 막도록 POST와 초기화 완료 전 버튼 비활성화를 적용했다.
- 앱 서버는 `http://127.0.0.1:3000`에서 계속 실행. 독립 출력 확인용 3001 서버는 검증 후 종료한다.
