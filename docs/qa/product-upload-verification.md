# 상품 사진 기반 제품 상세 제작 검증

검증일: 2026-09-21 · 로컬 개발 서버 `http://127.0.0.1:3000`

## 구현
- 제품 상세의 AI 시작 폼에 다중 파일 선택/드롭, 전송 상태, 원본 썸네일·크기, 대표 지정, 선택 해제를 추가했다. 최대 6장, JPG/PNG/WebP 각 10MB. 사진 없이 시작하는 기존 흐름을 유지한다.
- 상품명·상품 설명과 실제 이미지 바이트를 OpenAI Responses 이미지 입력으로 전달한다. 분석 사본은 방향을 보정해 최대 1600px로 축소하고, 원본 파일은 수정하지 않는다.
- 사용자 소유 asset ID만 참조하며 파일 형식·실제 디코딩·픽셀 수·정지 이미지 여부를 검사한다. 크레딧 예약 전에 참조 자료를 검증한다. multipart 본문은 content-length가 없어도 크기를 제한한다.
- 기획에서 각 섹션의 원본/새 이미지 선택과 썸네일을 확인한다. 승인 원본은 초안에 바로 적용하고, 새로고침과 문구 수정·편집기 인계 후에도 유지한다.
- 업로드 원본이 적용된 영역은 전체 빈 이미지 생성에서 제외한다. 내 라이브러리와 HTML ZIP에 원본을 보존한다.

## 실제 AI 및 브라우저 E2E
- 프로젝트: `c28f2f1f-79da-4a86-b4ad-308ba8852725`
- 워크플로우: `45fd34ef-fcd4-451b-a2bc-4efc65445224` · 최종 `completed`
- 모델: 저장된 `gpt-5.6-terra` · 6회 호출(이해/기획/작성/검수/부분 수정/재검수).
- 자료: 이전 데모에서 생성한 머그 PNG를 테스트 파일 `morning-mug.png`로 업로드했다. 실제 판매 상품의 사진/정책으로 간주하지 않는다.
- AI는 사진의 둥근 입구·곡선 손잡이·아이보리 색감·어두운 테이블·창가 빛을 관찰했다. 기획에는 사진 우측 색상 견본도 설명했다.
- 요청한 사진 1회 사용을 반영해 6개 섹션, 업로드 원본 1장, 새 이미지 0장으로 구성했다. 승인 전 새로고침에도 원본 선택을 복원했다.
- 검수에서 사진 관찰과 차콜 옵션 정보를 구분하도록 제안했고, 해당 섹션만 수정한 뒤 재검수에서 원고 문제가 남지 않았다. 미입력 배송·반품 정보는 확인 사항으로 유지했다.
- 원본은 초안·문구 수정·편집기·라이브러리·ZIP에서 유지됐다. 저장된 파일과 ZIP 내 이미지의 SHA-256이 업로드 원본과 같다.
- 이미지 제작 모달: `1/1장 준비`, `페이지에 적용됨`, 전체 빈 이미지 생성 비용 0. 이미지 생성 요청은 실행하지 않았다.
- 크레딧: 328 → 327. 원고 1 크레딧만 사용했다.
- 실제 API 오류 응답: 로그인 없음 401, 다른 Origin 403, 손상 이미지 400.
- 출력 데스크톱 1280px / 모바일 390px에서 이미지 로드 정상, 가로 넘침 없음. 모바일 업로드 시작 폼도 390px에서 넘침 없음. 검사 후 viewport를 원상 복구했고 임시 출력 서버는 종료했다.

## 증거
- `product-upload-live.json`: 실제 실행·검수·보드·저장 원본 해시·라이브러리 상태.
