- 앱 크레딧: 이미지 12 + AI 원고 1 = **13 크레딧** 사용. 기존 사용자 프로젝트는 수정하지 않고 QA 사본에서 검증.

## 실제 화면·데이터 검증
- QA 이미지 프로젝트: `89790505-7d41-4482-8963-af89469fd9b8`.
- QA AI 워크플로우: `e077bb6e-e452-42ba-ba79-f9d575d6c5c1`, 프로젝트 `26236a51-bb22-498b-9353-173e06065bd3`.
- 초안의 가상 이미지: 1600×900 / 900×1200, 비율과 장면 설명 노출. 실제 DOM `img`의 width/height와 영문 생성 프롬프트 `alt` 확인.
- 생성 대기→이미지 생성 중→확인 대기 상태, 진행 영역 shimmer와 버튼 잠금 확인. 진행률은 실제 준비된 이미지 수만 표시.
- 생성 후보가 준비되어도 원본 문구/이미지가 바뀌지 않음. 새로고침 후 후보·모델·수정 프롬프트 복원 확인.
- ‘확인하고 2장 적용’ 후 알림, 저장 상태, 페이지 구조의 썸네일 2개와 실제 이미지 로딩 확인. 원본 본문 배열과 동일함을 API 비교 검증.
- 모바일 모달 390×844에서 1열, 고정 제목/확인 영역 확인. 출력 미리보기 375px에서 scrollWidth=clientWidth=375, 적용 이미지 2개 로딩 확인.
- AI 초안에서도 동일 모달로 계획된 2개 섹션만 표시. 활성 워크플로우의 이미지 적용·버전 동기화·원고 검수 보존과 후속 문구 수정은 서비스 통합 테스트로 검증.

## 테스트가 다루는 실패·동시성
소유권, 유효 비율, HTML/alt escaping, FAQ 이미지 위치, 중복/동시 요청 1회 과금, 명시적 적용, 장별 모델·프롬프트 재생성, 실패 환불과 성공 후보 보존, 오래된 문구 덮어쓰기 거절, 보관 실패 후 저장만 재시도, 접수 불명 재결제 차단, 비용 변경·잔액 부족·영상 모델 거절, 활성 워크플로우 버전 일관성.

실제 E2E에서 발견한 ‘이미지 없는 FAQ/CTA의 빈 프롬프트를 거절’ 문제는 이미지가 계획된 섹션에만 필수 검증하도록 수정하고 회귀 테스트를 추가했다.

## 사용상 동작
모달을 닫아도 이미 접수된 제공자 작업은 유지된다. 아직 접수하지 않은 순서는 다시 모달을 열 때 재개한다. 생성은 선택한 순서대로 수행하고 성공 후보를 먼저 보관한다. 실패한 장만 재시도할 수 있다. 확인 시 섹션 내용이 달라진 경우 이전 후보를 자동으로 덮어쓰지 않으며, 후보는 라이브러리에 남는다. 목표 픽셀 크기는 페이지 설계 기준이며 실제 생성 해상도는 모델에 따라 달라진다. 미생성 영역은 제작 미리보기에만 표시하고 최종 HTML에는 안내용 가상 이미지를 넣지 않는다.
