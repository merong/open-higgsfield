# 시나리오 입력 자료 준비

모든 브랜드·수치·제품은 테스트용 가상 설정이다. 실제 업체 정보나 현재 상품 추천이 아니다. 이 폴더는 앱 public 디렉터리에 연결하지 않았다.

## URL 원문 4개

| 시나리오 | 파일 | 목적 |
|---|---|---|
| LP-01 | [lp-01-teamflow.html](lp-01-teamflow.html) | 서비스 기능·전환 목적 |
| LP-03 | [lp-03-class.html](lp-03-class.html) | 교육 정보 + 존재하지 않는 첨부 링크 |
| PD-01 | [pd-01-coffee.html](pd-01-coffee.html) | 가격·구성·배송 |
| PD-04 | [pd-04-hub.html](pd-04-hub.html) | 조건부 사양·호환성 |

로컬 수집기가 접근할 수 있는 환경에서 앱 저장소 루트 기준으로:

```sh
python3 -m http.server 4318 --bind 127.0.0.1 --directory docs/qa/agentic-scenarios/fixtures
```

이 경우 `FIXTURE_BASE_URL=http://127.0.0.1:4318`. 개발 브라우저가 열 수 있다는 사실만으로 모델/provider가 읽을 수 있다고 판단하지 않는다. **실제 URL 수집 경로**에서 접근을 확인한다. 외부 provider가 localhost를 읽지 못하면 `blocked_environment`다. 필요한 경우 이미 허용된 테스트 호스트에서 동일 파일을 제공하고 실제 주소·콘텐츠 해시를 기록한다. 시나리오가 SSRF 차단 우회를 지시하지는 않는다. 실행 후 자신이 시작한 자료 서버만 종료한다.

`lp-03-class.html`은 200, 링크된 `missing-curriculum.pdf`는 404인 것을 확인한다. 404 문서는 의도적으로 만들지 않는다. 주소를 확인하지 않은 `example.com` 같은 임의 사이트로 바꾸거나 URL 입력 테스트를 원문 붙여넣기로 대체하지 않는다. 붙여넣기 검사는 별도 run이다.

## 사진 자료 3세트 — 파일 미포함

실제 상품/공간의 시각 보존 검사를 위해 사진 준비를 실행 전제 조건으로 둔다. 생성 이미지·아이콘·placeholder를 실제 상품 원본으로 취급하지 않는다. 문서 작성 단계에서 유료 이미지 생성은 하지 않았다.

| 시나리오 | 필요한 자료 / 순서 | 확인할 시각적 기준 |
|---|---|---|
| LP-05 | 같은 작은 실내의 전체 사진 A, 수납 가구 디테일 B | 전체는 가로 구도·양쪽 공간 경계 식별, 디테일은 가구 구조 식별; 같은 공간임을 확인 |
| PD-02 | 하루결 50mL 크림 정면 A, 뒷면 B | 불투명 흰 튜브·초록 캡·HARUGYEOL 라벨·동일 제품; 읽히는 용량과 제품명 |
| PD-03 | 느린옷 셔츠 스카이블루 정면 A, 네이비 정면 B, 단추 디테일 C | 색상 대응과 같은 디자인 확인, C가 어느 색상인지 manifest에 명시 |

공통 준비: 사용 권한이 있는 자료, 긴 변 1600px 이상 권장, 판독 가능한 라벨/특징, JPEG/PNG/WebP, 사람의 식별정보 없음, 동일 파일을 baseline/candidate에 재사용. 이 규격은 테스트 준비 권장치이며 앱의 업로드 허용 한도를 대신하지 않는다.

PD-02는 배경을 실제로 변경하는 분기를 검증할 수 있도록 처음부터 밝은 아이보리 배경인 사진을 피한다. PD-03의 문서상 옵션은 M·L이며 사진으로 실측 치수를 추정하지 않는다. PD-05는 사진 없이 시작하고, 질문 응답에서만 브랜드 나란히·기본 모듈 1개를 제공한다. 치수 80×30×40cm와 부품 별도 판매는 후속 턴에서 처음 제공한다.

이 가상 브랜드에 정확히 맞는 실제 사진을 구하기 어렵다면 **실제로 확보한 동일 제품 사진에 맞춰** 상품명·색·라벨·수치를 일관되게 바꾼 로컬 fixture variant를 만든다. 원본 시나리오와 바뀐 필드를 기록하고 새로운 fixture 버전으로 고정한다. 맞지 않는 사진을 제출한 뒤 모델에 원래 가상 사실을 강요하지 않는다. 테스트 중간에 자료를 바꾸면 새 run으로 시작한다. 사진이 준비되지 않은 상태는 `blocked_fixture`이며 시나리오 자체의 작성 완료와 구분한다.

## 실행별 manifest

run 문서에 파일 경로·업로드 순서·역할·촬영 대상·제공 사실·권리 확인·픽셀 크기·SHA-256을 적는다. 비밀값이나 실제 고객 개인정보는 넣지 않는다. 해시는 예를 들어 `shasum -a 256 <file>`로 구한다. 업로드 후 앱 asset ID 및 provider로 전달된 이미지와 매핑한다. 변환된 이미지의 해시는 원본과 다를 수 있으므로 변환 여부도 기록한다.

동봉한 HTML의 기준 해시는 [source-sha256.txt](source-sha256.txt)에 있다. 원문을 바꾸면 해당 fixture 버전과 해시를 함께 갱신한다.

모든 사진/원문에 대해 `준비됨 / 누락 / 접근 실패 / 내용 불일치`를 실행 시작 전에 판정한다. 자료 준비가 끝나지 않았다면 UI 테스트 통과로 기록하지 않는다.
