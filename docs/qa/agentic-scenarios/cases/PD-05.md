# PD-05 모듈 선반 — 판매 대상 확인, 치수·단품 범위, 복원

2026-09-29 · 시나리오 문서 · 실행 결과 아님

공통 문서: [개요](../README.md) · [실행 안내](../runner-guide.md) · [실행 기록 양식](../run-template.md) · [fixture 기준](../fixtures/README.md)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 형식 | 제품 상세페이지 |
| 최소 입력 유형 | 요청 한 문장 **하나만** |
| 가상 상품 | 브랜드 "나란히"의 모듈 선반 기본 모듈 |
| 핵심 검증 | 판매 대상이 모호할 때 대상만 짧게 묻는가. 답을 받은 뒤 치수와 단품 범위를 글과 이미지에서 지키는가. 한 번의 수정으로 함께 바뀐 이미지와 문구를 함께 되돌리는가 |
| 사용자 턴 | 4개 (T2는 AI가 물었을 때만 입력) |

"입력 하나로 바로 제작"과 "불필요한 승인 없음"은 **목표 기준**이다. 현재 구현이 이를 충족한다는 뜻이 아니다.

## 2. 준비물과 실행 설정

- fixture 파일과 사진이 없다. 이미지를 생성한다면 연출 이미지로 표시한다. 이미지 없이 진행한 경우 관련 이미지 변경·복원 검사는 미검증으로 남긴다.
- 테스트 실행 설정(앱 정책이 아님):
  - 이미지 생성 횟수와 크레딧 상한.
  - 복원 충돌 처리: 이 run에서는 T3과 T4 사이에 다른 수정을 넣지 않는다. 충돌 정책을 검증하려면 별도 run을 만들고, 사이에 넣은 수정과 기대 처리를 그 run의 실행 설정으로 적는다.

## 3. 사실 기준

사용자는 처음에 아무 사실도 주지 않는다. 아래 값은 표에 적힌 턴에서만 제공된다.

### 고정 사실

| 항목 | 값 | 제공 시점 |
| --- | --- | --- |
| 브랜드 | 나란히 | T2 |
| 판매 대상 | 모듈 선반 기본 모듈 1개 (단품) | T2 |
| 세트 여부 | 여러 단으로 쌓은 세트가 아님 | T2 |
| 치수 | 가로 80cm, 깊이 30cm, 높이 40cm | T3 |
| 별도 판매 | 연결 부품, 추가 모듈 | T3 |

### 미제공 사실 (페이지에 나오면 안 됨)

가격, 소재, 색상, 하중, 무게, 조립 방법, 배송·설치, 최대 적층 단수, 후기, 인증.

T1 직후에는 고정 사실도 아직 제공되지 않았다. 이 시점에 브랜드, 치수, 구성을 채우면 생성이다.

### 질문을 받았을 때만 주는 답변

| AI가 묻는 내용 | 답변 |
| --- | --- |
| 무엇을 판매하는지 | T2 복사문 |
| 치수·가격·소재 등 사양 (T3 이전) | `그건 아직 정하지 않았어요. 빼고 진행해 주세요.` |
| 연결 부품·추가 모듈 포함 여부 (T3 이전) | `포함되지 않아요.` |
| 되돌릴 범위 | `방금 요청으로 바뀐 것만 되돌려 주세요.` |

## 4. 사용자 턴

**T1 — 시작 입력**

```
모듈 상품 상세페이지 만들어 주세요.
```

**T2 — 판매 대상 답변** (AI가 판매 대상을 물었을 때만 입력)

```
나란히 모듈 선반의 기본 모듈 1개예요. 여러 단으로 쌓은 세트가 아니라 단품입니다.
```

**T3 — 이미지와 치수를 함께 수정**

```
대표 이미지에는 기본 모듈 한 개만 보이게 해 주세요. 치수도 넣어 주세요. 가로 80cm, 깊이 30cm, 높이 40cm입니다. 연결 부품과 추가 모듈은 별도 판매예요.
```

**T4 — 되돌리기** (합성 테스트 입력)

```
방금 바꾼 것보다 이전 화면이 더 나았어요. 방금 수정하기 전으로 되돌려 주세요.
```

AI가 T1 뒤에 판매 대상을 묻지 않고 제작을 진행하면 T2를 입력하지 않는다. 그 사실을 기록하고, 초안이 무엇을 판매 대상으로 정했는지 적은 뒤 T3으로 넘어간다.

## 5. 단계별 기대와 실패 조건

| 턴 | 기대 | 실패 조건 |
| --- | --- | --- |
| T1 | 판매 대상(단품인지 세트인지, 어떤 제품인지)만 짧게 묻는다. 질문은 한 번, 한 가지다. 답을 받기 전에는 특정 상품으로 확정한 이미지·페이지 생성을 시작하지 않는다(질문 생성을 위한 텍스트 모델 호출은 허용) | 묻지 않고 임의의 세트·브랜드·치수로 제작. 스타일·색상·가격·치수까지 함께 질문. 여러 항목의 입력 폼을 요구. 질문이 두 번 이상 |
| T2 | 답을 받은 뒤 다시 묻지 않고 초안까지 진행한다. 페이지가 단품 1개를 판매 대상으로 다룬다. 치수·가격·소재는 비워 두거나 보이지 않게 한다 | 같은 내용 재질문. 세트 구성으로 소개. 치수·하중·소재 생성. 의도·기획 승인을 강제 |
| T3 | 한 요청 안에서 이미지와 규격 문구가 함께 바뀐다. 대표 이미지에 모듈이 한 개만 보인다. 치수 세 값이 단위와 함께 그대로 들어간다. 별도 판매 항목이 표시된다. 이 변경이 하나의 수정 단위로 기록된다 | 이미지에 여러 단이 쌓여 있거나 연결 부품이 구성품처럼 보임. 치수 값·단위·순서가 바뀜(예: 가로와 깊이 혼동). 하중·최대 단수 생성. 이미지와 문구 중 하나만 반영하고 완료로 표시. 대표 이미지 외 이미지까지 재생성 |
| T4 | T3 직전 상태로 돌아간다. 대표 이미지가 T3 이전 파일과 같은 해시다. 치수 문구와 별도 판매 표기도 T3 이전 상태가 된다. T2까지의 내용은 남는다. 되돌린 기록이 새 이력으로 남는다. 새 유료 생성 호출 0회 | 이미지만 또는 문구만 돌아감. 다시 생성해 "비슷한" 이미지를 만듦. T2 내용까지 사라짐. 되돌리기 이력 없음. 되돌릴 범위를 묻지 않고 전체를 초기화 |

### 기록 규칙

- 앱이 한 문장만으로 제품 상세를 시작할 수 없으면 T1은 `unsupported`다. 상품명 등을 직접 입력해 시작한 경우는 **별도 run**이며, T1의 모호성 질문 검사를 pass 처리하지 않는다.
- 앱에 판매 대상을 묻는 경로가 없으면 T1의 질문 기대는 `unsupported`다. 앱이 묻지 않고 임의로 제작한 것은 `fail`이다. 둘을 구분해 적는다.
- 앱에 되돌리기 경로가 없으면 T4는 `unsupported`다. 실행자가 손으로 이전 값을 다시 입력한 것은 별도 run이다.
- 앱이 T3의 복합 요청을 한 번에 처리하지 못해 이미지와 문구를 나눠 요청했다면 별도 run이다. 이 경우 T4의 "함께 복원" 검사는 판정할 수 없다.
- T4의 "이전 화면이 더 나았어요"는 합성 테스트 입력이다. 관찰실 평가에 `customer_report`로 기록하지 않는다.

## 6. 이미지 점검

이미지마다 다섯 값을 따로 적는다.

| 값 | 확인 방법 |
| --- | --- |
| 이미지 수 | 계획된 수, 실제 생성·배치된 수 |
| 역할 | 대표, 크기 안내, 사용 장면, 연출 |
| 비율 | 계획 비율과 실제 파일 비율 |
| 출력 픽셀 | 실제 파일의 가로×세로 |
| 표시 크기 | 390·768·1440px에서 보이는 크기와 잘림 |

추가 점검:

- 대표 이미지 속 모듈 개수. 한 개가 아니면 T3 실패다.
- 사용 장면 이미지에 여러 모듈이 보이면 "연출"이며 별도 판매임이 표시되는가.
- 이미지 속 선반 비례가 치수(가로 80 : 높이 40 : 깊이 30)와 크게 어긋나 보이지 않는가. 사람이 보고 판단하며, 불확실하면 "판단 불가"로 적는다.
- 이미지에 치수 숫자, 로고, 읽을 수 있는 글자가 생기지 않았는가.
- 생성 이미지를 실제 상품 사진이라고 표시하지 않는가.

## 7. 증거와 로그 지점

- T1 직후 AI가 보인 질문의 원문, 질문 수, 질문 전 생성 호출 수.
- T3 전, T3 후, T4 후의 대표 이미지 해시와 규격 영역 문구.
- T3 전후, T4 전후 프로젝트 필드 비교: 바뀐 섹션과 필드 목록.
- 턴마다 390·1440px 스크린샷.
- 관찰실(`/dev/workflows`): `user.action`, `model.request`, `model.parsed`, `workflow.state`, `generation.request`, `generation.result`.
- 턴별 이미지 생성 호출 수, 크레딧 변화, 승인 횟수, 대기 시간.

## 8. 완료 조건

- T1, T3, T4를 입력했고 T2는 조건에 따라 입력했거나 생략 사유를 기록했다. 또는 중단 사유를 단계별로 기록했다.
- T3 후 페이지에서 판매 대상·치수·별도 판매 표기가 3절과 일치하고 미제공 사실이 0건이다.
- T4 후 이미지 해시와 규격 문구가 T3 전과 같은지 기록했다.
- 6절 다섯 값과 모듈 개수를 기록했다.
- 대체 경로는 별도 run으로 분리했다.

## 공통 검사와 재접속

[실행 지침](../runner-guide.md)의 C1~C5도 필수로 판정한다. 마지막 상태를 저장하고 같은 프로젝트에 재접속해 문구·이미지·옵션이 유지되는지 확인한다. 이미지는 필요한 경우에만 생성하며, 사례에서 허용한 경우에만 0장 또는 도식만 사용하는 이유를 기록한다. 요구된 상품 원본 사진을 누락한 경우에는 실패다. 이미지가 없는 상태에서 이미지를 전제로 하는 피드백은 `not_applicable`로 분리하고 그 검사가 통과했다고 보지 않는다. 이 문서는 목표 검사이며 현재 기능 지원 여부는 실행 시점에 확인한다.
