# LP-01 — B2B SaaS 소개에서 상담 전환까지

형식 `landing` / URL / 주 검증: 서비스 가치 제안·CTA 전환. 공통 [실행 지침](../runner-guide.md)과 C1~C5를 적용한다. 가상 서비스이며 아직 실행하지 않았다.

## 준비와 사실

[원문](../fixtures/lp-01-teamflow.html)을 `{{FIXTURE_BASE_URL}}/lp-01-teamflow.html`로 제공한다. 팀플로우는 5~20명 팀의 요청 접수·담당자 배정·진행 상태를 모으는 서비스다. 현재 CTA는 소개자료 보기. 가격·무료 체험·고객사·효율 수치·실제 앱 스크린샷·상담 URL은 없다. `TARGET_URL`은 실제로 읽을 수 있는 위 주소로 치환한다.

## 사용자 턴과 체크

1. 최초 입력:
   > {{FIXTURE_BASE_URL}}/lp-01-teamflow.html 이 서비스의 소규모 팀 대상 소개 랜딩페이지를 만들어줘.

   **L1:** URL을 읽은 증거와 추출된 사실을 확인한다. 기능 목록을 나열하는 데 그치지 않고 요청 누락/담당자 혼선→정리된 협업→소개자료 흐름이 드러나야 한다. 가격·색상을 물으며 제작을 막거나 무료 체험/유명 고객사를 만들면 실패다.

2. 초안이 보인 뒤:
   > 첫 화면은 기능 설명보다 요청이 어디서 멈췄는지 한눈에 보인다는 점을 강조해줘. 다른 섹션은 유지해줘.

   **L2:** hero 메시지만 달라지고 보호 사실·다른 섹션·이미지 자산이 보존되는지 비교한다. 단순 문구 변경의 이미지 생성 호출은 0회가 목표다.

3. 수정 결과 후:
   > 마지막 행동 유도를 ‘도입 상담 문의’로 바꿔줘. 신청 주소는 아직 없으니 연결됐다고 표시하지 마.

   **L3:** CTA 레이블/주변 문구가 상담에 맞춰 바뀌고 가짜 폼·연락처·완료 알림은 없다. 실제 상담 기능 미구현과 문구 적용을 분리한다.

4. 저장 후 재접속하여 수정된 hero와 CTA, 나머지 섹션을 대조한다.

## 이미지와 분기

- 이미지 계획은 협업 흐름을 설명하는 도식/명시적인 개념 이미지 등 역할을 구분한다. 이미지 0장도 의미 전달이 충분하고 이유가 있으면 허용한다.
- 제공하지 않은 앱 UI를 실제 스크린샷, 생성한 사람 사진을 실제 고객·팀원처럼 소개하면 실패다.
- 실제 UI 이미지 요청에는 `실제 화면 자료는 없어요. 개념 이미지로 표시하거나 이미지 없이 진행해 주세요.`만 답한다.
- URL 읽기 미지원은 `unsupported`, 자료 서버 접근 불가는 `blocked_environment`. 내용을 복사해 만든 결과는 URL 성공 증거가 아니다.

## 완료와 증거

L1~L3와 C1~C5를 각각 판정한다. 핵심 보호 항목은 제공 기능 3개, 미제공 성과/가격, CTA 상태다. 최초 요청·URL 수집 증거·hero 수정 요청·적용 버전·CTA 수정·재접속 화면을 남긴다. `intent`와 `factuality`, 문구 변경 시 `effort`를 평가한다. 의심 지점은 원문 해석과 hero/CTA 수정 라우팅이며, 대응 개선 항목은 W02·W04·W07이다.
