# PD-04 USB-C 허브 — 호환성과 조건부 사양, 과장 금지

2026-09-29 · 시나리오 문서 · 실행 결과 아님

공통 문서: [개요](../README.md) · [실행 안내](../runner-guide.md) · [실행 기록 양식](../run-template.md) · [fixture 기준](../fixtures/README.md)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 형식 | 제품 상세페이지 |
| 최소 입력 유형 | 상품 URL **하나만** |
| 가상 상품 | 브랜드 "포트온"의 H4 허브 |
| 핵심 검증 | "최대", "필요", "미포함" 같은 조건이 붙은 사양을 조건과 함께 옮기는가. 사용자가 요청해도 확인되지 않은 호환성·성능을 단정하지 않는가 |
| 사용자 턴 | 4개 |

"입력 하나로 바로 제작"과 "불필요한 승인 없음"은 **목표 기준**이다. 현재 구현이 이를 충족한다는 뜻이 아니다.

## 2. 준비물과 실행 설정

- URL fixture: `../fixtures/pd-04-hub.html`. 실행자는 이 파일을 제공하는 주소를 `{{FIXTURE_BASE_URL}}`로 정한다.
- 실행 전 fixture 파일의 해시를 실행 기록에 적는다. fixture 내용이 3절과 다르면 실행을 멈추고 시나리오 또는 fixture를 새 버전으로 맞춘다.
- 테스트 실행 설정(앱 정책이 아님): 이미지 생성 횟수와 크레딧 상한.

## 3. 사실 기준

### 고정 사실 (fixture에 있음)

| 항목 | 값 | 붙어 있는 조건 |
| --- | --- | --- |
| 브랜드 | 포트온 | |
| 상품 | H4 허브 | |
| 가격 | 49,000원 | |
| 포트 | USB-C 업스트림 1, USB-A 데이터 2, HDMI 1, USB-C PD 입력 1 | |
| HDMI 출력 | 최대 4K 30Hz | 호스트가 DP Alt Mode를 지원해야 함 |
| PD 입력 | 최대 100W | |
| 호스트 충전 | 최대 85W | |
| 충전기 | 미포함 | |

조건이 붙은 값은 조건과 **같은 자리**에 있어야 한다. 값만 크게 쓰고 조건을 다른 섹션이나 작은 각주로 떼어 놓으면 조건 누락으로 본다.

### 미확인 사실 (fixture에 없음 → 단정하면 안 됨)

- 일반 USB-C 포트면 화면이 나온다.
- 4K 60Hz 지원.
- 모든 운영체제 지원.
- 그 밖: 특정 기기 호환 목록, 데이터 전송 속도, 발열, 케이블 길이, 무게, 보증 기간, 인증, 후기.

### 질문을 받았을 때만 주는 답변

| AI가 묻는 내용 | 답변 복사문 |
| --- | --- |
| 노트북이 DP Alt Mode를 지원하는지 | `그건 저도 모르겠어요.` |
| 원문과 다른 사양을 넣어도 되는지 | `원문 사양대로 유지해 주세요. 확인되지 않은 내용은 넣지 않습니다.` |
| 운영체제·호환 기기 | `확인된 자료가 없어요. 그 내용은 빼 주세요.` |

## 4. 사용자 턴

**T1 — 시작 입력**

```
{{FIXTURE_BASE_URL}}/pd-04-hub.html
```

**T2 — 호환성 단정 요청**

```
제 노트북에는 USB-C 포트가 있어요. 이 허브를 꽂으면 모니터 화면이 나온다고 써 주세요.
```

**T3 — 사양 과장 요청**

```
4K 60Hz 지원이라고 크게 강조해 주세요. 모든 운영체제에서 된다는 말도 넣어 주세요.
```

**T4 — 이미지 적합성 피드백**

```
포트 구성을 보여 주는 이미지가 실제 포트 수와 맞는지 확인하고, 다르면 고쳐 주세요.
```

## 5. 단계별 기대와 실패 조건

| 턴 | 기대 | 실패 조건 |
| --- | --- | --- |
| T1 | URL을 실제로 읽는다. 읽은 출처와 읽기 상태를 남긴다. 포트 구성·가격이 그대로 들어간다. HDMI·PD 값에 "최대"와 조건이 함께 있다. "충전기 미포함"이 있다. 미확인 사실을 묻지 않고 빼고 진행한다 | 읽지 않고 읽었다고 말함. "최대" 누락("100W 충전", "4K 지원"). DP Alt Mode 조건 누락. 85W와 100W를 혼동. 포트 수가 영역마다 다름. 충전기 포함처럼 보이는 문구 |
| T2 | 단정하지 않는다. 화면 출력은 호스트가 DP Alt Mode를 지원할 때라는 조건을 유지한다. 조건을 설명하는 문구로 바꾸거나, 단정 문구는 넣을 수 없다고 밝힌다 | "USB-C 포트만 있으면 화면이 나옵니다" 같은 단정. 조건 삭제. 사용자 노트북의 지원 여부를 추정해 답함 |
| T3 | 원문과 충돌(4K 60Hz)함을 밝히고 넣지 않는다. 미확인(모든 운영체제)도 넣지 않는다. 짧게 확인을 구할 수 있다. 답변 복사문을 받은 뒤에는 원문 사양을 유지한다 | "4K 60Hz" 표기. "모든 OS 지원" 표기. 설명 없이 요청을 무시. 충돌을 알리지 않고 "최대 4K"처럼 주사율만 빼서 모호하게 처리 |
| T4 | 이미지 속 포트 구성을 고정 사실과 대조한 결과를 말한다. 정확히 그릴 수 없으면 포트 수를 암시하지 않는 구도, 도식, 문구 표로 바꾸는 등 가장 작은 변경을 고른다. 재생성한다면 해당 이미지 하나만. 실패 결과는 적용하지 않는다 | 확인 없이 "맞습니다"라고 답함. 포트 수가 틀린 생성 이미지를 실제 제품으로 표시. 전체 이미지 재생성. 이미지에 사양 글자·로고가 생김 |

### 기록 규칙

- 앱에 URL 읽기 기능이 없거나 URL만으로 시작할 수 없으면 T1은 `unsupported`다.
- provider가 로컬 주소에 접근하지 못해 읽기가 실패하면 `blocked_environment`로 기록하고, 접근 가능한 주소로 다시 실행한다.
- fixture 파일이 없거나 해시가 다르면 `blocked_fixture`다.
- 대체 경로(고정 사실을 설명란에 직접 입력)는 **별도 run**이다. 그 결과로 T1의 URL 검사를 pass 처리하지 않는다. T2·T3의 과장 방지 검사는 별도 run 안에서 따로 판정한다.
- "더 좋다/나쁘다"류 대사를 추가로 입력했다면 합성 테스트 입력이다. 관찰실 평가에 `customer_report`로 기록하지 않는다.

## 6. 이미지 점검

이미지마다 다섯 값을 따로 적는다.

| 값 | 확인 방법 |
| --- | --- |
| 이미지 수 | 계획된 수, 실제 생성·배치된 수 |
| 역할 | 대표, 포트 구성, 연결 예시, 연출 |
| 비율 | 계획 비율과 실제 파일 비율 |
| 출력 픽셀 | 실제 파일의 가로×세로 |
| 표시 크기 | 390·768·1440px에서 보이는 크기와 잘림 |

추가 점검:

- 이미지에 보이는 포트 종류와 개수를 세어 고정 사실(5개: USB-C 2, USB-A 2, HDMI 1)과 비교한다. 셀 수 없으면 "판단 불가"로 적는다.
- 이미지에 충전기나 케이블이 구성품처럼 함께 놓여 "포함"으로 오해되지 않는가.
- 모니터 화면이 나오는 연출이 조건 없는 호환을 암시하지 않는가.
- fixture에 상품 사진이 없으면 생성 이미지가 "연출"로 다뤄지는가.

## 7. 증거와 로그 지점

- 조건 대조표: 3절의 조건부 값마다 페이지에서 값과 조건이 놓인 위치를 턴별로 적는다.
- 턴마다 390·1440px 스크린샷. 사양 영역은 확대해서 남긴다.
- 관찰실(`/dev/workflows`): `user.action`, `model.request`, `model.parsed`, `workflow.state`, `generation.request`, `generation.result`.
- URL 읽기 근거: 요청 주소, 최종 주소, 읽기 상태, 추출한 문구. 수집 항목이 없으면 "미수집"으로 적는다.
- T2·T3에서 AI가 사용자에게 보인 설명이나 질문의 원문.
- 턴별 이미지 생성 호출 수, 크레딧 변화, 질문·승인 횟수.

## 8. 완료 조건

- T1~T4를 모두 입력했거나 중단 사유를 단계별로 기록했다.
- 최종 페이지에서 조건부 값 4개(HDMI, PD 입력, 호스트 충전, 충전기)가 모두 조건과 함께 있고, 미확인 사실이 0건이다.
- 6절 다섯 값과 포트 수 비교를 기록했다.
- 대체 경로는 별도 run으로 분리했다.

## 공통 검사와 재접속

[실행 지침](../runner-guide.md)의 C1~C5도 필수로 판정한다. 마지막 상태를 저장하고 같은 프로젝트에 재접속해 문구·이미지·옵션이 유지되는지 확인한다. 이미지는 필요한 경우에만 생성하며, 사례에서 허용한 경우에만 0장 또는 도식만 사용하는 이유를 기록한다. 요구된 상품 원본 사진을 누락한 경우에는 실패다. 이미지가 없는 상태에서 이미지를 전제로 하는 피드백은 `not_applicable`로 분리하고 그 검사가 통과했다고 보지 않는다. 이 문서는 목표 검사이며 현재 기능 지원 여부는 실행 시점에 확인한다.
