# PD-03 옥스퍼드 셔츠 — 여러 이미지의 역할, 색상·사이즈 대응, 모바일 잘림

2026-09-29 · 시나리오 문서 · 실행 결과 아님

공통 문서: [개요](../README.md) · [실행 안내](../runner-guide.md) · [실행 기록 양식](../run-template.md) · [fixture 기준](../fixtures/README.md)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 형식 | 제품 상세페이지 |
| 최소 입력 유형 | 짧은 설명 + 상품 사진 (입력 유형 한 가지) |
| 가상 상품 | 브랜드 "느린옷"의 옥스퍼드 셔츠 |
| 핵심 검증 | 사진 3장이 각자 맞는 역할과 색상에 연결되는가. 색상·사이즈 옵션이 입력과 일치하는가. 모바일 화면에서 옷이 잘리지 않는가 |
| 사용자 턴 | 4개 |

"입력 하나로 바로 제작"과 "불필요한 승인 없음"은 **목표 기준**이다. 현재 구현이 이를 충족한다는 뜻이 아니다.

## 2. 준비물과 실행 설정

- 사진 3장. 이 패키지에는 실제 파일이 없다. 실행자가 [fixture 기준](../fixtures/README.md)에 맞는 허가받은 자료를 준비하고 manifest에 해시를 고정한다.

  | 자리 | 내용 |
  | --- | --- |
  | `{{PHOTO:PD-03/skyblue-front}}` | 스카이블루 셔츠 정면. 소매 끝과 밑단까지 전체가 보임 |
  | `{{PHOTO:PD-03/navy-front}}` | 네이비 셔츠 정면. 소매 끝과 밑단까지 전체가 보임 |
  | `{{PHOTO:PD-03/button-detail}}` | 단추 디테일 근접 사진 |

- 단추 디테일 사진이 어느 색상 제품인지 manifest에 적는다. 이 값이 T3 판정의 기준이다.
- placeholder나 생성 이미지를 상품 사진 대신 쓰지 않는다. 사진이 없으면 `blocked_fixture`다.
- 사진이 3절과 다르면(색이 다름, 옷 일부가 원본에서 이미 잘림 등) 실행을 멈추고 fixture를 새 버전으로 고친다. 원본에서 이미 잘린 사진으로는 T2를 판정할 수 없다.
- 테스트 실행 설정(앱 정책이 아님): 이미지 생성 횟수와 크레딧 상한, 점검할 화면 폭(기본 390·768·1440px).

## 3. 사실 기준

### 고정 사실

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 브랜드 | 느린옷 | 설명 |
| 상품 | 옥스퍼드 셔츠 | 설명 |
| 색상 | 스카이블루, 네이비 (2종) | 설명 + 사진 |
| 사이즈 | M, L (2종) | 설명 |
| 사진 구성 | 스카이블루 정면, 네이비 정면, 단추 디테일 (3장) | 첨부 |

### 미제공 사실 (페이지에 나오면 안 됨)

가격, 실측 치수(어깨·가슴·소매·총장), 소재 혼용률, 세탁 방법, 제조국, 모델 착용 정보, 핏 설명의 수치, 후기, 재고, 다른 색상·사이즈.

"옥스퍼드"라는 상품명에서 소재 혼용률(예: 면 100%)을 추정해 쓰면 실패다.

### 질문을 받았을 때만 주는 답변

| AI가 묻는 내용 | 답변 복사문 |
| --- | --- |
| 실측 치수·사이즈표 수치 | `실측 치수는 아직 없어요. M과 L 두 가지라는 것만 표시해 주세요.` |
| 단추 디테일 사진의 색상 | manifest에 적은 색상으로 답한다. 예: `단추 사진은 스카이블루 제품이에요.` |
| 가격·소재·세탁 | `확인된 자료가 없어요. 그 내용은 빼 주세요.` |

## 4. 사용자 턴

**T1 — 시작 입력** (사진 3장을 함께 첨부)

```
느린옷 옥스퍼드 셔츠 상세페이지를 만들어 주세요. 색상은 스카이블루와 네이비, 사이즈는 M과 L입니다.
```

**T2 — 모바일 잘림 피드백**

```
모바일에서 네이비 셔츠의 소매 끝과 밑단까지 전체가 보이도록 배치해 주세요. 이미 전체가 잘 보인다면 유지해도 됩니다.
```

**T3 — 색상과 사진 대응**

```
어떤 사진이 어떤 색상인지 헷갈려요. 색상 이름과 사진을 짝지어 보여 주세요.
```

**T4 — 사이즈표 요청**

```
사이즈표도 넣어 주세요.
```

T2 전에 390px 화면에서 실제 잘림 여부를 기록한다. 이미 전체가 보인다면 유지해도 통과할 수 있지만, 크롭 수정 기능이 검증됐다고 표시하지 않는다.

## 5. 단계별 기대와 실패 조건

| 턴 | 기대 | 실패 조건 |
| --- | --- | --- |
| T1 | 사진 3장을 모두 분석 입력에 쓴다. 3장 모두 페이지에 배치되고 역할이 구분된다(색상별 정면, 디테일). 옵션에 색상 2종·사이즈 2종만 있다. 미제공 사실을 묻지 않고 빼고 진행한다 | 사진 누락 또는 같은 사진 반복. 색상·사이즈가 추가되거나 빠짐. 소재·세탁·치수 생성. 원본 대신 생성 이미지를 상품 사진으로 배치. 이미지 장수를 사용자에게 고르게 함 |
| T2 | 크롭·표시 방식 변경으로 해결한다. 이미지 생성 0회, 원본 해시 동일. 390px에서 소매 끝과 밑단이 모두 보인다. 다른 화면 폭에서 새로 잘리지 않는다 | 재생성. 축소로 옷이 지나치게 작아져 식별이 어려움. 390px만 고쳐지고 768·1440px에서 잘림. 네이비 외 사진의 배치까지 임의 변경 |
| T3 | 각 정면 사진에 맞는 색상 이름이 붙는다. 단추 디테일은 manifest의 색상 쪽에 놓이거나 색상 표기가 붙는다. 색상을 판단할 수 없으면 짧게 묻는다. 이미지 생성 0회 | 색상 이름과 사진이 뒤바뀜. 단추 사진을 다른 색상 제품으로 표기. 색을 보정·변경한 새 이미지를 만듦. 색상명을 임의로 바꿈("하늘색" 등 입력과 다른 표기로 대체) |
| T4 | 수치가 없음을 밝히고 짧게 묻거나, M·L 구분만 있는 표를 만든다. 답변 복사문을 받은 뒤에는 수치 없는 표만 유지한다 | 어깨·가슴·총장 수치 생성. "일반적인 M 사이즈 기준" 같은 추정치. 같은 내용을 두 번 이상 질문 |

### 기록 규칙

- 앱이 여러 사진을 받지 못하거나 사진별 배치를 지원하지 않으면 해당 단계는 `unsupported`다.
- 앱에 가로 위치·표시 방식(전체 보기) 조정이 없어 T2를 해결할 수 없으면 `unsupported`다. 편집기에서 실행자가 손으로 조정한 결과는 **별도 run**이며 T2를 pass 처리하지 않는다.
- 사진이 준비되지 않았거나 manifest에 단추 사진의 색상이 없으면 `blocked_fixture`다.
- "더 좋다/나쁘다"류 대사를 추가로 입력했다면 합성 테스트 입력이다. 관찰실 평가에 `customer_report`로 기록하지 않는다.

## 6. 이미지 점검

이미지마다 다섯 값을 따로 적는다.

| 값 | 확인 방법 |
| --- | --- |
| 이미지 수 | 첨부 3장, 계획된 수, 실제 배치된 수. 원본 사용과 새 생성을 구분 |
| 역할 | 대표, 색상별 정면, 디테일, 연출 |
| 비율 | 원본 비율, 계획 비율, 배치 영역 비율 |
| 출력 픽셀 | 원본 픽셀, 분석용 변환본 픽셀 |
| 표시 크기 | 390·768·1440px에서 보이는 크기, 잘린 부위(소매·칼라·밑단) |

색상 대응 표 (턴마다 작성):

| 사진 | 실제 색상(manifest) | 페이지의 색상 표기 | 배치 섹션 | 일치 |
| --- | --- | --- | --- | --- |
| skyblue-front | 스카이블루 | | | |
| navy-front | 네이비 | | | |
| button-detail | (manifest 값) | | | |

사진을 세로로 회전해 찍었다면 회전 정보가 표시에서 올바르게 적용됐는지도 확인한다.

## 7. 증거와 로그 지점

- 사진 3장의 해시(manifest), 실제 전송된 변환 이미지의 해시.
- T2 전후 390·768·1440px 스크린샷. 네이비 사진 영역은 확대해서 남긴다.
- T2·T3 전후 프로젝트 필드 비교: 바뀐 섹션과 필드 목록.
- 관찰실(`/dev/workflows`): `user.action`, `model.request`, `model.parsed`, `workflow.state`, `generation.request`, `generation.result`.
- 턴별 이미지 생성 호출 수, 크레딧 변화, 질문·승인 횟수.

## 8. 완료 조건

- T1~T4를 모두 입력했거나 중단 사유를 단계별로 기록했다.
- 최종 페이지의 옵션이 색상 2종·사이즈 2종이고, 미제공 사실이 0건이다.
- 색상 대응 표의 세 행이 모두 일치한다.
- 세 화면 폭에서 옷의 잘림 여부를 기록했다.
- 대체 경로는 별도 run으로 분리했다.

## 공통 검사와 재접속

[실행 지침](../runner-guide.md)의 C1~C5도 필수로 판정한다. 마지막 상태를 저장하고 같은 프로젝트에 재접속해 문구·이미지·옵션이 유지되는지 확인한다. 이미지는 필요한 경우에만 생성하며, 사례에서 허용한 경우에만 0장 또는 도식만 사용하는 이유를 기록한다. 요구된 상품 원본 사진을 누락한 경우에는 실패다. 이미지가 없는 상태에서 이미지를 전제로 하는 피드백은 `not_applicable`로 분리하고 그 검사가 통과했다고 보지 않는다. 이 문서는 목표 검사이며 현재 기능 지원 여부는 실행 시점에 확인한다.
