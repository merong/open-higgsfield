# PD-01 드립백 커피 — URL에서 읽은 규격·옵션·구성 수량의 사실 정합성

2026-09-29 · 시나리오 문서 · 실행 결과 아님

공통 문서: [개요](../README.md) · [실행 안내](../runner-guide.md) · [실행 기록 양식](../run-template.md) · [fixture 기준](../fixtures/README.md)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 형식 | 제품 상세페이지 |
| 최소 입력 유형 | 상품 URL **하나만** |
| 가상 상품 | 브랜드 "오후상점"의 드립백 커피 |
| 핵심 검증 | URL에서 읽은 규격·구성 수량·판매 단위·배송비가 페이지 전체(요약, 규격, 배송, 이미지)에서 서로 어긋나지 않는가. 제공되지 않은 사실을 만들지 않는가 |
| 사용자 턴 | 4개 |

"입력 하나로 바로 제작"과 "불필요한 승인 없음"은 **목표 기준**이다. 현재 구현이 이를 충족한다는 뜻이 아니다. 충족하지 못한 단계는 5절 규칙대로 기록한다.

## 2. 준비물과 실행 설정

- URL fixture: `../fixtures/pd-01-coffee.html`. 실행자는 이 파일을 제공하는 주소를 `{{FIXTURE_BASE_URL}}`로 정한다.
- 실행 전 fixture 파일의 해시를 실행 기록에 적는다. fixture 내용이 3절과 다르면 실행을 멈추고 시나리오 또는 fixture를 새 버전으로 맞춘다.
- 테스트 실행 설정(앱 정책이 아님): 이 run에서 허용하는 이미지 생성 횟수와 크레딧 상한을 실행 기록에 적는다. 상한에 닿으면 앱이 어떻게 반응했는지 그대로 기록하고, 앱 정책으로 해석하지 않는다.
- 유료 호출 여부와 사용 모델은 실행자가 run 시작 전에 정한다. 이 문서는 어느 쪽도 요구하지 않는다.

## 3. 사실 기준

### 고정 사실 (fixture에 있음)

| 항목 | 값 |
| --- | --- |
| 브랜드 | 오후상점 |
| 상품 | 드립백 커피 |
| 구성 | 10g × 10개 |
| 가격 | 12,000원 |
| 판매 단위 | 10개 구성만 판매. 낱개 판매 아님 |
| 카페인 | 있음 |
| 배송비 | 3,000원 |

### 미제공 사실 (fixture에 없음 → 페이지에 나오면 안 됨)

무료배송 조건, 유통기한, 원두 산지, 효능·건강 관련 표현, 후기·평점, 할인, 재고, 인증, 로스팅 일자, 맛 점수.

총중량 "100g"처럼 고정 사실에서 계산한 값은 별도로 기록한다. 계산이 맞더라도 원문에 없는 표기이므로 "파생 표기"로 분류하고, 틀린 계산은 실패다.

### 질문을 받았을 때만 주는 답변

AI가 묻지 않으면 입력하지 않는다. 물었을 때만 아래 문장을 그대로 복사한다.

| AI가 묻는 내용 | 답변 복사문 |
| --- | --- |
| 무료배송 조건 | `무료배송 조건 자료는 아직 없어요. 제공한 배송비만 표시해 주세요.` |
| 유통기한 | `유통기한은 아직 정해지지 않았어요. 넣지 말아 주세요.` |
| 낱개 판매 여부 | `낱개로는 팔지 않습니다. 지금 구성만 판매해요.` |
| 그 밖의 미제공 사실 | `그 내용은 제공할 수 없어요. 빼고 진행해 주세요.` |

## 4. 사용자 턴

각 턴은 앞 턴의 결과가 화면에 반영된 뒤 입력한다. 복사문은 글자 그대로 쓴다.

**T1 — 시작 입력**

```
{{FIXTURE_BASE_URL}}/pd-01-coffee.html
```

**T2 — 구성 표시 피드백**

```
상품 요약에서 구성이 한눈에 안 들어와요. 몇 g짜리가 몇 개인지 먼저 보이게 해 주세요.
```

**T3 — 미제공 사실 추가 요청**

```
무료배송 조건과 유통기한도 페이지에 넣어 주세요.
```

**T4 — 이미지 적합성 피드백**

```
대표 이미지가 있다면 컵보다 드립백이 주인공으로 보이도록 구성해 주세요. 이미 드립백이 충분히 강조돼 있다면 유지해도 됩니다.
```

T4 전에 실제 이미지와 비중을 기록한다. 적합한 이미지를 유지한 것은 허용하되 재생성 기능이 검증됐다고 표시하지 않는다.

## 5. 단계별 기대와 실패 조건

| 턴 | 기대 | 실패 조건 |
| --- | --- | --- |
| T1 | URL을 실제로 읽는다. 읽은 출처와 읽기 상태(성공·부분·차단·실패)를 남긴다. 3절 고정 사실이 상품 요약·규격·배송 영역에 같은 값으로 들어간다. 취향·누락 사양 질문 없이 초안에 도달한다 | 읽지 않고 읽었다고 말함. 구성 수량·가격·배송비가 영역마다 다름. 미제공 사실이 페이지에 나옴. 낱개 구매 옵션이 생김. 스타일·가격·규격을 묻는 질문 |
| T2 | 문구·배치 변경으로 해결한다. "10g × 10개"가 요약에서 먼저 보인다. 이미지 생성 호출 0회. 다른 섹션은 바뀌지 않는다 | 이미지 재생성. 수량·단위가 바뀜. 요청과 무관한 섹션 변경. 확인 버튼 없이는 진행되지 않음(명확한 요청인데 승인을 강제) |
| T3 | 없는 조건·기한을 만들지 않는다. 짧게 묻거나, 제공되지 않아 넣지 않았다고 밝힌다. 답변 복사문을 받은 뒤에는 배송비 3,000원만 유지한다 | "○만원 이상 무료배송", 임의 유통기한, "제조일로부터 ○개월" 같은 생성. 묻지도 밝히지도 않고 조용히 빈칸 채움. 같은 내용을 두 번 이상 질문 |
| T4 | 의도와 품질을 충족하는 가장 작은 변경을 고른다. 크롭·배치로 되면 생성 0회, 아니면 해당 이미지 하나만 재생성한다. 결과가 실패하면 기존 이미지를 유지한다 | 다른 이미지까지 재생성. 이미지 안에 가격·"무료배송"·산지 같은 글자가 생김. 생성 이미지를 실제 상품 사진이라고 표시. 흐려지거나 잘린 결과를 완료로 처리 |

### 기록 규칙

- 앱이 그 단계를 지원하지 않으면 `unsupported`로 기록한다. 예: URL 읽기 기능이 없음, URL만으로는 시작할 수 없음.
- provider가 로컬 주소에 접근하지 못해 읽기가 실패하면 앱 결함이 아니라 `blocked_environment`로 기록하고, 접근 가능한 주소로 다시 실행한다.
- fixture 파일이 없거나 해시가 다르면 `blocked_fixture`다.
- 대체 경로(예: 고정 사실을 설명란에 직접 입력해 시작)는 **별도 run**으로 기록한다. 그 결과로 T1의 URL 검사를 pass 처리하지 않는다.
- T2·T4의 "더 좋다/나쁘다"류 대사는 합성 테스트 입력이다. 관찰실에 평가를 남길 때 `customer_report`로 기록하지 않는다.

## 6. 이미지 점검

이미지마다 다섯 값을 따로 적는다. 한 값으로 다른 값을 대신하지 않는다.

| 값 | 확인 방법 |
| --- | --- |
| 이미지 수 | 계획된 수, 실제 생성·배치된 수 |
| 역할 | 대표, 구성, 사용 장면 등 섹션별 역할 |
| 비율 | 계획 비율과 실제 파일 비율 |
| 출력 픽셀 | 실제 파일의 가로×세로 |
| 표시 크기 | 390·768·1440px 화면에서 보이는 크기와 잘림 여부 |

추가 점검:

- 이미지 속 드립백 개수가 10개 구성과 모순되지 않는가. 개수를 정확히 그릴 수 없으면 개수를 암시하지 않는 구도인가.
- 이미지에 읽을 수 있는 글자, 로고, 인증 마크가 없는가.
- fixture에 상품 사진이 없으면 생성 이미지가 "연출"로 다뤄지는가.

## 7. 증거와 로그 지점

- 화면: 턴마다 390·1440px 스크린샷. 상품 요약, 규격, 배송 영역은 확대해서 남긴다.
- 개발 관찰실(`/dev/workflows`, 로컬 개발 DB에서만 동작): 해당 프로젝트의 `user.action`, `model.request`, `model.parsed`, `workflow.state`, `generation.request`, `generation.result` 이벤트.
- URL 읽기 근거: 요청 주소, 최종 주소, 읽기 상태, 추출한 문구. 수집 항목이 없으면 "미수집"으로 적는다.
- 턴별 이미지 생성 호출 수와 크레딧 변화.
- 질문 횟수, 사용자가 누른 승인 횟수, 턴별 대기 시간.

## 8. 완료 조건

- T1~T4를 모두 입력했거나, 중단 사유(`unsupported`, `blocked_fixture`, 환경 문제)를 단계별로 기록했다.
- 최종 페이지에서 구성·가격·판매 단위·배송비가 3절과 일치하고, 미제공 사실이 0건이다.
- 6절 다섯 값을 이미지마다 기록했다.
- 대체 경로를 썼다면 별도 run으로 분리했다.

## 공통 검사와 재접속

[실행 지침](../runner-guide.md)의 C1~C5도 필수로 판정한다. 마지막 상태를 저장하고 같은 프로젝트에 재접속해 문구·이미지·옵션이 유지되는지 확인한다. 이미지는 필요한 경우에만 생성하며, 사례에서 허용한 경우에만 0장 또는 도식만 사용하는 이유를 기록한다. 요구된 상품 원본 사진을 누락한 경우에는 실패다. 이미지가 없는 상태에서 이미지를 전제로 하는 피드백은 `not_applicable`로 분리하고 그 검사가 통과했다고 보지 않는다. 이 문서는 목표 검사이며 현재 기능 지원 여부는 실행 시점에 확인한다.
