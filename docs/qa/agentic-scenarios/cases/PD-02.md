# PD-02 보습크림 — 상품 외형·라벨 보존과 배경만 수정

2026-09-29 · 시나리오 문서 · 실행 결과 아님

공통 문서: [개요](../README.md) · [실행 안내](../runner-guide.md) · [실행 기록 양식](../run-template.md) · [fixture 기준](../fixtures/README.md)

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 형식 | 제품 상세페이지 |
| 최소 입력 유형 | 짧은 설명 + 상품 사진 (입력 유형 한 가지) |
| 가상 상품 | 하루결 크림 50mL |
| 핵심 검증 | 실제 상품 사진의 형태·색·라벨을 보존한 채 배경만 바꾸는가. 보존할 수 없으면 원본을 유지하거나 필요한 질문을 하는가. 수정 결과를 되돌릴 수 있는가 |
| 사용자 턴 | 4개 |

"입력 하나로 바로 제작"과 "불필요한 승인 없음"은 **목표 기준**이다. 현재 구현이 이를 충족한다는 뜻이 아니다.

## 2. 준비물과 실행 설정

- 사진 2장. 이 패키지에는 실제 파일이 없다. 실행자가 [fixture 기준](../fixtures/README.md)에 맞는 허가받은 자료를 준비하고 manifest에 해시를 고정한다.

  | 자리 | 내용 |
  | --- | --- |
  | `{{PHOTO:PD-02/front}}` | 제품 정면. 불투명 흰색 튜브, 초록색 캡, `HARUGYEOL` 라벨이 읽힘 |
  | `{{PHOTO:PD-02/back}}` | 같은 제품의 뒷면 |

- placeholder 이미지나 생성 이미지를 상품 사진 대신 쓰지 않는다. 사진이 없으면 `blocked_fixture`다.
- 사진이 3절과 다르면(캡 색, 라벨 철자, 용량 표기 등) 실행을 멈추고 fixture를 새 버전으로 고친다.
- 테스트 실행 설정(앱 정책이 아님):
  - 이미지 생성 횟수와 크레딧 상한.
  - 복원 충돌 처리: 이 run에서는 T2와 T3 사이에 다른 수정을 넣지 않는다. 충돌 정책 검증은 이 시나리오 범위가 아니다.

## 3. 사실 기준

### 고정 사실

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 상품명 | 하루결 크림 | 설명 |
| 용량 | 50mL | 설명 |
| 용기 | 불투명 흰색 튜브 | 사진 |
| 캡 | 초록색 | 사진 |
| 라벨 | `HARUGYEOL` | 사진 |
| 사진 구성 | 정면 1장, 뒷면 1장 | 첨부 |

### 미제공 사실 (페이지에 나오면 안 됨)

가격, 성분, 효능·효과(보습 지속 시간, 피부 개선 등), 피부 타입 적합성, 인증·시험 결과, 사용기한, 제조국, 후기, 향.

뒷면 사진에서 실제로 **읽을 수 있는** 글자는 관찰 사실이다. 읽을 수 없는 글자를 추정해 쓰면 실패다. 실행자는 뒷면에서 읽히는 문구를 manifest에 미리 적어 둔다.

### 질문을 받았을 때만 주는 답변

| AI가 묻는 내용 | 답변 복사문 |
| --- | --- |
| 가격 | `가격은 아직 넣지 않습니다.` |
| 성분·효능·피부 타입 | `확인된 자료가 없어요. 그 내용은 빼 주세요.` |
| 상품 자체를 바꿔도 되는지 | `아니요. 제품은 사진 그대로 두세요.` |
| 되돌릴 범위 | `방금 배경을 바꾼 수정만 되돌려 주세요.` |

## 4. 사용자 턴

**T1 — 시작 입력** (사진 2장을 함께 첨부)

```
하루결 크림 50mL 상세페이지를 만들어 주세요. 사진은 제품 정면과 뒷면입니다.
```

**T2 — 배경만 수정**

```
대표 이미지의 제품은 그대로 두고 배경만 밝은 아이보리로 바꿔 주세요.
```

**T3 — 되돌리기** (T2가 실제 변경을 적용한 경우만, 합성 테스트 입력)

```
방금 바꾼 것보다 이전 이미지가 더 나았어요. 이전으로 되돌려 주세요.
```

**T4 — 크기 피드백**

```
라벨 글자가 잘 보이게 대표 이미지를 더 크게 보여 주세요.
```

T2 전에 실제 배경을 기록한다. 이미 밝은 아이보리라면 유지가 적합한지 기록하고, 배경 변경·복원 검사는 `not_applicable`로 남긴다. 다른 배경의 원본 variant로 다시 검증하려면 새 run을 만든다.

## 5. 단계별 기대와 실패 조건

| 턴 | 기대 | 실패 조건 |
| --- | --- | --- |
| T1 | 사진을 실제로 분석 입력에 쓴다. 정면 사진이 대표 이미지로 배치된다. 상품명·용량이 그대로 들어간다. 미제공 사실을 묻지 않고 빼고 진행한다 | 효능·성분·피부 타입 문구 생성. 라벨 철자 변경. 원본 대신 생성 이미지를 상품 사진으로 배치. 가격·규격 질문 |
| T2 | 원본을 편집·합성 경로에 실제로 전달한다. 결과에서 튜브 형태, 캡 색, 라벨 글자가 원본과 같다. 보존할 수 없으면 원본을 유지하고 그 사실을 알리거나 원본 활용 대안을 제시한다. 보존 확인을 통과한 결과만 적용한다 | 텍스트만으로 새 이미지를 만들어 제품이 달라짐. 라벨이 뭉개지거나 다른 글자가 됨. 캡 색 변경. 생성 성공을 보존 성공으로 표시. 제품까지 밝기·색이 바뀜 |
| T3 | T2 직전 상태로 돌아간다. 대표 이미지 파일이 T2 이전과 같은 해시다. T2가 함께 바꾼 문구·배치가 있으면 같이 돌아간다. 되돌린 기록이 새 이력으로 남는다. 새 유료 생성 호출 0회 | 주소만 돌아오고 이미지 바이트가 다름. 다시 생성해서 "비슷한" 이미지를 만듦. T1 결과까지 사라짐. 되돌리기 이력 없음 |
| T4 | 배치·표시 크기 변경으로 해결한다. 이미지 생성 0회, 원본 해시 동일. 390px에서 제품이 잘리지 않고 라벨이 흐려지지 않는다 | 재생성. 확대로 라벨이 흐려짐. 튜브나 캡이 잘림. 흐려지거나 잘린 결과를 완료로 처리 |

### 기록 규칙

- 앱에 원본을 전달하는 편집·합성 경로가 없으면 T2는 `unsupported`다. 텍스트 기반 새 생성으로 대신한 결과는 **별도 run**으로 기록하고 T2를 pass 처리하지 않는다.
- 앱에 되돌리기 경로가 없으면 T3은 `unsupported`다. 실행자가 편집기에서 손으로 원본을 다시 넣는 것은 대체 경로이며 별도 run이다.
- 사진 준비가 안 됐으면 `blocked_fixture`다.
- T3의 "이전이 더 나았어요"는 합성 테스트 입력이다. 관찰실 평가에 `customer_report`로 기록하지 않는다.

## 6. 이미지 점검

이미지마다 다섯 값을 따로 적는다.

| 값 | 확인 방법 |
| --- | --- |
| 이미지 수 | 첨부 2장, 계획된 수, 실제 배치된 수. 원본 사용과 새 생성을 구분 |
| 역할 | 대표(정면), 상세·뒷면, 연출 등 |
| 비율 | 원본 비율, 계획 비율, 실제 배치 비율 |
| 출력 픽셀 | 원본 픽셀, 분석용 변환본 픽셀, 편집 결과 픽셀 |
| 표시 크기 | 390·768·1440px에서 보이는 크기와 잘림 |

보존 점검 (T2 전후 비교):

| 항목 | 방법 |
| --- | --- |
| 실루엣 | 원본과 결과를 같은 배율로 겹쳐 튜브·캡 윤곽 비교 |
| 색 | 튜브 흰색, 캡 초록색의 색 변화 |
| 라벨 | `HARUGYEOL` 철자와 위치, 읽힘 여부 |
| 배경 | 요청대로 밝아졌는가 |

자동 판정 도구가 없으면 사람이 비교하고, 불확실하면 "판단 불가"로 적는다. 점수나 임계값을 임의로 만들어 "보존 보장"이라고 쓰지 않는다.

## 7. 증거와 로그 지점

- 원본 사진 2장의 해시(manifest), 실제 전송된 변환 이미지의 해시.
- T2에서 생성·편집 요청에 원본 참조가 실제로 들어갔는지: 관찰실의 `generation.request` 이벤트.
- T2 전, T2 후, T3 후 대표 이미지 파일의 해시.
- 턴마다 390·1440px 스크린샷.
- 관찰실(`/dev/workflows`): `user.action`, `model.request`, `model.parsed`, `workflow.state`, `generation.request`, `generation.result`.
- 턴별 이미지 생성 호출 수, 크레딧 변화, 질문·승인 횟수.

## 8. 완료 조건

- T1~T4를 모두 입력했거나 중단 사유를 단계별로 기록했다.
- 최종 페이지에 미제공 사실이 0건이고, 제품 형태·캡 색·라벨이 원본과 같다.
- T3 후 이미지 해시가 T2 전과 같은지 기록했다.
- 대체 경로는 별도 run으로 분리했다.

## 공통 검사와 재접속

[실행 지침](../runner-guide.md)의 C1~C5도 필수로 판정한다. 마지막 상태를 저장하고 같은 프로젝트에 재접속해 문구·이미지·옵션이 유지되는지 확인한다. 이미지는 필요한 경우에만 생성하며, 사례에서 허용한 경우에만 0장 또는 도식만 사용하는 이유를 기록한다. 요구된 상품 원본 사진을 누락한 경우에는 실패다. 이미지가 없는 상태에서 이미지를 전제로 하는 피드백은 `not_applicable`로 분리하고 그 검사가 통과했다고 보지 않는다. 이 문서는 목표 검사이며 현재 기능 지원 여부는 실행 시점에 확인한다.
