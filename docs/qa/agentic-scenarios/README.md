# 랜딩·상품 상세 사용자 참여 테스트 시나리오

2026-09-29 · suite `agentic-pages-v1` · 시나리오 10개 · **작성 완료와 실행 통과는 별개**. 이번 패키지는 재사용할 문서·입력 자료·결과 양식이다. 자동 실행기나 관리자 테스트 UI는 포함하지 않는다.

업종별 시장 점유율을 조사한 순위가 아니라, 일반적인 구매·상담·신청 목적과 서로 다른 제작 난점을 고르게 다루기 위해 선정했다. 식물 사례는 기존 회귀 자료로 유지한다.

랜딩 5 / 상세 5, 한 문장 3 / URL 4 / 사진 3. 교차 기능의 반복은 공통 회귀이며 각 사례의 주 검증 목적은 다르다. 사진은 포함하지 않으므로 사진 3개 사례는 [준비 규칙](fixtures/README.md)을 충족한 뒤 실행한다. URL 사례도 서비스가 읽을 수 있는 주소를 먼저 준비한다.

## 요청 예시

```text
docs/qa/agentic-scenarios/README.md의 LP-02를 baseline 모드로 테스트해 주세요.
runner-guide.md를 따르고, 실제 UI에서 처음 입력부터 저장·재접속까지 확인하세요.
```

```text
agentic-pages-v1에서 이미지 수정·상품 보존을 검증할 시나리오를 골라 주세요.
준비물을 확인한 후 PD-02를 실행하고, 결과와 trace 지점을 run-template.md에 기록하세요.
```

```text
LP-01, LP-02, PD-01, PD-02, PD-05 다섯 사례를 같은 모델/설정으로 비교해 주세요.
사용할 환경과 비용 한도는 이번 테스트 요청에 명시한 설정을 따르세요.
```

5개만 고를 때 위 묶음은 세 입력 유형과 상담/전환/상품 보존/모호성 검증을 포함한다. 이미지 배치 중심이면 LP-05·PD-03, 사실 정합성 중심이면 LP-03·PD-04를 추가한다. 케이스 ID를 지정하지 않은 요청에서는 목적에 맞게 선택하고 선택 이유를 실행 기록에 남긴다.

## 실행 자료

- [AI·사람 공통 실행 지침](runner-guide.md): 입력 분리, 분기, 판정, 관찰실 연결.
- [실행 기록 양식](run-template.md): 실행마다 복사하여 `runs/`에 저장.
- [입력 자료 준비](fixtures/README.md): 고정 URL 원문 및 사진 계약.
- [기계 판독용 카탈로그](catalog.json): ID·형식·입력·태그·문서 위치. 실행 코드가 아니다.
- [패키지 검증 기록](validation.md) · [실행 결과 폴더](runs/README.md).
- 기존 개발용 워크플로우 관찰실(`/dev/workflows`)과 연결하는 방법은 실행 지침에 포함했다. 관찰실 구현 자체는 이 시나리오 패키지에 포함하지 않는다.

문서를 읽거나 mock 응답을 재생한 것을 실제 AI E2E 통과로 보고하지 않는다. 현재 구현과 목표 UX를 분리해 기록한다. 시나리오의 합성 사용자 발화는 실제 고객 만족도 표본이 아니다.
