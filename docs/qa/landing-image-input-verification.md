# 랜딩 페이지 이미지 입력 검증

검증일: 2026-09-21. 로컬 개발 서버 `http://127.0.0.1:3000`.

## 구현

- 왼쪽 소개 영역을 다중 이미지 보드와 이미지 기반 프롬프트 추천으로 변경했다. 기존 공통 업로더의 파일 선택/드롭, 큰 미리보기, 썸네일 전환, 대표 지정, 선택 제외를 재사용한다.
- 추천은 업로드 원본을 분석해 페이지 방향과 사진별 섹션 활용을 제안한다. 명시적으로 적용하기 전에는 기존 메모를 바꾸지 않는다. 추천 후 메모를 수정하면 이전 추천 적용을 막는다.
- 이미지와 메모가 의도 분석, 섹션 기획, 원고 작성, 수정, 검수에 전달된다. 사진만으로 시작할 수 있고, 기획에서 승인한 원본은 초안과 편집기에 바로 배치한다.
- 소유권 검증, 파일 디코딩/용량 검증, 인증 및 기존 크레딧 정책을 유지한다.

## 실제 브라우저와 모델 검증

테스트 자료는 프로젝트의 `public/content/thumbnails/fern-house.webp`(640×480), `greenhouse.webp`(640×360) 두 장이다. 실제 관리자 설정의 `gpt-5.6-terra / low`를 사용했다.

1. 파일 선택에서 두 장을 업로드했다. 썸네일 전환, 대표 변경, X 선택 제외, 재추가를 확인했다. 제외된 이미지도 라이브러리 원본 URL은 HTTP 200을 유지했다.
2. “가격·예약·실제 위치·운영 시간 추정 금지, 같은 장소라고 단정하지 않기” 메모와 함께 실제 이미지 추천을 실행했다. 모델은 첫 사진의 물가·건축·식물과 두 번째 사진의 온실·빛·조각상을 구분하고 사진별 활용을 제안했다.
3. 응답 전후 기존 입력이 보존됐고, 메모 변경 시 적용 버튼이 비활성화됐다. 원래 메모로 돌아온 뒤 ‘추천 프롬프트 적용’을 눌렀을 때만 오른쪽 입력에 추천과 사진별 활용이 반영됐다.
4. 별도 QA 제작에서 두 원본과 같은 원래 메모로 의도 분석 → 사용자 방향 승인 → 5개 섹션 기획 승인 → 원고·검수를 실제 수행했다. 추천 UI 적용과 제작 워크플로우는 각각 검증했다.
5. 기획은 첫 화면에 fern-house, 핵심 소개에 greenhouse를 배치했다. 계획된 이미지 2장, 업로드 원본 2장, 새 이미지 0장이 표시됐다.
6. 초안 iframe에서 두 원본이 모두 로드됐고 실제 자연 크기는 각각 640×480, 640×360이었다. 새로고침 후에도 5개 섹션과 이미지 2장이 복원됐다.
7. 검수 확인 후 편집기로 이동했다. 워크플로우 `completed`, 원본 참조·섹션 미디어·이미지 보드 적용 상태가 유지됐다. 두 원본은 내 라이브러리의 랜딩 기능 필터로 조회됐다.
8. 390px 화면에서 이미지 보드/추천 영역의 가로 넘침이 없고 썸네일 선택이 작동했다. 전체 문서 폭도 390px이었다.

실제 테스트 프로젝트: `/projects/dacc378a-dccb-4b43-98ce-4442d5fcfa69`.
워크플로우: `64c467ef-fcc6-4bea-99e9-84b18bba2554`. 모델 호출 4회, 앱 크레딧 286 → 285. 이미지 생성 작업은 실행하지 않았다. 익명 POST는 새 업로드/추천 API 모두 401이었다. 저장 상태는 `landing-image-input-live-check.json`에 기록했다.

## 화면 증거와 범위

- `landing-image-recommendation-desktop.png`: 왼쪽 이미지 보드와 오른쪽 메모 입력.
- `landing-image-input-mobile.png`: 390px 업로드·추천 영역.
- `landing-image-input-plan.png`: 섹션별 원본 이미지 선택과 목표 크기.
- `landing-image-input-draft.png`: 첫 화면에 업로드 원본이 적용된 실제 초안.

OS 파일 드래그 자체는 수동 재현하지 않았고 공통 드롭 핸들러와 파일 선택 경로를 확인했다. 사진만 시작, 실패 응답, 다른 계정 접근, 문구 수정 후 원본 보존은 자동 테스트에서 검증했다. HTML 연결은 자동 테스트이며 실제 ZIP 다운로드·외부 배포는 이번 검증에 포함하지 않았다.

샘플 원고 검수에는 감상 표현 완화 권고 3개와 비어 있는 CTA 연결 주소 안내가 남아 있다. 이를 확인한 뒤 편집기로 넘겼으며, 샘플을 외부 공개하거나 최종 콘텐츠 검수를 완료한 것으로 간주하지 않는다.
