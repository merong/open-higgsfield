# 왼쪽 상품 사진 갤러리와 이미지 기반 추천

## 화면 구성
기존 제품 상세 AI 시작 화면의 왼쪽 예시 이미지를 실제 업로드 갤러리로 교체한다. 오른쪽 중복 업로드 폼을 제거한다.

```
상품 소개 / 설명              상품 정보
큰 사진 · 드롭 영역           [이미지 기반으로 추천]
현재 사진 X · 추가            추천 확인 / 적용할 항목 선택
[썸네일][썸네일][썸네일]      상품명 · 카테고리 · 가격
대표 지정 · 파일명/크기       상품 설명 · AI 제작 시작
```

왼쪽은 4:3 프레임 안에 원본을 contain으로 표시해 잘라내지 않는다. 썸네일의 선택 테두리와 대표 사진 배지는 서로 다른 상태를 나타낸다. X는 이번 제작의 선택 목록에서 제거하며 라이브러리 원본은 보존한다. 여러 파일 드롭·선택, 진행 상태, 부분 실패 후 성공 사진 보존, 최대 6장·각 10MB 제한을 유지한다. 모바일은 갤러리 다음 상품 입력 순서이고 썸네일은 가로 스크롤한다.

기존 디자인 시스템의 surface/text/border/accent 토큰과 Pretendard 타이포그래피를 사용한다. 빈 상태에는 무관한 예시 사진 대신 업로드 동작을 표시한다. 사진 트레이 자체가 주된 시각 요소다. 화려한 장식이나 새 색 체계는 추가하지 않는다.

## 추천 기능
상품명·설명을 쓰기 전에도 사진만으로 요청할 수 있다. 업로드한 사용자 소유의 원본을 분석 사본으로 변환해 저장된 OpenAI 모델에 전달한다. 상품명(일반적인 제안명), 카테고리, 상품 설명, 관찰 근거와 확인할 사항을 반환한다. 가격·규격·소재·효능·인증·배송 정책은 사진만으로 만들지 않는다.

추천은 미리 확인하고 적용한다. 빈 항목만 기본 선택하고 기존 입력이 있는 항목은 사용자가 명시적으로 선택해야 변경한다. 사진 선택·순서가 바뀌면 이전 추천은 초기화한다. 요청 중 이미지 변경·제작 시작을 잠가 다른 사진에 대한 추천이 적용되지 않게 한다. 실제 상품 정보를 수정하는 UI는 기존 입력 필드를 이용한다.

사진 추천에는 추가 앱 크레딧을 차감하지 않으며 서버에서 계정별 분당 3회로 제한한다. 실제 제작은 기존 1 크레딧 워크플로우를 그대로 사용한다. API 키는 서버에서만 읽는다.

## 검증
다중 업로드, 썸네일 선택/대표 지정/선택 사진 제거, 빈 갤러리, 부분 업로드 실패, 모바일 넘침을 브라우저에서 확인한다. 이미지 기반 추천의 실제 모델 호출 및 선택 적용을 검증하고, 타인 에셋·빈 입력·응답 오류·확정 상품 정보 보존은 자동 테스트한다. 기존 제품 상세 워크플로우도 회귀 검사한다.
