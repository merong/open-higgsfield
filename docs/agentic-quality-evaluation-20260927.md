# 에이전틱 워크플로우 실제 결과 평가

검증일: 2026-09-27 · 로컬 개발 서버 · 저장된 `gpt-5.6-terra / low` 설정 유지

## 결론

**네 포맷의 제작과 출력 경로는 실행되지만, 현재 결과를 일관되게 최적이라고 판단할 수는 없다.** 원고 검수 통과와 실제 이미지·영상의 완성도 사이에 차이가 있다. 특히 릴스의 구도 지시가 렌더링 값으로 전달되지 않는 문제가 실제 MP4에서 확인됐다. 카드뉴스는 재생성해도 원치 않는 라벨이 남았다.

이번 검증은 인증된 API로 제작 단계를 진행하고, 실제 브라우저에서 승인·출력·다운로드·재생·반응형 화면을 확인했다. 형식별 한 가지 입력을 깊게 검증한 사례 평가이며, 여러 주제에 대한 통계적 품질 보장은 아니다. 계정·관리자 등의 전체 회귀 테스트도 실행했지만 모든 화면을 새로 수동 점검한 것은 아니다.

## 재현한 실행 문제와 이번 수정

### 1. 기획 응답 규격과 저장 규격의 불일치

- 카드뉴스 첫 실행은 2회 모델 호출 후 `이미지 구상 입력을 확인해 주세요` 오류로 종료됐다. 기존 동작대로 1크레딧은 환불됐다.
- 랜딩에서는 이미지 설명 및 섹션 수 검증 오류가 발생했다. 저장된 단계에서 다시 시도했고 네 번째 기획 응답이 승인 가능한 결과가 됐다.
- 기획 요청의 구조화 스키마에 카드 역할·제목·본문·이미지 구상 길이와 랜딩 제목·질문·본문·이미지 설명 길이, 섹션 3~8개 제한을 연결했다. 서버 검증은 유지했다.
- 실패 당시 원시 응답을 보관하지 않았으므로 실제 초과 글자 수를 단정하지 않는다. 카드 이미지 구상 701자 응답은 별도의 회귀 테스트로 재현했다. 랜딩 진단 로그는 내용 대신 항목 수와 필드 길이만 기록한다.

구조화 응답 제약은 [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고했다. 제약 추가 후 정상 응답을 확인했지만 모든 재시도 실패가 사라졌다고 주장하지 않는다.

### 2. 카드뉴스의 복구 불가능한 실패 처리

기획·작성 등의 응답 검증 오류가 전체 실행을 바로 종료하던 처리를 일시 정지로 바꿨다. 마지막으로 저장된 원고와 승인 상태를 유지하고, 사용자 재시도는 같은 실행에서 진행한다. 추가 제작 크레딧을 예약하지 않으며 종료 시 기존 제작 예약분을 환불한다. 자동 무한 재시도는 추가하지 않았다.

회귀 테스트에서 다음을 확인했다.

- 수정 대상 밖의 카드 응답 거부 → 기존 원고 보존 → 재시도 성공 → 추가 예약 없음.
- 701자 이미지 구상 거부 → 부분 저장 없음 → 정상 응답으로 재개.
- 취소 환불, 최대 호출 한도, 지연 응답 무효화 동작 유지.

수정 파일: `src/service/workflow-model.ts`, `src/service/card-workflow.ts`, `src/service/landing-model.ts`, `src/service/landing-workflow.ts`, `test/card-workflow.test.ts`.

## 실제 결과에서 확인한 품질 한계

### 카드뉴스: 재생성만으로 개선을 보장할 수 없음

첫 실제 PNG 검수는 15항목 중 pass 12·attention 3, 선택 이미지 재생성 후 검수는 pass 11·attention 4였다. 이는 모델의 항목 판정이며 객관적 품질 점수가 아니다. 새로운 검수에서 다른 문제를 발견할 수도 있다.

3장 이미지의 병·라벨을 제외하도록 지시하고 재생성했다. 흙을 관찰하는 행동은 더 잘 표현됐지만 큰 라벨 병이 여전히 남았다. 같은 모델에 부정 지시를 추가하는 반복만으로 문제를 해결하지 못한 사례다. 원고 보호 필드 `id/kind/title/body/kicker/cta`는 전후 동일했다. 본문과 하단 CTA가 중복되는 문제는 보호 원문을 임의 축약하지 않고 확인 대상으로 남겼다.

### 릴스: 좋은 지시가 실행 가능한 편집값으로 이어지지 않음

구도 차이가 있는 3컷을 요청했지만 실제 중앙 프레임의 피사체 배치가 거의 동일했다. 출력 검수도 2컷 attention, 3컷 error를 반환했고 완료를 차단했다.

코드상 장면 생성 스키마에는 이미지 구상 문장만 있고 구도 값이 없다. `reel-workflow.ts`는 모든 장면을 `crop:50, zoom:100`으로 초기화한다. `reel-render.ts`는 이 숫자로 합성하며 가로 위치는 중앙으로 고정한다. 따라서 “수건·유리컵을 강조하는 크롭”이라는 영어 프롬프트만으로 이미지 합성 화면이 바뀌지 않는다. **이번에는 원인을 규명했으며, 장면 구도 모델·편집 UI·합성기 변경까지 구현하지는 않았다.**

또한 원고 검수가 ‘손이 닿는 자리’라는 비유를 실제 손 동작 금지와 혼동해 수정하면서 제목·설명이 중복됐다. 검수 기준의 구체화와 보정 후 퇴행 검사가 필요하다.

6초 샘플과 15초 출력물을 만들었고, 전체 디코딩 및 브라우저의 재생 종료를 확인했다. 시각 평가는 샘플 프레임·컷별 중앙 프레임을 포함하며 모든 프레임의 움직임을 수동 판정한 것은 아니다. 이번 경로는 **업로드 사진 합성**이다. 50 이하 크레딧 제한을 우회하지 않았고, 새 AI 영상 생성이나 음성·BGM 합성은 시험하지 않았다.

### 웹페이지: 반응형 통과와 의미 있는 구도는 별도 검증

다운로드한 HTML ZIP을 풀어 1280·768·360px에서 브라우저로 열었다. 두 페이지 모두 이미지 로드 성공, 문서 폭과 화면 폭 일치, 본문 최소 17px였다. 랜딩 FAQ 확장과 내부 섹션 이동도 확인했다. 이메일 CTA 주소는 입력값과 일치하며 실제 메일 발송은 하지 않았다.

랜딩의 원본 대표 사진은 유지했다. 특징 영역에 만든 새 이미지는 데스크톱의 넓은 크롭에서 하단 수건·바구니가 빠진다. 파일 자체 검수만으로는 잡을 수 없는 최종 배치 문제다. 원고는 사실을 지어내지 않았으나 ‘분류·사용 흐름·배치’가 여러 섹션에서 반복된다.

제품 상세는 사진만으로 판매 대상이나 펌프 구조를 확정하지 않는 점이 적절했다. 반면 불명확한 입력을 경고만 남긴 채 긴 상세 페이지로 확장하기보다, 어떤 용기가 판매 대상인지 먼저 물었으면 결과가 더 정확했을 것이다.

- Thinking UI는 [이전 점검](agentic-quality-review.md)의 구현을 사용했다. 이번 평가는 실제 생성·출력 품질을 중심으로 했으며 새 대기 UI 검증이나 비교 실험을 수행한 것으로 주장하지 않는다.
