# 랜딩 페이지 — AI와 함께 제작

## 목표와 범위

사용자는 모든 섹션의 문구를 작성하지 않고도 한 줄의 제품·서비스 설명에서 시작한다. AI가 방문자의 상황과 원하는 행동을 정리하고, 사용자가 방향과 섹션 기획을 각각 승인한 뒤 페이지 초안을 만든다. 식물·제품·서비스·행사·포트폴리오에 공통으로 적용한다.

이번 구현은 의도 분석, 기획 승인, 원고 생성·검수, 섹션 단위 AI 수정, 저장·재개와 기존 랜딩 편집기 연결까지다. 이미지 생성·업로드·라이브러리, 링크 편집, 반응형 미리보기와 HTML ZIP 출력은 기존 편집기를 재사용한다. ZIP은 배포 가능한 파일이며 실제 호스팅, 결제, 문의 수집 서버를 생성했다는 의미는 아니다.

## 화면과 상호작용

1. **시작:** 소개할 제품·서비스 메모 한 칸. 예시를 선택할 수 있다. 원고 제작 1 크레딧, 이미지 생성 비용은 별도임을 표시한다.
2. **방문자 의도 보드:** AI 제안과 원문에서 확인한 내용을 구분한다. `누구에게 / 해결할 문제 / 전달할 가치 / 원하는 행동`을 편집한다. 행동은 상담·구매·신청·소개 선택과 직접 입력을 지원한다. 유입 경로, 브랜드, 실제 근거·필수 문구, 버튼 문구·연결 주소, 스타일은 같은 화면에서 짧게 확인한다. 주소가 없어도 초안 제작은 가능하고, 최종 편집에서 확인 사항으로 남긴다. URL 내용은 자동으로 읽었다고 주장하지 않는다.
3. **방문자 흐름:** 세로로 연결한 섹션 카드에 `방문자의 질문 → 전달할 답변 → 섹션 역할`을 표시한다. 히어로와 마지막 행동 유도는 고정, 중간 섹션은 순서 변경·삭제, 제목과 메시지 직접 수정 가능. 자유 의견으로 기획 전체를 다시 제안받을 수 있다. 승인 전에는 본문을 만들지 않는다.
4. **초안과 검수:** 승인한 순서와 ID를 유지해 본문을 만들고 목적·원문·과장·근거·CTA를 별도 모델 호출로 검수한다. 데스크톱/모바일 미리보기, 섹션 목록, 검수 지적을 제공한다. 원하는 섹션만 지시하여 수정하고 다시 검수한다. 다른 섹션과 확정 CTA는 서버에서 보호한다.
5. **편집기로 이어가기:** AI 단계의 스냅샷을 확정하고 기존 랜딩 편집기를 연다. 이미지 생성·업로드·라이브러리와 문구·링크·스타일 수정 후 HTML ZIP을 보관/다운로드한다. 이후 프로젝트 열기는 편집기로 연결한다. 초안 원고 검수는 실제 화면의 픽셀 검수나 게시 완료로 표시하지 않는다.

### 디자인 방향

기존 Pretendard, 디자인 시스템의 다크 서피스·차콜 경계선·라임 액션 토큰을 사용한다. 라임은 선택/현재 단계/주요 행동에 한정하고, 제목과 넓은 간격으로 위계를 만든다. 첫 화면은 설명과 입력의 2열, 작업 중에는 핵심 화면과 간결한 진행 기록의 2열이다. 고유한 시각 요소는 **방문자의 질문과 페이지 답변을 연결한 세로 흐름**이다. 760px 이하에서 1열로 정렬하고 긴 문구는 줄바꿈한다.

```text
랜딩 페이지 / AI와 함께 제작
[01 방향] ─ [02 방문자 흐름] ─ [03 초안 검수] ─ [04 편집·출력]
┌─────────────────────────────────┬──────────────────┐
│ 방문자 의도 보드 / 섹션 흐름 / 미리보기 │ 저장 상태 · AI 진행 │
│ 방문자 → 문제 → 가치 → 행동             │ 실제 수행 요약      │
│ [수정 가능한 제안]                     │ 사용자 확인 이력    │
│ [이 방향으로 기획하기]                 │                    │
└─────────────────────────────────┴──────────────────┘
```

자체 검토: 카드뉴스의 장수·채널 중심 질문을 복사하지 않는다. 처음부터 긴 설문을 요구하지 않고 AI 제안을 수정하는 방식이다. 숫자·후기·가격을 꾸며 설득하지 않으며 실제 근거는 사용자가 제공한다. 진행 문구는 수행 상태와 결과 요약만 제공하고 내부 사고 과정을 노출하지 않는다.

## 구현 계약

- `landing_workflows`와 버전 스냅샷 테이블. 사용자 소유권, revision 비교, 모델 호출 lease, 요청 ID 중복 방지 적용.
- 상태: pending/running/waiting_user/ready/paused/completed/cancelled. 단계: understand/plan/write/review/patch.
- 관리자에 저장된 OpenAI 모델·effort로 Responses 구조화 출력을 사용한다. 자동 재시도 없이 단계별 제한 시간, 전체 최대 12회 호출. 사용자 승인 대기에는 호출하지 않는다.
- 시작 시 1 크레딧 예약, 첫 원고가 저장되면 확정. 원고 생성 전 중단 시 한 번만 환불. 중복 시작·응답·요청으로 중복 차감하지 않는다.
- 검증된 기존 Project/Slot 모델과 랜딩 HTML 렌더러를 사용한다. AI가 HTML이나 임의 URL을 주입하지 못하게 한다. URL은 사용자 확인값만 사용한다. 임의 이미지·실제 제품 사진을 조작해 첨부하지 않는다.
- 계획은 3~8개 섹션, hero/features/story/faq/cta로 구성한다. 제공되지 않은 후기·가격 전용 섹션은 만들지 않는다.
- 원고 생성 후 콘텐츠 변경은 버전 증가 및 검수 무효화. 선택한 섹션만 AI 수정 가능. 편집기 인계 후 workflow는 읽기 전용이며 최신 프로젝트를 덮어쓰지 않는다.
- 진행 중 프로젝트를 다시 열면 해당 workflow로 복구한다. 완료·중단 프로젝트와 기존 수동 제작 프로젝트는 기존 편집기를 사용한다.

## 검증 기준

- 메모 → 방향 수정·승인 → 섹션 순서 변경·승인 → 생성 → 원고 검수 → 단일 섹션 수정 → 편집기 → ZIP 흐름.
- 테스트: 소유권, 중복 차감·환불, 오래된 revision, 승인 게이트, 선택 범위 보존, CTA 불변, 취소 후 늦은 응답, 오류/호출 한도, 재개, 기존 프로젝트 CAS 충돌.
- 기존 카드뉴스/숏폼 회귀 테스트 및 TypeScript/build 확인. DB 테스트는 `memory://` 사용.
- 실제 저장된 모델로 소규모 생성 1회. 식물 클래스 예시와 다른 일반 서비스 fixture로 범용성 확인. 데스크톱·모바일 UI, 새로고침 복원, 실제 편집기/ZIP을 확인하고 `docs/qa/`에 결과 기록.
