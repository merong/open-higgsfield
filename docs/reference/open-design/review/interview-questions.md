# 후속 인터뷰 질문과 좁은 추가 분석 요청

2026-09-28 · 코디네이터에게 반환 · 아직 답변받지 않은 검토안

[인터뷰 1~9](../interview-log.md)의 최소 입력, 선택적 계획 검토, 스타일 자동 판단, 미제공 가격·규격 제외, 판매 대상만 확인, 최소 변경, 상품 외형 보존, 명확한 수정 즉시 적용과 이미지·연결 문구·배치 복원은 다시 묻지 않는다. 아래 질문은 실제 코드에서 도입 결과를 달리 만드는 **미정 정책**만 다룬다. 한 번에 하나씩 질문하고 미응답을 동의로 처리하지 않는다. 우선 Q1 → Q2, URL 진입 세부를 정할 때 Q3, 여러 코멘트를 도입할 때 Q4 순서를 권고한다.

## Q1. 재생성에 얼마까지 맡길 수 있는가?

**근거:** 현재 이미지 보드는 사용자가 모델과 생성 버튼을 선택하고 서버가 견적 합계를 확인한다. 원고 호출 한도와 이미지 크레딧은 별도다. 명확한 텍스트 수정 권한이 무제한 이미지 재생성 비용 권한을 뜻하지는 않는다. [보드 생성](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/landing-images.ts:57), [모델 선택 UI](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/editors/landing-image-board.tsx:73), [원고 호출 한도](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/landing-workflow.ts:134)

**질문:** 배경 수정에 이미지 재생성이 필요하면, 미리 정한 크레딧 한도 안에서는 AI가 모델을 골라 진행하고 한도를 넘을 때만 확인할까요, 아니면 비용이 드는 요청마다 금액만 확인할까요?

| 선택 | 장점 | 부담·한계 |
| --- | --- | --- |
| 요청/프로젝트에 정한 한도 안에서 자동 진행, 초과 때 확인 — 권고 | 반복 승인을 줄이며 지출 통제 가능 | 한도의 단위·금액과 모델 교체 가능 범위를 추가로 정해야 함. 답변 전에 숫자를 임의 확정하지 않음 |
| 비용이 드는 수정마다 금액 확인 | 각 지출을 직접 파악 | 명확한 반복 수정에도 중단이 생김. 무료 문구/배치 수정은 즉시 진행 원칙 유지 |

결정 영향: D4·D5, P3의 실행 정책. 원본 보존 능력이 없는 모델로 한도만 맞춰 자동 전환하는 것은 허용 대안이 아니다. 실제 요금·호출 가능성은 별도 미검증이다.

## Q2. 되돌릴 수정과 나중에 고친 내용이 겹치면 어떻게 할까?

**근거:** 현재 snapshot은 프로젝트 전체를 기록하고 일반 저장은 version 충돌을 거부한다. 수정별 변경 필드와 후속 수정의 의존 관계는 없다. [snapshot](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/landing-workflow.ts:26), [일반 저장](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/projects.ts:51), [이미지 fingerprint](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/projects/landing-images.ts:18)

**사례:** AI가 이미지와 제목·배치를 함께 바꾼 뒤 사용자가 제목을 다시 고쳤다. 이제 첫 AI 수정을 되돌리려 한다. 이미지와 연결 문구·배치를 복원한다는 초기안은 유지하되, 나중에 고친 제목과 충돌한다.

**질문:** 이후 수정한 내용은 최대한 남기고 겹치는 부분만 선택할까요, 아니면 한 번의 되돌리기로 그 수정 직전 페이지 전체를 복원할까요?

| 선택 | 장점 | 부담·한계 |
| --- | --- | --- |
| 독립 수정은 유지하고 겹친 내용만 선택 — 권고 | 나중 작업을 잃지 않음 | 충돌 때만 짧은 선택 필요. 같은 필드가 아니어도 이미지와 문구의 의미 의존성을 확인해야 함 |
| 해당 수정 직전 페이지 전체 복원 | 복원 단위를 이해하기 쉬움 | 이후 다른 섹션의 작업까지 사라질 수 있어 영향 표시가 필요 |

결정 영향: D5·P0. 이 질문은 비교·복원 자체를 다시 승인받기 위한 것이 아니다. 보존 기간과 비교 UI 세부는 사용량·실험 근거가 나온 뒤 결정하며 지금 한꺼번에 묻지 않는다.

## Q3. URL을 읽지 못했지만 대상은 알려진 경우 어떻게 이어갈까?

**근거:** 현재 앱은 URL 내용을 읽지 않는다. Open Design 브랜드 수집에는 thin/blocked가 있으나 상품 자료 수집 완결성을 보장하지 않는다. [현재 모델](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/landing-model.ts:41), [URL 결과 계약](/Users/brian/works/github/open-design/apps/daemon/src/brands/prefetch.ts:53)

**사례:** 사용자는 상품명·짧은 소개와 URL을 입력했지만 사이트가 차단됐다. 상품 자체는 특정되고 가격·규격은 읽지 못했다.

**질문:** 읽힌 설명만으로 먼저 초안을 만들고 URL 자료는 나중에 보충할까요, 아니면 짧은 설명이나 사진을 더 받은 뒤 시작할까요?

| 선택 | 장점 | 부담·한계 |
| --- | --- | --- |
| 가용 정보로 초안 진행, 읽기 실패와 미확인 범위를 표시 — 권고 | 시작 지연·추가 입력 최소 | 상품 이미지·세부 설득 근거가 부족할 수 있음 |
| 대체 자료를 한 번 요청한 뒤 진행 | 원본 자료 확보 가능 | URL을 선택한 사용자가 다시 입력해야 함 |

URL만 있고 상품도 특정할 수 없으면 이미 확정된 ‘판매 대상만 짧게 확인’ 원칙을 적용한다. 없는 가격·규격을 만들지 않는 원칙도 재논의하지 않는다. 결정 영향: D1·D6·P1.

## Q4. 서로 다른 영역의 코멘트를 한 묶음으로 반영할까?

**근거:** 현재 앱은 한 `targetId`의 문구 수정이 중심이고 실행 중 새 action을 거부한다. Open Design은 여러 코멘트를 각각 별도 큐 task로 만든다. [현재 수정 action](/Users/brian/works/agent/openhigsfield/open-higgsfield/src/service/landing-workflow.ts:207), [Open Design 큐](/Users/brian/works/github/open-design/apps/web/src/components/ProjectView.tsx:5558)

**사례:** 제목을 줄이고, 사진을 크게 하고, 다른 섹션의 표현을 바꾸는 세 코멘트를 남겼다. 명확한 개별 수정의 실행 원칙은 이미 확정됐지만 중간 결과와 실패 단위는 다르다.

**질문:** 충돌 없는 코멘트는 한 번에 반영해 요약을 볼까요, 아니면 코멘트별로 완료된 결과를 차례로 볼까요?

| 선택 | 장점 | 부담·한계 |
| --- | --- | --- |
| 충돌 없는 항목은 묶어서 반영 — 권고 | 반복 대기와 화면 흔들림 감소 가능 | 일부 실패 때 적용/복원 단위 설계 필요. 실제 호출·시간 절감은 미측정 |
| 코멘트별로 순서대로 반영 | 항목별 진행·실패 원인을 알기 쉬움 | 대기·호출 수 증가 가능, 뒤 작업이 앞 변경을 읽어야 함 |

상충하는 ‘사진 더 크게/작게’나 서로 다른 판매 상품 지정은 자동으로 마지막 요청만 선택하지 않고 필요한 선택을 좁혀 묻는 안을 제안한다. 실행 중 의견을 즉시 중단/대기 중 어느 방식으로 처리할지도 이 선택 이후 사례로 좁힌다. 결정 영향: D3·D7·P4. 첫 PoC를 단일 코멘트로 한정하면 이 질문은 뒤로 미룰 수 있다.

## 추가 분석 요청 — 사용자 질문과 구분

다음은 사용자에게 기술 구현 방식을 고르게 할 항목이 아니다. 이번 범위에서 부족한 증거만 좁게 반환하며 스스로 후속 조사·실행하지 않는다.

| 요청 | 좁은 범위·필요 이유 | 필요한 결과 |
| --- | --- | --- |
| A1 원본 보존 가능한 이미지 경로 | 현재 `imagePlane`의 빈 media를 기준으로 기존 generation catalog/platform의 참조 이미지·편집·마스크 지원이 페이지 보드로 연결 가능한지 확인. 일반 스튜디오 전체 감사 제외 | 모델/어댑터별 실제 입력 필드, 원본 전달 가능 여부, 배경 합성 대안, 지원하지 않는 경우의 분기. 실제 외형 보존은 별도 한정 샘플 검증 |
| A2 이력 에셋 수명과 저장 경로 | active/완료된 랜딩·일반 편집 저장에서 변경 기록을 공유할 위치, 에셋 삭제·보관 한도와 이전 버전 참조 관계 | 수정 단위 before/after 저장 및 복원 충돌 표, 참조 중인 에셋의 생존 조건. 500MB 한도에 맞는 기간/개수 정책은 실측 후 제안 |
| A3 URL 입력의 최소 수집 범위 | 공개 상품/서비스 URL의 텍스트·사진·출처와 실패 유형을 최소 입력 계약으로 연결. Open Design 브랜드 수집기 전체 이식 제외 | 성공/부분/차단/실패 예시, 상품 식별·복수 상품·가격/규격 출처 구분, 실패 시 Q3 연결. 네트워크 접근은 후속 허용 범위에서만 |
| A4 최종 크기·영역 변환 | 기존 renderer와 미리보기의 scale/crop/contain·cover 및 provider 실제 출력 크기 | 표시 위치→원본 영역 매핑, 요청 크기→실제 픽셀 비교, 잘림·흐려짐 판정 fixture |
| A5 견적 갱신과 모델 교체 | UI `i.cost` 합계와 서버의 새 모델 quote 비교 경로만 확인 | 비용이 다른 모델 선택 시 표시·전송·원장 일치 여부. 정적 의심을 재현 전 확정 결함으로 기록하지 않음 |

제품 코드·다른 분석 문서 변경, 추가 에이전트 생성, 설치·실행 테스트·유료 호출·배포는 이번 결과에 포함되지 않는다. 질문은 이 문서로 반환했으며 사용자에게 새 인터뷰를 직접 시작하지 않았다. 리뷰 결과 인터뷰와 명시적 후속 지시를 기다린다.
