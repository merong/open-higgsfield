# 제품 상세 · 상품 사진으로 AI 제작

## 목적과 화면
실제 상품 사진과 상품명·설명을 한 번에 전달하고, 사진의 배치를 승인한 뒤 상세 페이지를 만든다. 기존 제품 상세의 방향 확인 → 기획 승인 → 원고·검수 → 편집 흐름을 유지한다.

시작 폼: `상품 사진 [대표 사진 + 보조 사진] → 상품명/가격 등 → 상품 설명 → AI와 상품 기획하기`.
사진은 최대 6장, JPEG/PNG/WebP 각 10MB. 드롭·다중 파일 선택, 미리보기, 대표 지정, 선택 해제, 전송 진행과 오류를 표시한다. 선택 해제는 라이브러리 원본을 삭제하지 않는다. 이미지는 선택 사항이며, 사진 없이 시작하던 흐름도 유지한다.

디자인은 기존 시스템의 canvas #0a0a0b, panel #141617, primary text #f5f5f5, muted text #8a9294, accent #d1fe17 토큰을 재사용한다. 기존 Pretendard/Sans 제목·본문·작은 보조 설명의 위계를 유지한다. 새로운 장식 대신 대표 사진 배지와 원본 크기를 보여 주는 사진 트레이를 중심 요소로 쓴다. 모바일에서는 두 열 사진 트레이와 한 열 입력 폼으로 전환한다. 초안/기획의 원본 썸네일이 시작 폼과 이어지도록 한다.

## 데이터와 AI
- 기존 assets 저장소에 인증된 사용자 소유의 원본 바이트를 저장한다. MIME 선언뿐 아니라 실제 디코딩, 크기·픽셀 수·애니메이션 여부를 검사한다.
- 시작 요청은 asset ID 배열만 받는다. 소유권을 확인해 서버가 URL·이름·크기를 결정한다. 메타데이터는 워크플로우에 저장하고, 승인한 원본은 프로젝트의 섹션 media로 보존한다.
- AI 요청에는 상품명·설명과 이미지별 ID를 붙인 실제 이미지 입력을 전달한다. 분석용 이미지만 회전/축소하고 원본은 변경하지 않는다. 사진에서 보이는 특징과 사용자가 명시한 규격을 구별하고 사진만으로 소재·성능·인증을 추정하지 않는다.
- 기획에서 각 이미지 섹션은 업로드 원본 또는 새 이미지 제작을 선택한다. 대표 사진은 상품 소개의 기본값이다. 허용된 원본 ID만 수락한다. 승인된 원본은 초안에 즉시 적용하고, 문구 수정 시 유지한다. 전체 이미지 제작에서는 원본이 있는 섹션을 빈 이미지로 취급하지 않는다.
- 업로드 자체는 생성 크레딧을 사용하지 않는다. 기존 원고 1 크레딧과 선택적 이미지 생성 비용은 유지한다.

## 검증
유효·손상·형식 위장·과대 파일, 소유권/ID 변조/개수 제한, 멀티모달 바이트 입력, 원본 배치 승인·복원·수정 보존, 이미지 제작 보드, HTML/ZIP을 확인한다. 실제 상품 사진을 업로드하여 AI 분석과 초안의 원본 재사용을 확인하고 데스크톱/모바일 UI를 검수한다.
