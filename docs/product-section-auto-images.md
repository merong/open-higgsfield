# 업로드 사진 기반 상품 상세 이미지 일괄 생성

2026-09-29. 시작 시점에 대한 사용자 선택은 **초안 완성 후 ‘섹션 이미지 자동 생성’ 한 번 클릭**이다. 기획 승인이나 원고 완성만으로 유료 이미지 생성을 시작하지 않는다.

## 사용 흐름

1. 상품 사진을 업로드하고 상품 상세 기획·원고를 완성한다. 기획에서 이미지 포함 여부, 장면, 비율 및 사용할 사진을 조정할 수 있다.
2. 초안 아래에 이미지 수, 모델, 장당·전체 크레딧과 **섹션 이미지 자동 생성** 버튼을 표시한다.
3. 버튼을 누르면 이미지가 필요한 섹션마다 후보 한 장씩 순차 생성한다. 섹션에 지정한 원본을 참고하고, 미지정 섹션은 대표 사진을 사용한다. 이미지 제외 섹션은 생성하지 않는다.
4. 생성 진행·검수할 후보 수를 표시한다. 모달을 닫아도 AI 제작 화면 안에서는 이어서 진행한다. 페이지를 떠나면 접수한 공급자 작업은 유지되며, 남은 큐·결과 보관은 다시 접속했을 때 이어진다. 서버의 상시 백그라운드 워커는 아니다.
5. ‘이미지 후보·진행 확인’에서 결과와 프롬프트를 검토한다. 개별 재생성 시 기존 참조 사진을 유지한다. ‘확인하고 N장 적용’을 눌러야 상세페이지 이미지를 교체한다. 원본 업로드 파일은 남는다.

기존 초안의 ‘전체 이미지 제작 · 검수’에서도 ‘업로드한 상품 사진을 참고해 생성’을 선택하여 이미 사진이 있는 영역까지 새 후보를 만들 수 있다. 진행 중인 큐나 미적용 후보가 있으면 일괄 자동 생성으로 덮어쓰지 않는다.

## 모델·상품 보존

Marketing Studio Image의 direct editing 경로 `marketing-studio/image`와 `image_urls`를 사용한다. 공식 [API 명세](https://open.higgsfield.ai/models/marketing-studio/image/api-reference)를 기준으로 명시적인 참조 경로가 있는 모델만 사진 기반 생성 목록에 노출한다. 초기 제공 모델은 Marketing Studio Image 한 종류다. 기본 해상도는 1k, 섹션 비율은 1:1·3:4·16:9이다. 화면의 목표 배치 픽셀 수와 모델의 실제 출력 픽셀 수는 구분한다.

상품의 형태·비율·색상·재질·브랜딩·로고·구성품을 유지하고 배경·조명·구도만 조정하도록 요청한다. 섹션 장면과 승인한 핵심 메시지를 프롬프트에 반영한다. 이는 생성 모델에 전달하는 지침이며 외형 일치의 보장은 아니다. 실제 상품과의 일치는 후보 확인 단계에서 검수한다.

계정 소유의 업로드 이미지 바이트만 허용한다. 검증·EXIF 회전·최대 1600px JPEG 변환 사본을 공급자 저장소에 전송하고 HTTPS 주소를 생성 입력에 연결한다. 원본 바이트를 변경하지 않는다. 클라이언트가 임의 외부 참조 URL이나 다른 사용자 에셋 ID를 지정할 수 없다.

## 상태·결제·재개

- `LandingWorkflow.autoImages`: 최초 클릭 시 승인한 모델·총액·요청 키와 큐 생성 상태. 워크플로우 잠금 안에서 이미지 큐와 함께 저장한다.
- `ImageBoard.referenceImages`, `ImageItem.referenceImageIds`: 사진 목록과 섹션별 실제 참조 ID. 기존 JSON 레코드에는 선택 필드로 추가하며 별도 DB 마이그레이션은 없다.
- `project_image_boards`의 큐·리스·revision 및 `generation_jobs`의 idempotency key를 재사용한다. 중복 클릭/재접속으로 같은 생성 요청을 새로 결제하지 않는다.
- 서버가 이미지 수와 단가·잔액을 검증한다. 클릭 시 전체 작업을 큐에 등록하고 실제 공급자 접수 전에 각 이미지 비용을 차감한다. 다른 작업의 지출로 잔액이 줄면 일부 작업이 실패할 수 있다.
- 참조 업로드 실패는 생성 요청과 과금 전에 종료한다. 공급자의 명확한 실패는 기존 환불 정책을 따른다. 접수 결과 불명확 상태는 자동 재접수를 차단한다.
- 생성 결과 보관 실패는 새 생성 없이 보관을 재시도한다. 검수 중 페이지 내용이 바뀌면 오래된 후보로 덮어쓰지 않는다.
- 관리자가 저장한 API 자격 증명과 공급자 원점을 생성 작업에 보존하여 이후 상태 조회도 같은 연결을 사용한다.
- 기존 프로젝트별 워크플로우 trace에 사용자 클릭, 참조 ID, 생성 입력, 후보·적용 상태가 기록된다.
